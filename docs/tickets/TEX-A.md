## 目的（オーナーの言葉）
- 「正直、一番最初のマイクラのテクスチャーが一番視認性が高かったなと思っています。いちばんはじめのマイクラっぽいテクスチャーに戻すことはできますか？ 9*9*9ブロックの形はそのままでよいです。テクスチャーだけ戻したいです。」→ 3 通りから **(a) そのまま投影** を選んだ。
- 「影は1,2,3の全部にして欲しいです。箪笥やかまどは立体的なグラフィックにしなくてもいいので、9*9*9になる前の元のブロックのような影の付け方をしてください」

形（B ごつごつ・9×9×9・小ブロック地形）は今のまま。**色を元の 16 px の絵の投影にし、影 3 つを足し、道具のブロックを平らな箱にもどす。** きまりは `docs/art/DESIGN.md` 1〜5 章、試作の記録と計測は `docs/art/texture-back.md`、見本は `docs/art/texture-back/`（`texture-back.png`・`texture-back-shade.png`・`texture-back-check.png`）。

## きまり（くわしくは DESIGN.md の章）
- **投影**（4.1・4.2）: 面の向きで [上, 下, 横] のタイル（`BLOCK_TILES`）をえらび、ワールド座標から 16×16 の画素を読む。でこぼこの小ブロックはその場所の画素の色。小ブロック地形の横の面は「その場所の地面のてっぺんから何小ブロック下か」で grass_side の行を決め、16 行より下は dirt。
- **箱の段・LOD・遠く**（2・4.4）: 箱の段は近くと同じ投影。LOD はタイルの平均色。40→80 ブロックで画素の色をタイルの平均色へよせる（ちらつき止め）。
- **影 3 つ**（3 章）: (1) 面の明るさ 上 1.0・南北 0.8・東西 0.6・下 0.5（世界のブロックの面はぜんぶ同じ値）。(2) 小ブロックの角の暗がり（4 段 1.0・0.82・0.68・0.55、面の中は双線形）。(3) キャラの丸い影（かけ算のまぜ方、キャラの板より先に描く、水の中と 6 ブロックより上では出さない）。
- **平らな箱**（5.3）: かまど・たんす・スプリンクラー・レンガ・かわら・はたけ・ぬれたはたけ（7 種）は、9×9×9 の前と同じ 1 ブロックの箱と atlas の絵（`sectionExtras` の `pushFace`）。影は前と同じ（角の光のなめらかな平均）に (1) の値とブロック単位の (2) をかける。箱のまわりに空の色のすきまを作らない。
- **鉱石はでこぼこのまま**（5.2）。色は投影だけ。
- 光（空・ブロック・昼夜・たいまつの色あい）は今のまま（`lightShader`）。
- **試作の切りかえ（`?tex`・`?shade`）は残さない。** Look の色（palette の色・`terrainColor` の色・3D の模様 `shapeTexture` の色）は描画に使わない。Look の `fill`（形）と小ブロック地形の形は使う。
- 作業台・チェストというブロックは今のゲームにない（しまう物はたんす）。

## (2) 角の暗がり（AO）の作り方 — 三角形をふやさない
試作の頂点 AO（`art-paint-local` の `sectionMesher.ts` `?shade=ao`）は、AO がちがう面をつなげられず **三角形が約 2.6 倍**（スタート 38 万 → 98 万、上空 43 万 → 108 万。上限 120 万に近い）になった。本番は次の順で選ぶ。

| 順 | 作り方 | 三角形 | 描画回数 | ほかの費用 | いつ使う |
|---|---|---|---|---|---|
| **第一案 S1** | **シェーダーで計算**: セクションごとに小ブロックの「うまり」の 3D テクスチャ（下）を持ち、フラグメントで面の前の層のとなり 8 こを読んで 4 すみの段を出し、面の中の位置で双線形にまぜる | **+0** | **+0** | GPU メモリ 1 セクション約 0.4 MB（スタートで小ブロックのセクション 約 40 → 約 16 MB）。フラグメントで texelFetch 8 回。作り直しで 0.4 MB の転送 | まずこれ |
| 代わり S1b | **頂点に AO の絵の場所を入れて、面をまとめたまま持つ**: まとめた面ごとに (w+1)×(h+1) の小さな AO の絵（ライトマップ）を 1 まいの絵に焼き、頂点に UV を足す | +0 | +0 | 頂点 +4 バイト、メモリは面の数だけ（S1 より小さい）。つめこみの処理が複雑 | S1 のメモリが 32 MB をこえるとき |
| 第二案 S2 | 試作の頂点 AO を **近くだけ**（AO 半径 16 ブロック、12〜16 で 1.0 へ）。外は AO なし | 見積もり スタート 約 53 万（38 万＋近くの分の 2.6 倍） | +0 | 作り直しの時間が少しふえる | S1・S1b が Mac で 60 fps に届かないとき |

- 「頂点の色に AO を入れて、まとめた面をそのまま」だけでは、まとめた面の 4 すみにしか暗さが入らず、面の中の段の根もとが暗くならない。だから S1b のように「AO の絵の場所」を頂点に入れる。
- **S1 のうまりの 3D テクスチャ**: セクション（144³ 小ブロック）＋まわり 1 小ブロック = 146³。1 小ブロック 1 bit、x 方向に 8 こずつつめて `R8UI`（19×146×146）。メッシュ作りがすでに持っているうまりの表から作る。道具の平らな箱・不透明の atlas のブロックは「全部つまった 9×9×9」として入れる（地形側の AO が箱の根もとで暗くなる）。水・たいまつ・十字の板はつまっていない。
- 小ブロックの段（r 以内）だけ。箱の段・LOD は AO なし。r−8 から r で 1.0 へ（段の切りかえでぱっと変わらない）。
- 平らな箱の面は頂点 AO（ブロック単位、1 面 1 四角なので三角形は増えない）。

### 上限をこえそうなとき（この順でへらす。(1)(3) は費用 0 なのでいつも入れる）
1. S1 のメモリが 32 MB をこえる → AO を作るセクションを近い順に 24 ブロックまで（外は AO 1.0）。それでもこえる → S1b。
2. Mac（F3）でスタート・上空・ほらあなのどれかが 60 fps に届かない → S2（AO 半径 16）。まだ届かない → 半径 12 → 8。
3. まだ届かない → 設定「すみの かげ」（既定 ON）を足して OFF にできるようにし、オーナーと相談する。
4. **三角形 120 万（r=32 のどこでも）と描画回数 スタート 300 / 上空 700 は、どの場合もこえない**（S2 の半径でおさえる）。

## テストが使う hook
`window.__rikkun.render.*` に開発が足す（`src/world/hook.ts` か `src/debug/testHook.ts`。いまは `render.chunks()` だけ）。`Face = 'top' | 'bottom' | 'north' | 'south' | 'east' | 'west'`（north = −z）。

```ts
faceShade(): Record<Face, number>;            // (1) の値。{ top: 1, bottom: 0.5, north: 0.8, south: 0.8, east: 0.6, west: 0.6 }
flatBlocks(): string[];                       // 平らな箱で描く id（DESIGN 5.3 の 7 種）
texelAt(x: number, y: number, z: number, face: Face): { tile: string; px: number; py: number; rgb: [number, number, number] };
// ワールドの点 (x,y,z)（面の上）が使うタイルと画素（シェーダーと同じ式の TS 写し。rgb は sRGB 0〜255）
aoAt(x: number, y: number, z: number, face: Face): number;      // その点の AO（1.0 = なし。シェーダーと同じ式の TS 写し）
toScreen(x: number, y: number, z: number): { x: number; y: number; onScreen: boolean }; // CSS px
pixel(sx: number, sy: number): [number, number, number];        // いまのコマを描いて、その画素を読む（sRGB 0〜255）
blobShadow(): { visible: boolean; x: number; y: number; z: number; size: number; opacity: number;
                renderOrder: number; spriteRenderOrder: number; transparent: boolean };
aoStats(): { mode: 'shader' | 'lightmap' | 'vertex' | 'off'; radius: number; textureBytes: number; sections: number };
setAo(on: boolean): void;                    // テスト用: AO を切る（基準 7 の ON / OFF くらべ）
setBlobShadow(on: boolean): void;            // テスト用: 丸い影を切る（基準 8「くつの画素は ON / OFF で同じ」「かけ算」。tester が追加で依頼）
```

- `texelAt`・`aoAt` の点 (x,y,z) は「ブロックの面の平面の上」の点。小ブロックのへこみの底に当たるときは、その列の見える表面（へこみの底）の画素・AO を返す。
- テストは 1 コマ撮ったスクリーンショットから多くの画素を読む（`pixel` は 1 回ごとに描くので遅い）。`pixel` はスクリーンショットと同じ値（±2）を返すこと。
- 期待の数は hook（ゲームの値）に聞く。タイルの画素は `texelAt` の `rgb`、光の式は `world/light/curve.ts` と同じ式。
- キャラが画面をふさがないよう、見る面はキャラの横か上に作る（`player.set` で向きを決める）。
- hook の名前・形を変えるときは、このチケットとテストを一緒に直す。

## 気になる所（試作で 夜・ほらあな・水のふち・道具の箱 を撮った結果。`texture-back-check.png`）
1. **置いたブロックの根もとに空色のすきま**（A）: 小ブロック地形の草の上にブロックを置くと、根もとに空が見える（今の main でも出る。下の地面の小ブロックがブロックの上までない所から、中の空っぽが見える）。平らな箱はよく置くので **この TEX-A で直す**（基準 9）。案: 置いたブロックの下ととなりの列は、小ブロック地形のてっぺんをブロックの上にそろえる（へこませない）か、下のブロックの見える横の面を描く。
2. **小ブロックの面のつぎ目に 1 画素の空色の点**（B。T 字のすきま）: ほらあなの暗いかべで目立つ。今の main でも出る（最初の main には無い）。投影とは関係ないので **別の issue を PO に提案**（TEX-A の範囲外）。
3. **水のふちの小ブロックのすきまに空色の点**（D）: 今の main でも出る。2 と同じ issue にまとめる。
4. 水の中では丸い影を出さない（試作では水の底に出ていた）。
5. 夜・ほらあなの暗さとたいまつの光は、今のしくみのままで正しく出る。丸い影は暗い所ではほぼ見えない（かけ算なら青くうかない）。
6. 鉱石はでこぼこのままで、最初の main と同じくらい見える（平らにしても目立ちかたはほぼ同じ）。
7. 平らな箱とでこぼこの地形がならぶと「作った物はまっすぐ、自然はごつごつ」で分かりやすい。ただし試作の箱の横は前の 0.8 のままで、となりの地形（東西 0.6）と少しくいちがって見えた → 本番は (1) の値を全部の面で同じにする（基準 6）。
8. 上空で 16 px の点が細かくちらつく → DESIGN 2 章の「遠くは平均色へよせる」で直す（基準 10・13）。
