## 目的（オーナーの言葉で）
「GPU のない CI/CD 環境で、GPU 処理が必要となるチェックをしていることが問題」「ずっと続いているこの問題を解決したい」（yuzu 2026-10-17。案 A と B を選び、調べ直しでこの形に）。
調べた結果: project files `ci-gpu/PLAN.md`。

## なぜ
- E2E 1 本ぶんの時間の大半は、起動後に はじまりの地形の **小ブロック（9×9×9）の細かいメッシュ** を作る所（8.4〜12.3 秒、CPU）。細かいメッシュをやめて箱の段だけにすると 1.4〜1.9 秒。メッシュのデータ 78 MB → 4.7 MB。
- 試しに全部 386 本を細かいメッシュなしで回すと 374 本がそのまま緑。w2・bal-a・m7 の 21 本は 4.2 分 → 1.7 分。
- 落ちたのは見た目・メッシュそのものを見る所: texA AC2・AC4・AC7・AC10・AC12、seethru E1×3・E2・E3、voxE-mesh AC1。rarity7 AC15 は時間切れ（65 秒。原因は要確認）。
- 影を E2E で既定オフにしている（`VITE_SHADOW_DEFAULT=off`、SHADOW.md §6）のと同じ考え。

## やること（決まり）
1. **ゲーム側**（遊びは変えない）
   - 小ブロックの半径に「0 = 小ブロックなし（近くも箱の段）」を足す。`normalizeMicroR(0)` は 0 のまま。F4 の切りかえは今のまま 16 → 24 → 28。
   - 既定の半径は環境変数 `VITE_MICRO_DEFAULT` で変えられる。`off` のとき 0。なし・ほかの値のときは 28（2026-10-18 から。それまでは 32）。
   - `?microR=16|24|28` は環境変数より強い（今のまま）。`?microR=0` も 0 として受けつける。
   - ふつうに遊ぶとき・`npm run dev`・公開したゲームは28（2026-10-18 から。それまでは 32）。
2. **E2E の設定**: `playwright.config.ts` の webServer の command に `VITE_MICRO_DEFAULT=off` を足す（影と同じ所）。
3. **性能の設定**: `playwright.perf.config.ts`（`npm run perf`）は本物のゲームを測るので、細かいメッシュありのまま（webServer を上書きする or perf の spec が `?microR=28` を付ける。perf の数が前と同じになること）。
4. **細かいメッシュのまま回す spec**（URL に `microR=28` を付ける）。次のどれかに当たる spec・テスト:
   - (a) 地形の画素・色・すけ・AO を読む（texA・seethru など）
   - (b) メッシュの段・セクション数・三角形・描画回数・メッシュのバイトを確かめる（voxE-mesh・texA AC12・m5 の上限など）
   - (c) 影を見る（shadow1）
   - (d) オーナーや ui-reviewer が地形の見た目を判断するためのスクショを撮る（m6-shots の HUD・m7 のはたけの景色など。ui-gate は DOM を見るだけなので付けない。下の「付けなかったもの」）
   - どれに付けたかを下の表に書く。迷ったら付ける（今と同じ＝安全側）。
5. **新しいテスト**（実装の前に赤）:
   - E2E: E2E の開発サーバーで `?microR` なしで開くと `world.sectionStats().microR === 0`、近くの列も `micro` の段がない。`?microR=28` を付けると 28 で、近くは `micro`。
   - ユニット: `normalizeMicroR(0) === 0`、既定の半径の決め方（環境変数 `off` → 0 / なし → 28 / URL が強い）。
6. テストの期待は変えない。test.fail()・skip を足さない。

## まもること
- 手元では、さわった spec と smoke だけ回す（`npx playwright test e2e/<spec>`、`--workers` は付けない）。全部は CI。
- `npm run check:fast` が通ること。
- `reuseExistingServer: true` なので、手元で `npm run dev` が動いていると E2E もそれを使う（細かいメッシュあり）。新しい E2E を確かめるときは dev サーバーを止めてから。

### 付けなかったもの（見たうえで、箱の段のままでよい）
| spec | 理由 |

| `e2e/ui-gate.spec.ts`（全画面 × 3 つの大きさ・CHAR-2 AC34・CHAR-4 AC13） | 見るのは DOM のくずれときまり。景色は HUD のうしろにあるだけ。ドット比べは同じ世界どうしの比べで、細かいメッシュの有無に関係ない。起動が 50 回以上あり、付けると 10 分近く増える。景色つきで ui-reviewer に見せたい画面ができたら、`boot()` にその画面だけ足す |

### rarity7 AC15 の時間切れ（原因）
細かいメッシュとは関係なかった。現在のコードで単独に回すと AC15 が 44 秒（2 本並列）、箱の段にした試作で 28 秒（AC14 も 27 秒）。持ち物の画面を開いて `step` を回す場面が重く、ほかの重い spec と並ぶと 60 秒をこえる（試作で seethru・voxE-mesh と並べると AC14・AC15 とも落ちた）。`rarity7.spec.ts` の時間の上限を 120 秒にした（m3・m5 と同じ書き方）。

## 新しいテスト（tester が書いた。実装の前は赤）
| ファイル | 中身 | いまの結果 |
|---|---|---|
| `e2e/e2e180-micro.spec.ts` | 既定（`?microR` なし）: `sectionStats().microR === 0`・micro の段 0・プレイヤーのいるセクションが `box`・近く（dist ≤ 20）に micro なし・LOD は今のまま / `?microR=28`: 28・近くは micro / `?microR=0`: 0 として受けつける / `playwright.config.ts` の webServer に `VITE_MICRO_DEFAULT=off` | 3 本が赤（既定・`?microR=0`・config）。`?microR=28` は今も緑（実装後にも緑のままでいる、片側の見まもり） |
| `src/world/render/voxel/tier.e2e180.test.ts` | `normalizeMicroR(0) === 0`・半径 0 の `nextTier` は micro にならない（距離 0 も箱。48 の前後と LOD は今のまま）・`MICRO_RADII` は 16/24/28 のまま・`decideMicroR` | 9 本が赤、4 本は今のまま守る見まもり |

**約束（開発へ）**: はじめの半径は `decideMicroR(search: string, envDefault: string | undefined): number` を `src/world/render/voxel/tier.ts` に作って export する。`main.ts` が `decideMicroR(location.search, import.meta.env.VITE_MICRO_DEFAULT)` を `renderer.config.microRadius` に入れる（影の `decideShadowStart` と同じ形）。URL の `?microR=0|16|24|28` > 環境変数 `off` → 0 > なし・ほかの値 → 28。数でない `?microR` は無いのと同じ。`nextTier(d, prev, 0)` は micro を返さない（`DEFAULT_MICRO_R` は 28）。

**試作での確かめ**（コミットに入れない、別の作業コピーで）: 上の約束どおりの最小の実装と config の 1 行を入れると、新しい E2E 4 本・ユニット 13 本・smoke 5 本・seethru 6 本・voxE-mesh 5 本・texA（AC2/4/7/10/12）5 本が緑になった。
