# SAVE-30: 保存がブロックの並び順の番号に頼らないようにする（issue #30）

| 項目 | 内容 |
|---|---|
| マイルストーン | 9×9×9（VOX-B より前） |
| 状態 | テスト準備中 |
| 周回数（全ループ合計） | 0 / 10 |

## 目的
`BLOCK_TYPES`（`src/world/blocks/blockTypes.ts`）の配列の添字が、そのまま保存の番号になっている。ブロックを途中に足したり並べかえたりすると、保存した世界のブロックが別の物に化ける（土が畑になる など）。VOX-B でブロック定義を大きく触る前に、保存が「id の文字」で読めるようにする。今のセーブは消さずに読めるまま残す（全部リセットは VOX-B で新しい世界になるときだけ。2026-10-16 オーナー決定）。

画面・絵・音は変わらない（デザイン・アート・サウンドは不要）。

## 番号が保存されている所（3 つ）
1. 列の保存（IndexedDB `chunks` の `data`。`src/save/chunkCodec.ts` の `encodeSections`）
2. pagehide の保険（localStorage `rikkun-world-pending` の `cells` = [x, y, z, 番号] × n。`src/save/SaveManager.ts` writePending / `src/save/restore.ts` readPending）
3. VOX-F より前の古い localStorage の保存（`blocks` = [位置, 番号] × n。`src/save/restore.ts` applyLegacySave。読むだけ）

ほかの保存（持ち物・たんす・かまど・農業など）は id の文字で持っているので対象外。

## 決めたこと（直し方）
- **列の形式を版 2 にする**（`CHUNK_FORMAT_VERSION = 2`）。縮める前のバイト列の頭に「この列で使う id の一覧（パレット）」を入れ、セクションの番号はその一覧の中の番号（0〜n-1）にする。読むときに一覧の id から今の `BLOCK_TYPES` の番号を引き直す。
  - 一覧を入れるのは `data` の中（縮める前の頭）。`StoredChunk` の形・IndexedDB・ファイルに出す/読む（`portable.ts`）の形は変えない。
  - 一覧のバイトの並びは開発が決めてよい（例: [id の数 n][各 id: 長さ 1 バイト + ASCII]）。uniform / palette / full の 3 つの形はそのまま。
- **版 1 の列は、凍らせた版 1 の id の表で読む**。表 `BLOCK_IDS_V1` は今の `BLOCK_TYPES` の id 31 個の並びを文字で書き写した定数（`BLOCK_TYPES` から作らない）。版 1 の列はさわったときに版 2 で書きなおされる。わざわざ全部を書きなおさない。
- **保険（pending）に `ids`（書いたときの id の一覧）を足す**。`cells` の番号はその一覧の番号。`ids` がない保険（今のビルドが書いたもの）は `BLOCK_IDS_V1` で読む。
- **古い localStorage の保存は `BLOCK_IDS_V1` で読む**。
- **知らない id**（ゲームから消えたブロック）が版 2 の列にあったら、その列はこわれた列として扱う（今と同じ: 生成に戻し `corruptColumns` に数える。ほかの列は読む）。保険の中の知らない id のマスは飛ばす。
- 古いビルドが版 2 の列を見たときは、今の `NewerFormatError` のしくみで読み取り専用になる（上書きしない）。新しくしなくてよい。
- 番号を自由に並べかえてよくなるが、**今回は `BLOCK_TYPES` の並びは変えない**（ほかのコードが番号の定数を使っているため。範囲外）。
