## 2. 音ファイルの 置き場所と形式（案。開発・サウンドが決めてよい）

- **置き場所**: `public/sound/nick/appear_oyabun.mp3`・`appear_taisho.mp3`・`appear_nushi.mp3`（Vite がそのまま配る）。
- **形式**: **mp3**（Chrome・Safari のどちらでも `decodeAudioData` で読める）。48kHz・ステレオ（左右のずらしを活かす）・128kbps 前後。ogg は オーナーの Mac のブラウザで鳴るのを確かめてからなら可。
- **小ささの目安**: 1 つ 130KB 以下・3 つで 400KB 以下（128kbps でファイルの長さ 5.3・6.3・7.9 秒 → 約 85・101・126KB）。おわりの 小さな残響（−60 dB より下）は 切ってよい（聞こえる長さ −20 dB までは 変えない）。
- **作る人**: `sfx-designer` が v4 の WAV（`B_appear_*.wav`）から ffmpeg で書き出す。**音そのもの（長さ・音色・大きさ）は 変えない**（オーナーが聞いて決めた物）。書き出したあと、ピーク・立ち上がり・聞こえる長さを測り直して 数を残す。
- **素材のきまり**: リポジトリに入れるのは 加工後の mp3 3 つだけ。v4 の `samples/*.mp3`（太鼓・心臓・鐘の元の素材）は **入れない**。加工の手順（`build.py`）は入れてよい（素材を読む場所は リポジトリの外）。
- **出どころの記録**: 音のそばに 説明ファイル（案: `public/sound/nick/README.md` か `docs/audio/CREDITS.md`）を置き、出どころ（効果音ラボ・URL）・使った素材（和太鼓 ドン・ドドン、心臓、お寺の鐘）・規約（加工してゲームに入れてよい・商用可・クレジット任意・素材の再配布不可）・尺八は合成・加工の方法（v4 README の「加工の方法」）を書く。
- **安全の数**: 音ファイルのピーク −1 dBFS 以下・立ち上がり（鳴りはじめ〈最大の 1%〉→ 最大の 9 割、meta の `attack_s`。今 1.11・1.86・2.90 秒）0.05 秒以上。途中の 太鼓の一撃（どーん）の急さは オーナーが聞いて OK 済み。ゲームで かける音量の倍率は 1 以下（大きくしない）。
- **鳴らし方**: はじめに読みこんで 鳴らす形にしておく（鳴らすときに待たない）。「効果音の音量」設定をかけ、0 なら鳴らさない。読みこめていない・失敗したときは 鳴らさず止まらない（§6）。BGM はまだ無いので、BGM を小さくする所は 作らなくてよい。
- **音の記録（テスト用）**: 二つ名の音の出来事 1 回で「鳴らす頼み」を 1 回記録する（読めたかどうかに関係なく）。実際に鳴ったかは 別に記録する。名前・窓口は開発が決める。
- **試聴ページ**: リポジトリに 3 つを鳴らせる ページを置く（ルール C「音を変えたら試聴ページで鳴らせる」。置く場所は開発が決める。v4 の `listen.html` の 出たとき B の所と同じ鳴らし方）。ファイルがあるかは ユニット、鳴るかは AC24 で オーナーが聞く。

## 4. テストの方針（ルール #102: テストは実装より先）

1. **tester が先**（ブランチの最初のコミット）:
   - E2E: `e2e/bal-b.spec.ts` の AC10 に「二つ名の音の出来事 1 回で、その二つ名の出現音の **鳴らす頼み** の記録が 1 回」（`src/fx/soundLog.ts` の列など。窓口と音の名前は開発と決める。**読みこみは待たない**・「鳴った」の記録は E2E では見ない）「たおしたときは 今の たおした音」を足す。2 体目の重ねない（§6）も 1 本。
   - UI 検査（AC19）: 二つ名の妖怪（たいしょう・ヌシ、色の段階 1〜3）・おしらせ・おの のアイコンと手に持った形 が写る画面を `npm run check:ui` の対象に足す（ない画面だけ）。
   - 新しいテストを 1 回回して **落ちる（赤）** のを確かめ、`code-reviewer` が基準どおりか見る。
   - こわれる既存テスト: `src/yokai/ai/hpBar.test.ts`（寸法が DESIGN 13.3 に変わる。「20 本で 1.6 以内」は そのまま通るはず）、仮の絵・★ を前提にした物があれば直す（消すなら理由を台帳に）。
2. **developer**: ユニットテストを先に書く（赤 → 緑）。例: 色の表どおりに差しかわる（13.1 の表の数 × 段階 2・3）、ちょうちんの どうが 3 段階とも暗くならない、アイコン・おの の絵が `itemArtBal` の物、重ねない時間が 聞こえる長さ（3.0・3.8・5.2 秒）、音量 0 で鳴らない、音量の倍率 1 以下、うその読みこみ係（成功・失敗・まだ）で「頼み」と「鳴った」の記録が分かれる、ファイルの安全の数（AC20 (2)。入れた mp3 を読んで ピークと立ち上がりを測る など、確かめ方は tester と決める）、試聴ページのファイルがある、ヌシの光の明るさの式（周期 2.5 秒・幅）。**テストの期待は変えない**（変えたいときは デザインへ差し戻し、台帳に）。
3. 回す E2E: `npx playwright test e2e/bal-b.spec.ts e2e/bal-c.spec.ts e2e/bal-d.spec.ts` と smoke（`npm run test:e2e:fast`）。全部は CI。
4. 検証: UI 検査 → `ui-reviewer`（違いが出た画面だけ）。スクショ（色 3 段階 × 夜・ヌシ・おしらせ・おの）と 試聴ページのパス、描画回数・三角形の前後を PR に。そのあと オーナー確認（AC21〜AC25）。
