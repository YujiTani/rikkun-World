# FIX-129: 右上の時計で、絵が月なのに文字が「あさ」（issue #129）

## わかったこと（PO が再現した）
- 正しいのは **文字**。ひる 1000 は `clockScene` で `morning`（ことば「あさ」、絵は 午前の太陽）。仕様 `docs/tickets/M6-clock.md` どおり。
- 原因は `src/ui/clock.ts` の入れかえ。時間帯が変わると、うしろの img に前の絵（よる の月）を入れ、前の img に新しい絵を入れて opacity 0 → 1 で 0.5 秒かけて出す。ことばは すぐ変わる。
- VOX-E のスクショは `time.set(1000)` で よる から一気に とばした直後に撮ったので、前の img が opacity 0 のまま（月だけ見える）に写った。再現: よる（70000）→ 0.8 秒待つ → `time.set(1000); step(1)` の直後、`.clock-word` は「あさ」、前の img は `is-fade` で opacity 0。
- ふつうに遊んでいるときも、変わり目の 0.5 秒は 絵とことばがずれるが、これは仕様の「ふわっと入れかえ」なので そのまま。

## なおし方（PO 決定）
- **時間が とんだとき（`time.set`・ロード・これからの ふとん など）は、絵を ふわっとさせずに すぐ入れかえる**。ことばと絵が その場でそろう。
- **ふつうに時間が進んで変わり目をこえたときだけ、今までどおり 0.5 秒で ふわっと入れかえる**。
- 「ふつうに進んだ」の見分け方: 前に `setTime` で見た dayTick から、1 日の長さで回りこみを考えた **前向きの差** が小さい（1 秒 = 60 ステップ以下）とき。それ以外（大きくとんだ・もどった）は「とんだ」。
  - 夜明けの終わり → ひる 0（回りこみ）は ふつうの進み。
- 見分けは純粋な関数にして `src/ui/clockModel.ts` に置く（ユニットテストできるように）。例: `clockShouldFade(prevTick: number | null, tick: number, s: TimeSettings): boolean`。
- `setTime(dayTick, settings, day)` の形は変えない。DOM（`#clock[data-scene]`・`.clock-word`・`.clock-img`・`is-fade`）も変えない。
- すぐ入れかえるときは、走っている `is-fade` もはずす（前の img が opacity 0 のまま残らないように）。

## 受け入れ基準
1. よる から ひる 1000 に `time.set` でとばし、1 ステップ進めた**直後**（待たない）: `#clock[data-scene=morning]`、ことば「あさ」、いちばん上に見えている絵が あさ の絵（前の img に `is-fade` がなく、opacity 1、src が あさ の絵）。
2. ほかの とびかたでも同じ（例: ひる → よる、よる → ゆうやけ）。絵とことばが いつもそろう。
3. ふつうに進んで変わり目をこえたとき（変わり目の少し前に set → 待ってアニメが終わる → step で変わり目をこえる）は、前の img に `is-fade` が付き、0.5 秒の入れかえが走る。終わったあとは opacity 1。
4. ユニット: `clockShouldFade` の境目（差 1・60 は true、61・大きくとぶ・もどる・最初（prev なし）は false、回りこみの 夜明け最後 → 0 は true）。

数は決め打ちせず、時間の長さや変わり目はゲーム（`window.__rikkun.time`・`clockScene` に合う dayTick）に聞く。たとえば変わり目は `h.time.set(t); h.step(1)` で `data-scene` が変わる所を探す、など。
