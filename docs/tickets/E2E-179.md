# E2E-179: テストの時計（E2E ではゲームの中の「ms の予算」を「1 コマ何個まで」にする）

| 項目 | 内容 |
|---|---|
| マイルストーン | テストの土台（#179） |
| 状態 | 準備中 |
| 周回数（全ループ合計） | 0 / 10 |

## 目的（オーナーの言葉で）
「GPU のない CI/CD 環境で、GPU 処理が必要となるチェックをしていることが問題」「ずっと続いているこの問題を解決したい」（yuzu 2026-10-17。案 A を選択）。調べた結果: project files `ci-gpu/PLAN.md`。

## なぜ（調べた結果）
- E2E のゆれのもとは、ゲームの中で 1 コマにする仕事の量が **本当の時間（ms）** で決まっていること。
  - `WorldRenderer` のメッシュ作り: 「1 コマ 8 ms まで（かならず 1 つは作る）」（`FRAME_BUDGET_MS`）。
  - `WorldLight` の光: 「1 コマ 2 セクション、ただし 3 ms まで」（`TIME_BUDGET_MS`）。
- 手元で測った 1 コマの仕事: 細かいメッシュありで小ブロック 1〜2 個、なしで箱 1〜4 個、光 1〜3 回。機械の速さで変わる。
- texA の `__quiet`（落ちつくまで `step(5)`）のように「落ちつくまで進める」テストは、進むコマ数が機械で変わる → 時刻や動くものの状態が変わり、描画回数などが ±1 ゆれる（PR #178 の texA AC14 116/117、perf m5 の 51/52）。
- 1 コマの仕事を **数** で決めれば、同じコマ数なら どの機械でも同じ結果になる。

## やること（決まり）
1. **時計の決め方**（`src/world/frameClock.ts` を新しく作る。名前は `decideMicroR` と同じ形）
   - `type FrameClock = 'time' | 'count'`
   - `decideFrameClock(search: string, envDefault: string | undefined): FrameClock`
     - 決める順: URL の `?clock=time|count` > 環境変数 `VITE_FRAME_CLOCK` が `count` なら `'count'` > `'time'`。
     - URL のほかの値・空は 無いのと同じ。
   - ふつうに遊ぶとき・`npm run dev`・`npm run perf`・公開したゲームは `'time'`（今のまま）。
2. **数の予算**（`'count'` のとき。値は `frameClock.ts` に定数で置く）
   - メッシュ（`WorldRenderer.process`、はじめの一気 `attach` は今のまま無制限）:
     1 コマに **作ったメッシュ（箱・小ブロック）8 個まで、そのうち小ブロックは 1 個まで**。小ブロックを 1 個作ったら、そのコマはおしまい。
     全部空気・見えないセクション（メッシュを作らない）は数えない。ただし 1 コマに 合計 256 個まで（止まらないように）。
     `'time'` のときは今のまま（8 ms・かならず 1 つ）。
   - 光（`WorldLight.update`）: 1 コマに **本当に計算したセクション 2 個まで（今の BUDGET）、ただで片づけるものもふくめて合計 64 回まで**。時間は見ない。
     `'time'` のときは今のまま（2 個・3 ms）。
   - 渡し方: `new WorldRenderer(world, microR, clock)`（3 つ目、既定 `'time'`）。`WorldRenderer` が `WorldLight` に渡す。
3. **E2E の設定**: `playwright.config.ts` の webServer の command に `VITE_FRAME_CLOCK=count` を足す（影・小ブロックと同じ所）。`playwright.perf.config.ts` は足さない（本物のゲームを測る）。
4. **テストの窓口**: `window.__rikkun.clock()` が いまの時計（`'time' | 'count'`）を返す。
5. **新しいテスト**（実装の前に赤）
   - ユニット: `decideFrameClock` の決め方。`'count'` の `WorldRenderer` で 1 回の `update()` が 作るメッシュ 8 個まで・小ブロック 1 個まで（`rebuildLog` の frame で数える）。同じ世界を 2 回作って同じコマ数 進めると `rebuildLog` が同じ。`'count'` の `WorldLight` で 1 回の `update()` の計算が 2 個まで。`'time'` が既定。
   - E2E（`e2e/e2e179-clock.spec.ts`）:
     - AC1: E2E の開発サーバーでは `__rikkun.clock() === 'count'`。`?clock=time` を付けると `'time'`。
     - AC2: 細かいメッシュあり（`fine()`）で開き、一時停止して同じ数だけ `step(1)` したとき、各コマで作った小ブロックは 1 個まで・メッシュは 8 個まで（`world.rebuildLog()`）。
     - AC3: 同じ URL を 2 回開いて、一時停止 → 同じ手順で「落ちつくまで進めた」コマ数と `rebuildLog`（x, y, z, kind, frame）と `renderStats()` の drawCalls・triangles が 2 回で同じ。
6. 遊び・見た目・音は変えない。既存のテストの期待は変えない。test.fail()・skip を足さない。

## やらないこと（調べて やめたもの。理由は PR に書く）
- E2E で実時間のループを止めて `step()` だけで進める: 80 か所のテストが `lock.simulate(true)` のあと実時間で進むのを使っている（期待を変える書きかえになる）。1 コマの仕事を数にすれば、実時間のループは「何コマ進んだか」を変えるだけで、そのテストはもともとゲームに聞いて待っている。
- 描くのはテストが頼んだときだけ: 2 回目からの描画は 1 回 0.005〜0.011 秒で重さの元ではない（PLAN.md §1）。一時停止中の `step()` のあとの 1 回の描画を、スクショのテストが使っている。
