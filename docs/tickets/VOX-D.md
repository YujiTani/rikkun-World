## 目的
VOX-B の「8×8 列（128×128）に固定・まわりを仮の海でかこむ」をやめて、**プレイヤーのまわりの列を、近い順に作り（または保存から読み）、遠くなったら捨てる**。歩けば世界がどこまでも続き、VOX-B で見えなかった大きな山も見に行ける（決定 2026-10-17-voxb-terrain-look）。起動は「足もとのまわりができたら すぐ始める」にして、それまでは「じゅんびちゅう」を出す。世界の果ては ±30,000 の見えない壁。設計は `docs/design/VOX-plan.md` §1・§2・§7・§8・§9・§10（オーナー OK 済み）。

## 範囲（この PR でやる・やらない）
1. **持つ範囲を輪にする**（§2）: プレイヤーのいる列を中心に、生成 8・光 7・描く 6・捨てるのは 10 より外（下の「数の表」）。列は「なし → 読みこみ中 → 生成ずみ → 光ずみ → メッシュずみ」と段を進む。
2. **128×128 の固定と、仮の海のふち（VOX-B S6）をやめる**（PO 既定 2）。`LOAD_BOUNDS` に頼った読みこみ・`applyEdgeSea`・洞くつの口の「海のふちにかかるか」の判定はなくす。どの列も `generateChunk` のそのままの形になる。
3. **起動を近い順にする**（§8）: 保存があれば保存したプレイヤーの位置、なければスタートを中心に、近い列から作る。「開始の条件」（下の表 K1〜K2）がそろったら遊べる。それまで「じゅんびちゅう」を出し、プレイヤーは動かさない（落ちない）。
4. **保存とのつなぎ**（PO 既定 4・§7）: 起動のとき IndexedDB は **meta と「ある列のキーの一覧」だけ**読む（列の中身は全部は読まない）。列がいるときに、一覧にあれば その 1 列だけ読み、なければ生成する。**さわった列（saveDirty）は、保存が書き終わってから捨てる**。
5. **列を捨てるときの、世界の上の物の扱い**（PO 既定 5。下の「列を捨てるときの決まり」）: 妖怪は静かに消す。落ちている物・たんす・かまど・畑は消さずに残し、その列が読みこまれていない間は止める。
6. **仮の regions と ふるい畑・やせいの やさい の置き場所**（PO 既定 3）: スタートのまわり 128×128 の四角 R を、ブロックを読みこまずに `terrainFor(seed).height` などの「高さ」だけで調べて、今の形（`WorldRegions`）のまま作る。読みこんでいる列・テレポートに関係なく同じ答え。biome にするのは VOX-G。
7. **±30,000 の見えない壁**（§1 の 10・§9）: プレイヤー・妖怪・落ちている物は壁をこえない。壁の外のマスは ほる・おく ができない。
8. **今の「世界は原点から 128」の前提をなくす**: `loadedBounds()` を「世界の大きさ」として使っている所（下の「直す所」）を、負の座標・動く範囲でも正しく動くようにする。
9. **新しい音・新しい絵はなし**（PO 既定 6）。じゅんびちゅうは、今ある HTML の画面と今あるアイコンで作る。`docs/fun.md` に足すものなし（達成ではないので演出は出さない）。
10. **やらない**: Web Worker（VOX-H）、regions → biome・高さの相対化の本番（VOX-G）、バイオームの中身（VOX-I）、`contracts.ts` の分割（#156。同時にやらない。`contracts.ts` には、ストリーミングと描画のつなぎ目に要る最小の型だけ足す）、ゲームの中で遠くへ飛ぶしくみ（`world.teleport` はテスト用だけ）。

### 計算しなおし
- 描く輪のふち: プレイヤーが列の中のどこにいても、描く輪のふちまでは 6×16 = 96 ブロック以上 ＞ 霧 88。切り口は見えない。
- R が開始の前にできているか: R の x の はし sx−64 の列は (sx >> 4) − 4、sx+63 の列は (sx >> 4) + 3 か + 4。R はスタートの列からチェビシェフ 4 以内 ⊂ 開始で生成ずみの半径 6（K3）。
- メモリ: 441 列 × 144 KB = 63.5 MB ≤ 64 MB（§2・§10）。
- 歩いて追いつくか: はしる 5.6 ブロック/秒 → 1 列（16）を 2.86 秒 = 171 コマで横切る。ななめに 1 列進むと 新しく 生成 33・光 29・メッシュ 25 列 ＋ 段の変わる列 約 10。見込み 生成 33×3 ms + 光 29×3 ms + LOD 25×2 ms + 小ブロック 10 列×4 セクション×15 ms ≈ 840 ms → 1 コマ平均 約 4.9 ms ＜ 8 ms。生成の輪（8）は プレイヤーより 7 列先にあるので、読みこんでいない列（`'outside'`＝固い）に ぶつかることはない。
- 開始までの見込み（クラウド）: 生成 169×3 ms ≈ 0.51 s ＋ 光 121×3 ms ≈ 0.36 s ＋ 小ブロックの段 約 21 列×4 セクション×15 ms ≈ 1.26 s ＋ 箱・LOD 約 60 列 ≈ 0.1 s ＝ 約 2.2 s ≤ 2.5 s。こえたら perf ループ（VOX-H の Worker の前に、順番と予算を見なおす）。

## 列を捨てるときの決まり（今のコードを見て、いちばん こわれにくい形）
今は 128×128 が いつも読みこまれているので、`getBlock` が `'outside'` を返す所 ＝「ブロックが消えた」として記録を消すしくみが いくつかある。列を捨てると、それが「消えた」と まちがえる。**読みこんでいない列の上の物は、消さずに止める**を原則にする。

| 物 | 今のしくみ（場所） | VOX-D の決まり |
|---|---|---|
| 妖怪 | 水平 64 より遠いと静かに消える（`YokaiManager.farTick`、`farRemoveDist 64`） | 列を捨てるとき、その列にいる妖怪は 静かに消す（落とし物なし。farTick と同じ扱い）。64 ＜ 捨てる距離（11 列 ≥ 160）なので、ふだんは farTick が先に消す。**出る場所は 描く輪（≤ 6）のメッシュずみの列だけ**。出る場所さがし・空を飛ぶ妖怪の はしの判定は、負の座標・動く範囲で正しく動く（今は `loadedBounds().x1` を「大きさ」に使っている） |
| 落ちている物（ふくろ・やられたときの ふくろ もふくむ） | 時間で消える（`DropField`）。meta の `bags` に保存 | **消さない**。読みこんでいない列の上では動かさない（落ちない・ながされない・ひろえない）。消えるまでの時間は 今と同じに進む。列がもどったら、その場所から また動く |
| たんす | ブロックが `tansu` でなくなると 中身ごと記録を消す（`StorageSystem.update`・`list`） | ブロックが `'outside'`（読みこんでいない）のときは **記録を消さない**（中身を守る）。消すのは、読みこんでいる列で ブロックが本当に変わったときだけ |
| かまど | 焼くのは ブロックに関係なく進む（`CraftSystem.update`） | 今のまま進む（焼きあがりも たまる）。開いている かまど の列が捨てられたら（ふつうは無い）画面を閉じる |
| 畑（作物・はたけ・じょうろの のこり・ごきげん・スプリンクラー） | 作物のマスが作物でないと記録を消す・はたけの見直しで はたけでないと消す（`FarmSystem.update`）。マスの番号は `loadedBounds()` の大きさで作る（`FarmSystem.ts:141-146`）。`pet`・`sprinkler` の番号も 範囲が せまい | 読みこんでいない列の畑は **時間を止める**（そだたない・かわかない・記録を消さない）。列がもどったら つづきから。列を読みこんだとき、その列の はたけ・スプリンクラーを数えなおす。**マスの番号は ±30,000・高さ 0〜351 のどこでも重ならない**こと（どう作るかは開発） |
| 光・メッシュ | `takeColumnEvents`・`syncColumns` で列の出入りを受けとる | 今のしくみで受けとる。捨てた列の となりの光は捨てない（§4） |
| 地下の「見えない」印 | `edgeClosedBelow = SEA_Y − 8`（仮の海のふち用） | 値は今のまま（読みこんでいない列の横は、y < 136 では ふさがっているとみなす）。輪のふちの洞くつから 地下が「見える」にならないように |

## 「じゅんびちゅう」の表示
新しい絵・音は作らない。今の案内画面（「クリックして あそぼう！」の大きいボタン）と、今あるブロックのアイコンを使う。字はひらがなだけ。

### 何を出すか
- **ことば**: 「じゅんびちゅう」と、そのあとに「・」が 0〜3 こ ふえて もどる（0.5 秒ごと。1 秒に 2 回 ＜ 安全の 3 回）。
- **ブロック 5 こ**: 今あるブロックのアイコン 5 しゅるい（どれにするかはアート。例: つち・いし・き・はっぱ・せきたん）を横に ならべる。まだの物は うすい（すけて見える）、できた物は ふつうの色。**できた数 = floor(p × 5)**（p は K4）。1 こ ふえたとき、その 1 こだけ 1 回 小さく はねる（0.2 秒。点滅はしない）。
- **分かること**: 字が読めなくても「ブロックが 左から そろっていく → ぜんぶ そろったら あそべる」が分かる。こわくない（暗くしない・ぐるぐる回る矢印や 時計は使わない）。待つ間も、案内のタブ（あるく・ほる…）は 今までどおり押して見られる。

## テスト用の窓口（`window.__rikkun`）
`world.*`（`src/world/hook.ts`）に足す。今ある物は 今の名前のまま使う。

```ts
teleport(x: number, z: number): void;              // テスト用。中心を (x, z) の列にして 輪を作りなおす。そろうまで プレイヤーは動かず、そろったら (x, groundHeight + 1, z) に立つ。じゅんびちゅう は「遠くへ もどる」と同じ
stream(): {
  ready: boolean;                                   // 開始の条件（K1・K2）がそろっている
  phase: 'boot' | 'play' | 'wait';                  // 起動中 / 遊んでいる / 遠くへ もどる・テレポートで待っている
  progress: number;                                 // K4 の p（0〜1）
  center: { cx: number; cz: number };
  columns: { loading: number; generated: number; lit: number; meshed: number }; // 今その段にいる列の数（meshed は lit・generated に数えない）
  queued: number;                                   // 待っている仕事の数（0 = 輪が全部そろった）
  saving: boolean;                                  // 保存（捨てる前の保存・ふだんの保存）が書いている途中
  unloadPending: number;                            // 輪の外になったが、保存の書き終わりを待って まだ捨てていない列の数
  totals: { generated: number; readFromSave: number; unloaded: number; savedBeforeUnload: number }; // 起動からの合計
  frameMs: { last: number; max: number };           // 記録用（合否は perf）
};
settle(opt?: { full?: boolean; maxFrames?: number }): Promise<ReturnType<WorldHook['stream']>>;
  // 次の 3 つが そろうまで進める: ① ready（full なら queued 0 も） ② saving === false ③ unloadPending === 0。
  // 保存の書きこみ（IDB の返事）も待つので、そのあと「捨てた列は読みこまれていない」「hasChunk が true」を すぐ見てよい。
  // maxFrames（既定 2000）で やめて そのときの stream() を返す
setStreamWork(n: number | null): void;               // B4。`?streamWork=<n>` と同じ。null で 本番の ms の予算
chunkStage(cx: number, cz: number): 'none' | 'loading' | 'generated' | 'lit' | 'meshed';
wall(): number;                                     // 30000
```
- **`__rikkun.ready`**: `__rikkun`（と `__rikkun.world`）は 今と同じ時に置く。`__rikkun.ready` だけ、**起動の `stream().ready` が true になってから** true にする（今の spec は `__rikkun.ready === true` を待っているので、どの spec もさわらずに 開始のあとから始まる）。一度 true になったら、テレポート・遠くへ もどる で `stream().ready` が false になっても `__rikkun.ready` は true のまま。起動中を見たいテスト（基準 5・24）は `__rikkun.world` が置かれるのを待ち、`stream()` を見る。
- `loadedChunks()` は 読みこんでいる列 全部（起動で動かなければ 289）。
- `size()` は `{ x, y: 352, z }`。x・z は 読みこんでいる範囲の はば（動く。テストは x・z を使わない）。
- `spawn()`・`startTorch()`・`regions()`・`caveMouths()`・`terrainAt()`・`genHash()` は、その列が読みこまれていなくても 同じ答え。
- `save.*`: `hasChunk(cx: number, cz: number): boolean`（IDB の キーの一覧にある）を足す。`save.info()` に `storedChunks: number`（キーの一覧の数）を足す。
- `player.respawn()`（スタートへ もどす。やられた・落ちた と同じ道すじ）。今ないなら足す。
- `?streamWork=<n>`: B4（テスト・UI 検査用）。ふだんは使わない。
