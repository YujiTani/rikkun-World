## 性能（前回との比較）
前回は仮の景色（箱 1 つ）の記録。今回は島（スタート地点・北向き）。クラウドは GPU なし（SwiftShader）なので fps は見ない。

| 項目 | 前回 | 今回 | 目標 |
|---|---|---|---|
| drawCalls | 1 | 25 | 100 以下 |
| triangles | 768 | 14,738 | 300,000 以下 |
| geometries / textures | 1 / 0 | 18 / 1 | |
| stepMsMedian | 0.1 | 0.6 | |
| stepMsP95 | 0.2 | 1.4 | |
| ブロック変更の作り直し（20 回の中央値） | - | 1.7〜3.3 ms（2 回計測） | 4 ms 以下（記録のみ） |
| ブロック変更の作り直し（最大） | - | 16〜23 ms | 8 ms 以下（記録のみ。**超えている**） |

描画回数・ポリゴン数は目標に十分ゆとりがある。作り直しの最大が 8 ms を超えるのは、最初の 1 回（チャンクのバッファを作る）が遅いなどの見立て。M2 で掘るたびにカクつくか、perf チームに見てもらうとよい。

## 見つけた問題
NG はなし（台帳への追記なし）。次は NG ではない気づき。
- 【軽微・気づき】`src/debug/testHook.ts` の `player.get()` の型が `unknown` で、E2E は `window.__rikkun as any` で回避した。型を付けると書きやすい。
- 【軽微・気づき】AC37 のボタンの幅が 512px の下限ぎりぎり（512.48〜513.97）。画面の幅 40% の指定が実測で割れそうなら余裕を持たせる。
- 【軽微・気づき】AC19 の最大値（目標 8 ms）超過、AC21 の岩山の小ささ、AC22 の海の色のくすみは上の表のとおり（オーナー確認で見てもらう）。
- 既知の軽微な点（世界の端の水の細い線、タイトルの「準備中」、作り直し時間の目標は記録のみ）は NG にしていない。
