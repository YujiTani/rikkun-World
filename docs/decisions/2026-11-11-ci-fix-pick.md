# 2026-11-11 CI の赤を直すあいだは落ちた spec だけ回す（#444）

オーナー（yuzu）: 「CI error を修正するたびに、もういちど push してすべての CI をまわしてます。30 分かかる」→ 直すあいだは落ちたテストだけ、最後に 1 回全部、の形に OK。「私の操作不要でそれを判断するようにしてほしい」。

## しくみ（`ci.yml`。案は `docs/setup/ci-e2e-pick.yml`）

スレッドは GitHub の API でワークフローを手で動かせない（`workflow_dispatch` は 403。2026-11-11 に確かめた）。スレッドにできるのは push と、PR を draft にする・やめることなので、その 2 つで切りかえる。

- PR が **draft** で、先頭のコミットのメッセージに `[e2e: e2e/a.spec.ts e2e/b.spec.ts]` がある → その spec だけを 1 ジョブ「E2E（えらんだ spec）」で回す（数分）。型・ユニットはいつもどおり回る。
- このとき必須チェック「E2E（全部）」は、えらんだ spec が通っても**わざと赤**にする（全部を回すまでマージできないように）。
- draft をやめる（ready）と、同じコミットで全部（6 シャード）が回る。
- draft でない PR・`[e2e: …]` がないコミット・main への push は、今までどおりいつも全部。

## 手順（PR を出したスレッドが自分で判断して進める。オーナーには聞かない）

1. **赤を読む**: 落ちたジョブのログから、落ちたテストの spec を拾う。テストの名前が出ていない赤（45 分切れ・`npm ci` やダウンロードの失敗・ランナーが止まった）は **4.** へ。
2. **PR を draft にして、直しを push**: コミットのメッセージの最後のほうに `[e2e: <落ちた spec> <さわった所の spec> e2e/smoke.spec.ts]` と書く（1 行で、空白で区切る。`e2e/m7.spec.ts:120` のように行の番号も付けられる）。
3. **結果を見る**: 見るのは「型チェックとユニットテスト」と「E2E（えらんだ spec）」。「E2E（全部）」の赤は「全部はまだ」の印なので直さない。
   - えらんだ spec が赤 → 2. にもどる。
   - 緑 → PR の **draft をやめる**。全部が 1 回回る。緑ならマージへ（自動マージの予約は draft にすると外れるので、ここで入れ直す）。別のテストが赤なら 2. にもどる。
4. **時間切れ・不調だけの赤**: 直さず、落ちたジョブだけ再実行を 1 回（API の `rerun_failed_jobs`。権限がなくてできないときは、PR を draft にしてすぐやめると全部が回り直す）。同じ形で 2 回つづいたら原因を調べる。
5. **再実行で通ったテスト**は「ゆれ」なので issue にする（skip・削除で緑にしない）。

## 注意
- 新しい `ci.yml` が入る前に main から分かれたブランチでは、このしくみは動かない（いつも全部回る）。先に main を取りこむ。
- 最初の push（PR を出すとき）は draft でないので全部回る。全部の結果を 1 回見てから直しはじめる。
- `.github/workflows/` はスレッドから push できない。ワークフローを変えるときは `docs/setup/` に置いてオーナーに入れてもらう。
