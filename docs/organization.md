# 開発組織図（ドラフト v0.1）

> ステータス: **壁打ち中**。オーナー（人間）と相談しながら更新していく。

## 基本の考え方

AI エージェントを「チーム」として分け、それぞれに役割・入力・出力・権限を決める。
エージェント同士は直接おしゃべりせず、**成果物（ドキュメント・コード・テスト結果）を受け渡す**ことで連携する。
こうすると、どこで何が決まったかが Git に全部残り、あとから追いかけやすい。

## 組織図

```
                    ┌─────────────────────────────┐
                    │ オーナー（人間 / パパ）        │
                    │ ・方向性の決定・最終承認        │
                    │ ・りっくん（6歳）のプレイ観察   │
                    └──────────────┬──────────────┘
                                   │ 要望 / 承認
                    ┌──────────────▼──────────────┐
                    │ PO エージェント（とりまとめ）    │
                    │ ・計画/マイルストーン管理        │
                    │ ・タスク分解と各チームへの依頼    │
                    │ ・受け入れ判定 → オーナーへ報告  │
                    └───┬──────────┬──────────┬───┘
              仕様依頼   │   実装依頼 │   検証依頼 │
          ┌─────────────▼┐  ┌──────▼──────┐  ┌▼─────────────┐
          │ デザインチーム │  │ 開発チーム    │  │ テストチーム   │
          │ ゲーム体験/   │→ │ コード実装    │→ │ 自動テスト/   │
          │ 見た目/UI仕様 │  │ ユニットテスト │  │ 画面確認/報告  │
          └──────────────┘  └──────▲──────┘  └──────┬───────┘
                                   └── 不具合チケット ──┘
```

## 各チームの役割（案）

| チーム | 担当すること | 受け取るもの | 出すもの | やってはいけないこと |
|---|---|---|---|---|
| **PO** | 計画・優先順位・タスク分解・受け入れ判定 | オーナーの要望、各チームの報告 | タスク票、マイルストーン報告 | 自分でコードを書く |
| **デザイン** | 遊びの仕様、6歳向けの分かりやすさ、見た目・色・UI・効果音の方針 | PO のタスク票 | 仕様書（`docs/design/*.md`）、受け入れ基準 | 実装の詳細を決める |
| **開発** | 仕様どおりに実装、ユニットテストを書く | 仕様書、不具合チケット | コード、PR 相当のコミット | 仕様を勝手に変える |
| **テスト** | 自動テスト実行、ブラウザで実際に動かしてスクショ確認、受け入れ基準チェック | 仕様書の受け入れ基準、実装 | テストレポート、不具合チケット | 不具合を自分で直す |

ポイント: **開発チームとテストチームを分ける**ことで「作った本人が自分でOKを出す」状態を防ぐ。

## 1つの機能が完成するまでの流れ

1. オーナー → PO: 「モンスターと戦いたい」
2. PO → デザイン: 仕様を書いて（受け入れ基準つき）
3. デザイン → PO: 仕様書（例: スライムはジャンプで近づく、3回叩くと倒せる）
4. PO → オーナー: 仕様の確認（ここで方向修正しやすい）
5. PO → 開発: 実装して
6. 開発 → テスト: 実装完了
7. テスト → 開発: 不具合あれば差し戻し（最大 N 回）／ OK なら PO へ
8. PO → オーナー: 「できました。こう遊べます」
9. **オーナー＋りっくんが Mac で実際に遊ぶ** → 感想が次の要望になる

## 実装方法（Claude Code での実現案）

- PO = メインのセッション（オーケストレーター）
- デザイン / 開発 / テスト = `.claude/agents/` に定義するサブエージェント
  - それぞれにシステムプロンプト（役割・ルール）と使ってよいツールを設定
  - 例: デザインはコードを編集できない、テストはソースを編集できない
- 受け渡しはファイル（`docs/design/`, `docs/test-reports/`）と Git コミット
