## 1. 道具の ながれ

```
見本（オーナー）→ PixelLab（下絵。いる ときだけ）→ Pixel Art Studio（仕上げ。build.py で 1 点ずつ）→ 見本シート → art-reviewer → オーナー → developer が ゲームへ
```

| 道具 | 使う とき | 使わない とき |
|---|---|---|
| **PixelLab**（v2 の REST API） | キャラ・妖怪の 8 方向、アイテムの 形の 案、エフェクトの 時間の 割りふりの 下絵 | 16×16 の 仕上げ（自分で 描く 方が そろう）。数が たりない とき |
| **Pixel Art Studio**（Skill `.claude/skills/pixel-art-studio/`） | **すべての 仕上げ**。パレット・ふち線・にじみ・コマを そろえる。下絵の 掃除（`pixelpipe.py`） | ― |
| **meshy**（契約ずみ） | 3D の 形が 本当に いる 物だけ（手に 持つ 物の 立体・3D の キャラ）。画像 → 3D で 作って modeler が 整える | 板の エフェクト・アイコン・タイル |
| **Blender MCP** | 手に 持つ 物の 押し出し・3D の 止め絵（MOTION の 決めポーズ） | 2D だけの 物 |

### 1.1 PixelLab の 使い方
- **v2 の REST を 使う**（`https://api.pixellab.ai/v2`。説明 `GET /v2/llms.txt`・`/v2/openapi.json`）。v1 の Python SDK は USD で はらう ことが あるので 使わない。
- 認証: クラウドでは 通信の 途中で 自動で つく → `Authorization: Bearer dummy`。手元では 環境の 変数 `PIXELLAB_SECRET`。
- **呼ぶ 前と 後に `GET /v2/balance` を 記録**する（`art/<ID>/pixellab/balance_*.json`）。お試しは「generations」の 回数で はらう（USD は 0 の まま）。
- 1 回の 値段（2026-10-21 に 説明と 実際の 請求で たしかめた）:

  | 呼ぶ 所 | 使う 回数 | 向く 物 |
  |---|---|---|
  | `POST /vfx`（`artist: "lite"`） | **1** | エフェクトの 下絵（コマ・時間の 割りふり） |
  | `POST /create-image-pro-flash`（32×32 など） | 5 → **いまは 使わない** | （アイテムの 形の 案） |
  | `POST /create-1-direction-object` | 10〜25 | 使わない（高い） |
  | `vfx` の `pro` | 6〜28 | 使わない（lite で たりる） |
- **2026-10-21 オーナー決定「PixelLab は いったん lite で」: 1 回 1 generation より 高い 呼び方（Pro Flash・Pro・object など）は 使わない。** いま 使って よいのは `POST /vfx` の `artist: "lite"`（新しく 作る・`effect_id` と `conversation` で 直す、どちらも 1）だけ。ほかの 呼び方を 使う ときは、先に 値段を 説明で たしかめ、1 より 高ければ 使わない。
- 1 issue で 呼ぶ 回数の 上限は 依頼文で 決める（今回 5 回 まで → 2 回・6 generations）。
- 返って くる 物は 非同期: `background_job_id` を 5〜10 秒ごとに `GET /v2/background-jobs/{id}`。
- 出来た 絵は `art/<ID>/pixellab/` に 置く。**そのまま ゲームに 入れない**（下絵）。PixelLab の 規約（お試しの 回数で 作った 物を 公開して よいか）は、本番で 使う 前に PO が たしかめて 書く（オーナー確認待ち）。

### 1.2 Pixel Art Studio の 使い方（このリポジトリでの 読みかえ）
- Skill の 例の `./pixel-art/<slug>/` は **`art/<ID>/<名前>/`** に 読みかえる。`build.py` が 絵の 元（毎回 同じ 絵が できる スクリプト）。書き出した PNG を 手で 直さない。
- Skill の `sys.path` の 例は **`.claude/skills/pixel-art-studio/scripts`**（リポジトリの 根から）:
  ```python
  ROOT = os.path.abspath(os.path.join(os.path.dirname(__file__), "..", "..", ".."))
  sys.path.insert(0, os.path.join(ROOT, ".claude", "skills", "pixel-art-studio", "scripts"))
  from pixelstudio import Sprite
  ```
- `open` は クラウドでは 使えない。かわりに `preview.png` を Read で 見る。
- 回し方: 描く → `preview.png`（拡大）と `s.stats()` を 見る → `references/validations.md` で ダメ出し → 直す を **2〜3 回**。
- 乱数は `random.Random(seed)` か `noise(seed=)` だけ。
- 下絵の 掃除: `python3 .claude/skills/pixel-art-studio/scripts/pixelpipe.py <下絵.png> --max-colors <色の 数>` → できた `build.py` を 続けて 直す。

### 1.3 置き場所

| 物 | 場所 |
|---|---|

| PixelLab の 下絵・残りの 記録 | `art/<ID>/pixellab/` |

## 2. 全部の 絵に 共通の きまり

### 2.1 パレット
- 物の なかまごとの 色は DESIGN.md の 表を 使う（世界の タイル = `textures.ts`・妖怪 13 章・どうぶつ 16 章・めずらしさ 13b 章・UI = `tokens.css`）。新しい 色は 足す 前に 見本シートで 並べて 見せる。
- 色の 段は CRITERIA 7: 明るい ほど 少し あたたかく、暗い ほど 少し つめたく。真っ白・真っ黒・いちばん 強い 色は 使わない。世界に ピンク・マゼンタ・真っ白を 使わない（DESIGN 6 章）。
- 色の 数の 上限（2026-10-21 オーナー OK）: アイテムの アイコン **12 色まで**（ふち 1 ＋ 物 3 段 × 2〜3 なかま ＋ 光 1）、1 つの エフェクト **5 色まで**、キャラ・妖怪 1 体 **16 色まで**。
- 雷・光の エフェクトは 足し算で 重ねる。**暗い 色 = すける**（半透明の 点は 使わない）。にじみは 暗い 色の 網（ディザ）で 描く。

### 2.2 ふち線
| 物 | ふち線 |
|---|---|
| 世界の ブロック | **描かない**（DESIGN 2 章。形・面の 明るさ・AO で 出す） |
| アイテムの アイコン | **1 点の こい 色**（物の いちばん 暗い 色より もっと 暗い 同じ なかまの 色。例: 雷神剣 `#1B1240`、おの `#2A1E14`）。外がわ だけ。光の 小さな しるし（稲妻・きらり）には 付けない |
| エフェクト | 描かない（足し算の 光なので）。形は 芯と にじみの 明るさの 差で 出す |
| キャラ・妖怪の ドット絵 | （オーナー確認待ち。3 案で 決める。今の 案は「外がわ 1 点・光の 側は 1 段 明るい ふち（selout）」） |

### 2.3 光の 向き
- ドット絵（アイコン・キャラ・妖怪の 板）: **左上から**。光の 側（左上）が いちばん 明るく、右下が かげ。刃物の 光の 線も 左上の がわに 置く。
- 世界の ブロック・3D: DESIGN 3.1 の 面の 明るさ（上 1.0・南北 0.8・東西 0.6・下 0.5）。絵の 中に 影を 描きこまない。
- エフェクト: 自分で 光る。影を 描かない。かわりに 2.5 の「まわりを 明るく」で 世界に 光を 当てる。

### 2.4 大きさ（1 点の 大きさ）
| 物 | 絵の 大きさ | 1 点 |
|---|---|---|
| 世界の タイル | 16×16 | 1/16 ブロック（DESIGN 2 章） |
| アイテムの アイコン | 16×16（今の アイコンと 同じ。マスには 整数倍で 出す） | ― |
| 小さな エフェクト（火花・パリィ・かけら） | 32×32 まで | 1/16 ブロック（タイルと 同じ） |
| 大きな エフェクト（雷・真空波・ドーム） | 雷 B は 1 コマ 64×256 | **1/8 ブロック**（タイルの 2 点。いつも タイルの 整数倍） |
| 地面に 寝かせた 輪 | 96×96（半径 6 ブロック） | エフェクトと 同じ |
| キャラ・妖怪の 板 | （オーナー確認待ち） | ― |

- 1 つの 絵の 中で 点の 大きさを まぜない（回す・のばす・ちがう 大きさの 貼りつけを しない）。
- ゲームの 中では Nearest・ミップマップなし（`generateMipmaps = false`）。UI は `image-rendering: pixelated` で 整数倍。

## 3. エフェクトを「ペラペラに 見せない」 6 つの 作り方（絵を 作る 側の きまり）

ART-PIPE-1 の 試作 1 の 6 つを、pixel-artist が 守る 形に した もの。数は 雷で ためした 目安（オーナーが ゲームの 中で 見て 変えて よい）。

1. **カメラに 向く 板 ＋ 決めの コマ**
   - 板の 向き: おちる・たつ 物（雷・光の 柱）は **たて軸だけで カメラへ 向く 板**（Y 軸の ビルボード。上から 見下ろしても 板が ねない）。とぶ 物（真空波）は 今の 十字の まま。
     **（2026-10-21 オーナー OK: 雷だけ。DESIGN 17・18 章）** DESIGN 17 章（2026-10-19「ドット絵の 板の エフェクトは ぜんぶ 十字」）と ちがう。十字は 斜めから 見ると 2 まいが 左右 反対に かさなって 二重に 見える（`art/ART-PIPE-1/thunder-*/sheet.png` の 8 方向ならべ 上の 段）。2026-10-21 の「常に カメラに 向かって 正面と なり、一番 決まる 絵が 表示される」に 合わせて 変える 案。
   - コマは **4 区間**（予兆 → のびる → 決め → 余韻）。描く 絵は 6〜8 コマ。
   - **決めの コマは 1 まいの 絵を 6 ステップ（2 ステップ/コマ で 3 コマ分）止める**。のびるは 1〜2 コマで 一気に（間を ぬるく しない。MOTION 8）。
   - 形の 数（バリエーション）は 4 通り。同じ 作り方で seed を 変える。
2. **ささる 所を うすく（ソフトパーティクル）**
   - 板の 下の 2〜3 行（1/4〜3/8 ブロック）を **網で 4 段** ぬく（なめらかな 半透明に しない）。
   - そのうえに 着地の 形（とげの 星・光の 玉・はんこ）を 重ねて、地面との 切れ目を かくす。
   - ゲームの 側の「深さで うすく する」は developer の 仕事（絵の 側は 上の 2 つ まで）。
3. **奥行きを ずらした 3 まい ＋ つぶ**
   - 奥 = にじみ（暗い 色の 網、太い）・中 = からだ・手前 = 芯（いちばん 明るく 細い）。ゲームでは −0.3 / 0 / +0.3 ブロック ずらす。
   - 3 まいは **1 まいの 絵（アトラス）**に ならべる: たて = まい（奥 → 手前）、よこ = コマ、さらに 下へ 形の 数。→ 描画 1 回。
   - つぶは 別の 小さな 絵（2×3 くらい）。出る ときは 明るい 色、きえる ころは 1 点の 暗い 色（点滅させない。だんだん 暗く）。数は 30〜40。
4. **地面に 寝かせた 光の 輪**
   - 上から 見た 絵で 描く（カメラに 向けない）。**輪の 半径 = 攻撃の 半径**（雷は 5 ブロック = 40 点）。
   - 2 まい: 「出る」（輪 ＋ 中の もよう）と「きえる」（輪だけ・暗い 色）。広がりと 明るさの へり方は コードで。
5. **出た しゅんかんだけ まわりを 少し 明るく（色つき）**
   - 絵ではなく 光の 数で 決める: 色は 芯の 色（黄みの 白）、明るさ **+35% まで**、半径 8 ブロック、**1 回だけ**、12 ステップで 3 段に さがる。空は 明るく しない。画面 全体の 白い ぴかっ は しない（DESIGN 15.4・`fun.md` 6）。
   - 光は シーンに 置きっぱなしの 1 つで 強さだけ 変える（足したり 消したり すると 作りなおしが おきて 重い）。
   - 「うごきを へらす」では 光は 半分、つぶは 出さない。
6. **ドット絵の まま**
   - Nearest・ミップマップなし。1 点の 大きさは タイルの 整数倍（2.4）。にじみも 網で 描き、なめらかな グラデーションを 使わない。半透明の 点を 作らない（`stats()` の semi-alpha 0）。

### 3.1 数の 上限（エフェクト 1 つ。2026-10-21 オーナー OK）
| | 上限 | 雷の 3 案 |
|---|---|---|
| 描画回数 | **4 まで** | 3（雷の 板 1・地面 1・つぶ 1）。今の 雷は 5 |
| 三角形 | **150 まで** | 64〜88 |
| 絵の 大きさ | 1 まい **4096 まで**（たて・よこ） | 雷 B 1024×1024、地面 256×128 |
| 同時に 出る 数 | 1 しゅるいに つき 1 つ（雷は ため が いるので かさならない） | ― |
