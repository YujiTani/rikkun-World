# VOX-C 性能レポート

- 判定: 合格（光の初期化の時間・メモリとも前より小さい）
- 計測シナリオ: クラウド（GPU なし）。
  1. `e2e-perf/m5.perf.ts`（今の島 128×48×128。worktree の中、前=VOX-C の 1 つ前のコミット、後=この変更。各 2 回）
  2. `src/world/light/lightPerf.test.ts`（島を 128×H×128 に置いた世界。H=48 と H=352。地下は石でうめる。前の光=`referenceLight.ts` の全部いちまい計算、メモリは前の 4 枚ぶん）

## 数値（改善前 → 改善後）
| 項目 | 改善前 | 改善後 |
|---|---|---|
| 光の初期化 H=48（m5.perf, lightInitMs） | 143.6 / 137.2 ms | 42.3 / 40.0 ms |
| ブロック 1 個ほる→次のコマの作り直し 中央値（m5.perf, rebuild） | 232 / 180 ms | 64 / 65 ms |
| 光の初期化 H=48（lightPerf） | 167〜200 ms | 52 ms |
| 光の初期化 H=352（lightPerf） | 439〜607 ms | 89 ms |
| 光のメモリ H=48 | 3.1 MB（4 枚） | 0.47 MB |
| 光のメモリ H=352 | 23.1 MB（4 枚） | 0.47 MB（地下は「持たない」ので高さを上げても増えない） |
| ブロック 1 個ほって 光を全部計算（H=48 / 352） | （全体の箱を計算） | 約 17 ms / 約 15 ms（27 セクションぶん。1 コマ 2 セクションずつなので 約 1.2 ms/コマ） |

## 原因の分析
- 前は世界ぜんぶ（原点から広がる 1 枚の配列 × 4）を毎回なめていた。今は ①ふさがったセクション（光 0）は読まない・持たない ②地面より十分上の空だけのセクションは 1 バイト ③のこり（地面の近く）だけ 3×3×3 の箱から計算する。
- 初期化は 横 4×4 列 × たて 4 セクションのかたまりでまとめて計算（箱のかさなりを減らす）。
- 空の光は列ごとの高さ地図から「高さより上は 15」とし、まわりの高い列に面した所だけ広げの元にする（全部を待ち行列に入れない）。

## 改善案（優先度順）
1. 光の計算を Worker へ（計算は three を使わず配列だけ。順番に関係なく同じ答えなので出せる）。
2. たいまつの作り直しが目立つなら、光を 3D テクスチャにする案 B。
