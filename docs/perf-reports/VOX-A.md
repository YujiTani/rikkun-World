# 性能メモ VOX-A（列＋セクションの入れ物）

見た目と動きは変えない PR。入れ物を「1 本の配列」から「列の辞書＋セクション」にしたので、読み書きの時間が悪くならないかを前後で比べた。
クラウドは GPU なしで、時間は 1 回ごとにゆれる（±20% くらい）。数回の中央値で見る。

## `npm run perf`（e2e-perf/m5.perf.ts、3 回ずつ）

| 項目 | 前（main） | 後（この PR） |
|---|---|---|
| 島を作る genMs | 82 / 81 / 88 ms | 68 / 94 / 89 ms |
| 最初の光 lightInitMs | 146 / 134 / 156 ms | 131 / 140 / 167 ms |
| 1 チャンクの作り直し（掘る→作り直し）中央値 | 159 / 141 / 146 ms | 126 / 137 / 143 ms |

描画回数・三角形の数は同じ（start: 66 回・27,726 三角形）。

## 部品ごと（vitest の小さい計測。15 回の中央値）

| 項目 | 前 | 後 |
|---|---|---|
| 島の生成 | 33〜42 ms | 40〜41 ms |
| 光の最初の計算 | 138〜152 ms | 152〜154 ms |
| 64 チャンクのメッシュ | 77〜83 ms | 81〜99 ms |

## やったこと（読み書きを速くした所）
- `getIndex`: 全部が整数かを `x === (x|0)` で見る・直前の列を覚える（辞書を引かない）・full のセクションは配列を直接読む（`Column.fast`）・uniform は番号をそのまま返す。
- `setBlock`: full のセクションの中は直接書く。dirty は列ごとの印（ビット）と一覧で持ち、`Set` を毎回さわらない。「見えない」印のつけなおしは、だれかが印を読むまで何もしない。
- 保存の全マス比べ: 1 マスずつ `getIndex` を呼ぶのをやめ、`fillFlat` で平らな配列に写してから比べる（比べる回数は同じ、呼び出しが減る）。
