# VOX-B 性能レポート（無限の地形の生成）

- 判定: 合格（クラウドで測れる範囲。本当の fps はオーナーの Mac の F3 で見る）
- 計測シナリオ: `npm run perf`（m5 の 5 視点）、起動直後の `renderStats()` / `genStats()` / `sectionStats()`（seed 20261012、SwiftShader）。クラウドの時間は ±20% ゆれる。

## 原因の分析
- 新しい地形は 高さ 352 の地下に 洞くつ・鉱石があり、地下のセクションが「空気をふくむ」ため、ふさがった判定（全マスがふさがった）だと 洞くつのセクションがぜんぶ作られた。起動の 10 秒ほど、メインスレッドが 1 コマ 150〜300 ms ふさがった。
- 対策として「空にとどいていない地下の空気」も「見えない」にした（`VoxelWorld.buildExposure`）。空・読みこんでいない列・ほった穴につながった空気を 幅優先で数える（77k マス、約 70 ms、最初の 1 回だけ）。ほると、つながった洞くつのセクションだけ作りなおしに入る（`noteDug`）。
- 世界のふちの地下（海ゆかの下）は 外から見えないので、`edgeClosedBelow = SEA_Y - 8` より下は ふちの列も「見えない」にできる。
- 残りの「見える」洞くつは 地上の口につながっているもの（口は 4 列に 1 つの見積もり、mouthChance 1/4）。

## 改善案（優先度順）
1. 洞くつの「見えない」は 口からの距離・視線で さらに減らせる（口が遠い洞くつを 箱ティアに落とす）。
2. 起動の最初の 1 列 61 ms は JIT。気になるなら 生成を 2 列ずつ分けて 起動画面に出す。
3. 保存から戻した「ほった穴」は 記録されないので、ふさがった部屋は「見えない」と数えられる（まれ。ほると 直る）。

## オーナーに Mac で見てほしいところ（F3 で fps 確認）
- スタートから 山・森・洞くつの口へ歩いて、F3 の fps が 落ちないか。
- 洞くつに入る・出る・ほるときの カクつき（地下のセクションが 作られる瞬間）。

## texA の上限の決め直し（PO の判断）
前の上限は平らな島のころの数字。新しい地形（山・起伏・足の下の洞くつ）では、見た目を変えずに入れられないと developer が確かめた。オーナーは地形の見た目を OK 済み。本当の重さは Mac の F3 で見る。予算は測った大きいほう（場所でぶれる分は CI と手元の大きいほう）の 1.2 倍。hill は 0.1 下げた値。

| 項目（texA） | 前の上限 | 測った値 | 新しい上限 |
|---|---|---|---|
| AC7 AO のテクスチャ（textureBytes） | 32 MB | 65.4 MB（手元の別の回は 49.9 MB） | 78.4 MB |
| AC12 スタートの三角形 | 45 万 | 944,272 | 1,140,000 |
| AC12 上空の三角形 | 52 万 | 1,120,094 | 1,350,000 |
| AC12 スタートの描画回数 | 83 | 117 | 141 |
| AC12 上空の描画回数 | 98 | 139 | 168 |
| AC13 hill の見やすさ点数（下限） | 2.30 | 2.269 | 2.20 |

理由:
- 山と起伏: 島は平らで三角形が少なかった。新しい地形は丘・山・木で、近く（小ブロックの範囲 r=32）の地表の三角形と、段ごとのメッシュ（描画回数）が増える。hill は大きな明暗が弱く、緑の草原と木が多い見た目になる。
- 足の下の洞くつの小ブロック描画: 世界の高さが 352 で、足の下の洞くつのセクションも小ブロックで描かれる。AO のテクスチャが縦に伸び、三角形も増える。
- 変えていない物: r=32 の角でも 120 万以下・700 回以下（今のまま通っている）、start 1.95・high 1.10 の点数。
