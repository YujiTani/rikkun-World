# VOX-E 性能レポート

- 判定: 基準 5（三角形・描画回数）は合格。基準 4 は「近くの小ブロックのセクション全体の中央値」は合格、「地面のあるセクション 1 つ」は 15ms を超える（下記）。Mac の実測はオーナー確認。
- 計測シナリオ: クラウド（SwiftShader、GPU なし）、seed 既定、r=32、時刻固定、スポーン地点。E2E の `renderStats()` と `world.meshStats()`、ユニットでの `SectionMesher.build` の時間（warm）。

## 数値
| 項目 | 目標 | 結果 |
|---|---|---|
| 三角形 スタート（r=32） | 120 万以下 | 624,716 |
| 三角形 上空（y=80 から見下ろし） | — | 657,338 |
| 描画回数 スタート | 300 以下 | 76 |
| 描画回数 上空 | 700 以下 | 92 |
| geometryBytes スタート | 上限 192MB | 42.7MB（メッシュ 109 個） |
| 歩いたあと（角 4 か所） | 上限で止まる | 4.4〜6.0MB で毎周同じ（b と c 一致） |
| 小ブロック 1 セクションの作り直し（全セクション 192 個、見えないものを除く、中央値） | 15ms 以下 | 2.8ms（p90 45ms、最大 85ms） |
| 地面のあるセクション（y 0〜15）1 つ | 15ms 以下 | 約 35ms（最適化前 52ms。内訳: 地形の高さ S 約 15、格子と色 約 9、greedy 約 16） |
| 箱のセクション 1 つ | — | 0.4〜2ms |
| 1 コマの作り直し合計 | 8ms 以下 | 予算 8ms（かならず 1 つは作るので、地面のセクションを 1 つ作るコマは 35ms 前後） |

## 原因の分析
- 地面のあるセクションは 9×9 の地形の高さ S（`microSurface`）を 162×162 列ぶん計算する。これと greedy（x・z 向きの面は格子の歩幅が大きい）が重い。
- 見えない・空のセクションと上の段はほぼ 0 なので、全体の中央値は小さい。
- 先に箱で出す（約 2ms）ので、小ブロックができるまでの間も穴は出ない。

## 改善案（優先度順）
1. S（高さ）を列ごとに覚えておき、変わった列のまわりだけ計算し直す（地面のセクションの 15ms → 約 8ms 見込み）。
2. x・z 向きの greedy を、メモリの並びに沿った走査にする（約 16ms → 6ms 見込み）。
3. Web Worker（VOX-plan §5）に出す。

## オーナーに Mac で見てほしいところ（F3 で fps 確認）
- F3 のあと F4 で小ブロックの半径 16 → 24 → 32 を切りかえ（URL は `?microR=16`）。fps とごつごつの見え方。
- ブロックをほったとき、穴の面がすぐ出るか（地面のセクションは小ブロックの作り直しで一瞬かかる）。
