## 1. ねらい（りっくんが どう 楽しむか）

- 今の 地下は「もぐっても 何も ない」。**ふかく もぐるほど いい 物が 出る** を 目で 分かる ように する。あさい 所は せきたん・ねんど、なかほどは てつ・白い せっかいせき・光る ほたるいし、ふかい 所は きん と すいしょう。
- ほらあなを 歩くと、かべに 鉱石が よく 見える（今の 約 5 倍）。「あった！」が 何度も ある。自分で 掘っても 今の 約 3 倍 出る。
- **坑道** は はじまりの 近くに かならず ある、木の わくの 入口。たいまつで 明るい さか道を 下りるだけで、こわく なく ふかい 所まで 行ける。とちゅうの 横穴から ほらあなへ 冒険に 出られ、明かりを たどれば もどれる。いちばん 下には きんが きらきら、そして **宝箱**。
- ほらあなには 5 つの「ふしぎな 所」が ある（天井の 高い ひろい ほらあな、白い つららの しょうにゅうどう、地下の 池 ちていこ、ぼんやり 明るい ほたるの ほらあな、めったに 見つからない すいしょうの ほらあな）。見つけると 実績。
- この ゲームだけの 鉱物 **ほたるいし**: 暗い 所で ぼんやり 光る。持って かえって 置くと あかり。
- きん・すいしょうは **てつの つるはし** が ないと 掘れない → 「てつの つるはしを 作って、もっと ふかく」という 目当てが できる。
- 地下に いると 妖怪が 近くに 出る（今の バグを なおす）。たいまつ・ほたるいしで 明るく すると 出ない。たたかうか、明るく して 安心 するかを 自分で 選べる。

### 3.2 見た目の 条件（アートの 3 案で 守る こと。どれに するかは yuzu）
- **鉱物の ブロック 6 つ**（ねんど・せっかいせき・しっくい・ほたるいし・きんの いし・すいしょうの いし）:
  - ブロックは みんな 四角で 影の 形では 分けられないので、**地の 石の 中の つぶの 形と 明るさ** で 見分ける。今の せきたん（黒い かたまり）・てつ（はだ色の かたまり）とも 白黒で 見分けられる。
  - きんの いしは てつと 色だけで なく つぶの 形も ちがう（色が 分かりにくい 人にも 分かる）。
  - ほたるいしは **暗い 所で 光って 見える**（まっくらな ほらあなで 3 マス 先から 見つけられる）。明るさは ずっと 同じか、ゆっくり 強く・弱く（1 回 2 秒 以上・ゆれは ±15% まで。点滅しない。ブロックの 予算 `docs/art/design/03-budget.md` 15.3・15.4 の とおり）。
  - すいしょうの いしは とがった 結晶が 面から 少し 出て 見える と よい（形で 分かる）。たいまつの 光で きらっと（点滅 なし）。
  - しっくいは 白くて なめらかな かべ。今の いし・すな・ゆきと 見分けられる（ゆきと 同じ 白に しない）。
  - 鉱物の つぶは「おさえない」・地形 なので 平らに しない（DESIGN `docs/art/design/01-world.md` の 鉱石の きまりと 同じ。さがす 目じるし）。
- **つらら**: 天井から さがる 白い 細い 形。十字の 板で 作れる 大きさ（`docs/art/design/03-budget.md` §15: 三角形 16）。**先は まるく・白く やわらかく**（とがった さんかくは「あぶない」に 見えるので）。
- **坑道の 入口・わく**: 2 本の 柱と はりの「門」の 形で、**自然の ほらあなの 口と 影で ちがう** と 分かる。入口の 両がわに たいまつ。はりは まっすぐ（鳥居に 見えない）【PO 案】。道の わくは かべ・天井に うめて 道を せまく しない。はじまりの 坑道の 山は スタートから 見える 高さ（§4.5.1）。
- **宝箱**: たんす・かまど・こたつと 影で 見分けられる（ふたが まるい・かどに かざり など）。あいた 宝箱は ふたが あいて 中が からっぽ と 分かる。
- **ほらあなの 種類**: ゲームの 中の スクショ 5 枚を 見て、6 歳が どれか 言える（ひろさ・白い つらら・水と 岸・暗い 中の 光の 点・とがった すいしょう）。
- **こわく しない**: 骨・血・こわい 顔の かざりは 置かない。ふかい 所も 黒で なく こい 青・むらさき よりの 暗さ（DESIGN の 夜・ほらあなの きまり）。

- 木・草花は 坑道の 入口・坑道の 小さな いしの 山（はじまり・ほか）の 上と まわり 2 マスに 置かない。

#### 4.7.3 安全（どの 部屋も）
1. 床の 下 2 マスは 固い（下の ほらあなへ 落ちる 穴が ない）。ちていこの 池の 底も 同じ。
2. **かべの 穴は 歩いて 行き来 できる 物だけ**【2 版で 直した】: 部屋の かべに ひらく ふつうの ほらあなの 穴は、穴の 床（外の ほらあなの 立てる マス）と 部屋の 床の 段差で きめる。1 以下 → そのまま。2〜3 → 1 マス すすんで 1 段の いしの だんを 部屋の 中か 穴の 中 3 マス 以内に 置いて つなぐ（どの だんも 足から 上 4 マスが 空気）。4 以上（上でも 下でも）・外に 立てる マスが ない → いしで ふさぐ（高い 所から 部屋へ 落ちない・部屋から 下へ 落ちない・入れるのに 登って もどれない 穴を 作らない）。
3. 天井から 地面まで 8 マス 以上、海の 下は 10 マス 以上（地上・海に 穴が あかない）。
4. 池の ふかさ 2 まで。岸から 水へ 1 段。
5. **歩いて 出られる 出口が 1 つ 以上**【2 版で 直した】: 部屋の 床の どの マスからも、歩いて（§6.1 の 歩ける きまり）穴を 出て、外の ふつうの ほらあなか 坑道を 4 マス 以上 すすめ、もとの 床へ もどれる。出口の ない 部屋は 全体の 1 割 まで で、穴が ぜんぶ ふさがった「ひみつの 部屋」（掘れば 見つかる。2 の きまりで 落ちて 入る 穴も ない ので 閉じこめられない）。
6. **床は 段差 1 まで**（どの 部屋も。池の 岸〜水は のぞく）。たまご形・まるい 部屋は 下を 平らに ならす。1 段 上がる 所は 下の マスから 上 4 マスが 空気（自動ジャンプで のぼれる）。ひろい ほらあなの 柱は 床から 天井まで（のぼって 落ちる 高い 台を 作らない）。

#### 4.7.4 ふつうの ほらあな
- 今の 細い 道（3D ノイズ）・洞くつの 口の 形は **かえない**（古い 列との つなぎ目を 合わせる ため）。かわるのは 部屋・坑道が かかる 所だけ。

### 4.8 保存（今までの セーブ）【2 版で 直した】
- 保存に ある 列（さわった 列）は **そのまま**（前の 作り方の 地形・鉱石）。保存に ない 列は 新しい 作り方で 作る（層・鉱石・新しい 鉱物・坑道・ほらあなの 種類）。今までも「生成で 作れる 所は 保存しない」きまり。
- **りっくんの 今の 世界が 消えない ことが いちばん 大事。** 版 3 いじょうの 保存は ぜんぶ 読める: 「つづきから」に 出る・開ける、ファイル（.rikkun.gz）も 読める。読まないのは 版 2 まで（今の まま）。今の コードは 版が 今と 同じで ないと 読まない 所が ある（`src/start/lastWorld.ts` の 最初の 列の 版・`src/save/portable.ts` の 版の くらべ）ので、**1A で「3 いじょう 今の 版 いか なら 読む」に する**（版 3 と 4 の 列が まざった 世界も 読める。いちばん 古い 読める 版〔3〕は 1 か所に 書く #304。今の 版より 新しい 保存は 今どおり 読まない）。1A の テストの 準備で 書きかえる 既存テスト: `SAVE_GEN` を 3 に 固定した `src/achievements/live3.test.ts`・`src/animals/live4.test.ts`、「gen が 今の 版と ちがえば 読まない」の `src/start/lastWorld.test.ts`（期待を「2 まで 読まない・3 から 今の 版まで 読む」に 直す。ほかの 期待は かえない）【レビュー係 足し】。
- **地形の 作り方の 版**（`SAVE_GEN`、今 3）を 上げる 時（developer 任せに しない）:

  | issue | 版 | わけ |
  |---|---|---|
  | 1A | 1 つ 上げる（3 → **4**） | 地下の 作り方（層・鉱石）が かわる 境目を 保存に のこす |
  | 1B | **上げない** | 1A の 層に 鉱物を 足すだけ。列を またぐ 物が なく、まざっても 切れない |
  | 1C | 1 つ 上げる（→ **5** ＝ 坑道の 版） | 列を またぐ 坑道が 入る。この 版より 前に 保存した 列が 坑道の「古い 列」 |
  | 1D | 1 つ 上げる（→ **6** ＝ 部屋の 版） | 列を またぐ 部屋が 入る。この 版より 前に 保存した 列が 部屋の「古い 列」 |

  マージの 順が かわったら、数は マージした 順に 1 つずつ。坑道の 版・部屋の 版の 数は 1 か所に 書く（#304）。
- **古い 列の 見分け方: meta に 一覧**（2 版で 決めた。キーに 版は 入れない）:
  - 世界の meta（シード・持ち物 などと 同じ 所。今も 書いた ときの 版 `gen` を 持つ）に、古い 列の 一覧を 2 つ 持つ: **坑道の 一覧**（坑道の 版より 前に 保存した 列）・**部屋の 一覧**（部屋の 版より 前に 保存した 列）。名前は developer（例 `oldCols.kodo`・`oldCols.heya`）。
  - 作り方: 世界を 開いた とき（列を 作りはじめる 前に）、meta の `gen`（その 世界を 最後に 保存した ときの 版）が 坑道の 版より 小さければ、**起動で 読む 列の キーの 一覧**（VOX-D D1。今も 読んで いる）を そのまま 坑道の 一覧に する。部屋も 同じ（部屋の 版と くらべる）。meta が ない・こわれて いる ときは 版 3 と みなす（安全な ほう）。
  - 一覧は **作った あと ふやさない・へらさない**。古い 列を さわって 保存しなおしても 古い まま（中身は 前の 作り方の 地形の まま だから）。新しく 保存した 列は 入れない。新しい 世界は 一覧 なし。
  - meta は 保存の たびに 作りなおして `gen` を 今の 版で 書く ので、**一覧も 毎回 いっしょに 書く**（落とすと 次から 古い 列が 分からなく なり、坑道が 古い 列で 切れる）。一覧と 新しい `gen` は かならず 同じ 書きこみ（1 つの transaction）に 入る。**meta を 作る 所は 1 か所**（`SaveManager.makeMeta`）で、IndexedDB に 書く meta も、ページを 閉じる ときの 保険（localStorage の `PENDING_KEY`。起動では 保険の meta が 保存の meta より 先に 使われる〔`streamRestore.ts`〕）の meta も そこから 出る。**一覧は そこで 入れる**（保険から もどした 世界でも 一覧が のこる）。一覧は かわらないので、かわったか くらべる 文字（`makeMeta` の `key`）には 入れない【レビュー係 足し】。
  - 生成は 起動で 読んだ 一覧を 使う（列を 作る たびに 保存を 読まない）。確かめた【レビュー係】: 起動は `wireBoot` の `openStoredKeys` が meta と キーを 読み終えて から、`wireSave` の `ColumnIO.generate`（`generateChunk`）が 列を 作りはじめる。生成は ページの 中の 1 つの 流れ（Worker なし）なので、`openStoredKeys` の すぐ あとで 一覧を 作って `generateChunk` に わたせば 間に あう（同じ (seed, cx, cz, 一覧) なら 同じ 列）。`createWorldInfo` は 保存を 読む 前に 作る ので、はじまりの 坑道の 場所は 一覧が できて から 決める。
  - ファイルの 書き出し・読みこみ（.rikkun.gz）は meta ごと なので 一覧も 入る。古い 版の ファイルを 読みこんだ ときも、開いた ときに 上と 同じに 一覧を 作る。
  - 列の 記録（`{v, gen, h, data}`）と キーの 形は かえない。列の 記録の `gen` は 書いた ときの 版の まま で よく、古い 列の 見分けには 使わない（`packColumn`・`unpackColumn` は かえなくて よい）。
  - **キーに 版を 入れない わけ**: キーの 形を かえると 今の 保存の 列を ぜんぶ 書きなおす ことに なり（りっくんの 世界を いじる・時間が かかる・とちゅうで 止まると こわれる）、起動で キーを 読む しくみ（VOX-D D1）も かわる。meta の 一覧なら 開いた とき キーの 一覧を 1 回 写すだけで、列の 記録は さわらない。大きさは 列 1 つ 数バイト（保存の 列が 数千 でも 数十 KB）。起動で ふえる 仕事は 一覧の 書きこみ 1 回だけ（VOX-D の 起動の 時間を のばさない）。
- **古い 列に かかるなら 作らない**: 坑道は 坑道の 一覧、部屋は 部屋の 一覧で 見る（とちゅうで 切れた 坑道・半分の 部屋・落ちる ふちを 作らない）。かかる ＝ 坑道（道・つなぎの へや・こべや・へや・山。まわり 2 マス）・部屋（まわり 4 マス）の マスが その 列に ある。
- はじまりの 坑道は 坑道の 一覧に かからない 候補から えらぶ（§4.5.1 の 順に ひろげる）。えらんだ 場所は meta に 書き、次から 同じ。
- 新しい ブロックの 番号は 後ろに 足す（古い 保存の 番号は かわらない）。
- 宝箱の あいた・あいて いない は ブロックで 持つ ので、列の 保存で のこる。
- 持ち物・家・畑・実績 など ほかの 保存は かわらない。

## 6. 受け入れ基準

確かめる 層: 【ユニット】【E2E】【UI 検査】【オーナー確認】【perf】。テストは `window.__rikkun` に 聞いて 確かめる。登録表・表の 件数や §4 の 目安の 数は テストに 決め打ちせず、窓口（`mine.oreTable()` など）から 読む（#311）。**新しい 画面は ないので【UI 検査】の 基準は なし**（実績・図鑑は 行が ふえる だけ。今の UI 検査で 見る）。E2E は 1A・1B・1D で 1 本、1C で 2 本。

### 6.1 テスト用の 窓口案（名前と 形の 約束。置く 所は developer）
`window.__rikkun.mine`（生成の 計算だけで 答える 物は、読みこんで いない 所でも 答える。`biome` と 同じ）:
- `layers()` → `{ id: 'asai' | 'nakahodo' | 'fukai'; minY: number; maxY: number | null }[]`（asai の maxY は null ＝ 地面まで）、`layerAt(y)` → `'asai' | 'nakahodo' | 'fukai' | null`

- `shaftPath(id)` → `{ x, y, z, part: 'entrance' | 'ramp' | 'landing' | 'side' | 'joint' | 'koheya' | 'room' }[]`（道の 足の マス ぜんぶ）

- `chestAt(x, y, z)` → `{ table: string; opened: boolean } | null`、`chestTable(name)` → `{ items: { item, count }[]; lots: { id: string; chance: number }[] }`、`open(x, y, z)`（右クリックと 同じ）

- `oldCols(kind: 'kodo' | 'heya')` → `number`（古い 列の 一覧の 数。新しい 世界は 0）、`isOld(kind, cx, cz)` → `boolean`（§4.8）

**歩ける きまり**（2 版。C4・D4・D5・D8 の 道さがし。tester が テスト側に 1 つの 関数で 作り、みんなで 使う。ゲームの 中に 道さがしは 要らない）:
- **立てる マス**: 足の マスと 頭の マスが 体の 通る マス（空気・たいまつ・つらら・草花 など 固く ない 物。水は のぞく）で、足の 下が 固い ブロック。
- **1 歩**: となり 4 方向の 立てる マスへ。同じ 高さ・1 下 → 行ける。1 上 → 今の 自動ジャンプが できる とき だけ（今の マスの 足から 上 4 マス〔足・頭・その 上 2〕が 体の 通る マス。`PlayerController` の 頭の 高さ 3.05 と 同じ）。2 以上 上・2 以上 下 → 歩けない（落ちる 1 歩は 使わない）。
- **行き来 できる** ＝ A から B へ も B から A へ も 歩いて 行ける（上りの ほうが きびしい ので、かならず 両方 しらべる）。
- **「空気」の 数え方**: この 仕様の「上 4 マスが 空気」「どの マスも 空気」（C3・C6・§4.7.3 など）は、**体の 通る マス**（空気・たいまつ・つらら など 固く ない 物。水は のぞく）で 数える。たいまつは 道の はしの 足の マスに 立つ ため【レビュー係 足し】。

## 7. yuzu に 聞くこと（オーナー確認① で）

1. **鉱石の 量**: 決定は「約 3 倍」。掘って 出る ぜんぶの 数は 約 3 倍、ほらあなを 歩いて **見える 数は 約 5 倍**（1 列 1.9 → 9.2。新しい 鉱物を 入れて 約 12）に した（かべに 出やすく した 分）。多すぎ ないか？（試作で 歩いて みて 決めても よい）
2. **坑道の 形と 明かり**: 「おりかえしの さか道」（行って まがって もどる。迷わない・せまい 所に おさまる）に した。ぐるっと まわる らせんの ほうが いいか？ たいまつは **こわれない たいまつ**（いつも 明るく 安全。持って 帰れない）で いいか？
3. **地下の 妖怪の 数**: 地下は 昼でも 夜の 地上と 同じ（5 秒に 1 回 ためす・5 体まで）。坑道の 道と ほたるの ほらあなでは 出にくい。こわすぎ ないか？（少なく するなら 地下だけ 3 体まで など）
4. **宝箱の 中身**: きん 3・てつの かたまり 3・すいしょう 1・ほたるいし 2・たいまつ 8（＋はらぱんみみず・忍者・侍の くじ）。多すぎ・少なすぎ ないか？
5. **名前と 使い道**: 金の 鉱石を「きんの いし」、水晶の 鉱石を「すいしょうの いし」。せっかいせきは かまどで「しっくい」（白い かべの ブロック）。ほたるいしの 明るさは たいまつより 少し 暗い 10（まわり 4 マスは 妖怪が 出ない）。はじまりの 坑道と、山の 斜面が ない 所の 坑道の 入口は 小さな いしの 山（まわりが 平らなので 山を 作る。山で ない 国でも 坑道に 会える ように。目安は スタートから 768 マス 以内に ほかの 坑道 2 つ 以上）。これで いいか？
6. **光る ブロックの 予算を ほたるいしだけ ゆるめて いいか**【レビュー係 足し】: ブロックの 予算（オーナー 2026-10-17。`docs/art/design/03-budget.md` 15.3・15.4）は「光の 強さ 9 まで」「光る 物は 1 列に 8 こ まで（D 組）」。ほたるいしは 光 10・ほたるの ほらあなで 24 こ 以上 なので こえる。だめなら 光 9（妖怪が 出ない はんいは 3 マス）にして、ほたるの ほらあなの ほたるいしを へらす。
