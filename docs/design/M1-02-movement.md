# M1-02: 移動と視点の切り替え（仕様書）

> タスク票: `docs/tickets/M1-02.md` / 関係する計画: `docs/plan.md` F2、`docs/plan-review.md` R2・R3・R11
> 世界（島の形・ブロックの種類・スタート地点・世界の端の場所・テストに使ってよい場所）は `docs/design/M1-01-world.md` に従う。
> この仕様書が決めるもの: 向きの数え方（§4.3）、水の中の動き（§4.2）、当たり判定（ブロックと世界の端。§5）、時間の止め方（§2.4）、テスト用の窓口の **全体の一覧**（§6.1）、テスト地形の置き方（§6.2）。分担の表は M1-01 §4-12。

## 1. ねらい（りっくんがどう楽しむか）

- 島を「自分の足で」歩き回り、ぴょんと段差を登れるのが気持ちいい。
- V を押すと自分の姿（ブロックの人形）が見えて、「これがぼくだ！」と分かる。
- 操作がむずかしくて止まってしまわないこと（R2）。マウスが外れても、大きなボタンを押せばすぐ戻れる。
- M1 の終わりに、りっくんが 3 分さわって「むずかしすぎないか」を確かめる（付録 A）。

## 2. 遊び方（プレイヤーから見た動き）

### 2.1 操作（入力はすべて Action 経由。`src/input/actions.ts`）

| したいこと | キー・マウス | Action |
|---|---|---|
| まえに あるく | W / ↑ | `moveForward` |
| うしろに さがる | S / ↓ | `moveBack` |
| ひだりに よこあるき | A / ← | `moveLeft` |
| みぎに よこあるき | D / → | `moveRight` |
| ジャンプ | スペース | `jump` |
| むきを かえる | マウスを うごかす | （マウスの動き。Action ではなく「見る量」として受け取る。§6.1 `input.look`） |
| じぶんの め ⇔ うしろから みる | V | `toggleView` |

- 歩く向きは「カメラが向いている水平方向」が基準。三人称でも同じ（W はいつも画面の奥へ）。
- 上や下を向いていても、歩く速さ・向きは水平のまま（上を向いて W を押しても飛ばない）。
- ななめ（W＋D など）でも速さは同じ（ななめだけ速くならない）。
- 反対どうし（W と S を同時など）は打ち消して止まる。
- ジャンプは地面に立っているときだけ。スペースを押しっぱなしにすると、着地するたびに続けてジャンプする（6 歳はタイミングを合わせにくいため）。
- 空中でも WASD で向きを変えられる（空中でも地上と同じ速さで動ける）。
- **オートジャンプ（初期値: オン）**: 地面を歩いていて、進む先に「高さ 1 ブロックの段」があり、その上に体が入るすき間があるときは、自動でジャンプして登る（くわしい条件は §4.6）。2 ブロック以上の壁では自動ジャンプしない。設定でオフにできる（§4.1）。
  - 理由: 6 歳は「歩きながらスペース」を同時に押すのがむずかしい（R2）。りっくん操作テストでオン／オフの様子を見る（付録 A）。

### 2.2 視点

- **一人称**（はじめはこれ）: プレイヤーの目の位置から見る。自分の人形は見えない。
- **三人称**: プレイヤーのうしろ・少し上から、プレイヤーと同じ方向を見る（上下を向いたときの置き方は §4.4）。ブロックの人形が画面の中央少し下に見える。
- V を 1 回押すたびに切り替わる。押しっぱなしでも 1 回だけ切り替わる。切り替えは一瞬（アニメーションなし）。
- 画面中央に小さな「＋」（ねらいの印）を、どちらの視点でも出す（M2 で掘る場所をねらうため）。

### 2.3 はじめるとき・マウスが外れたとき（ポインターロック）

- ゲームを開くと、まず §3.2 の「あそぶ ボタン」の画面が出る。ボタン（または画面のどこか）をクリックすると、マウスが画面に閉じこめられ（ポインターロック）、遊べる。
- Esc を押した・別のウィンドウに行った・ブラウザのタブを替えたなどでロックが外れたら:
  1. 押していたキーはすべて「はなした」扱いにする（キャラが勝手に歩き続けない）。
  2. ゲームの時間を止める（§2.4。M1 では動くものがないが、M3 以降の妖怪（ようかい）にやられないため）。
  3. §3.2 の画面を出す。
- ボタンを押してロックが戻ったら、画面を消して続きから遊べる（位置・向き・視点はそのまま）。
- 例外（M2 から）: **持ち物画面を開くためにゲームが自分でロックを外したとき** は、1・2 は同じだが 3 の案内画面は出さず、持ち物画面を出す（`docs/design/M2-dig-inventory.md` §2.5）。
- ブラウザの都合で、Esc の直後（約 1 秒）はロックをかけ直せないことがある。そのときはボタンを出したままにし、ボタンがゆっくり「ぷるん」と弾むアニメーションで「もう 1 回おしてね」と伝える（エラー文は出さない）。

### 2.4 時間の進み方（ロック・案内画面と、テスト用の `step()`）

ゲームの時間（tick）が進む道は 2 つあり、止まり方がちがう。

| 進み方 | 進むとき | 止まるとき |
|---|---|---|
| **ふだんのゲームループ**（実時間で 1 秒 60 ステップ） | ロック中 **かつ** `pause()` されていない | ロックが外れている（案内画面が出ている）とき。`pause()` されているとき |
| **テスト用の `step(n)`** | **いつでも必ず n ステップ進む**（ロック・案内画面・`pause()` に関係なし） | — |

- **起動直後**: まだ 1 回もロックしていないので「ロックなし」。案内画面（`クリックして あそぼう！`）を出し、ふだんのゲームループは止まっている（tick は増えない）。画面の描画（世界がうっすら見える）は続ける。
- **ロックなしのあいだの入力**: 遊びの Action（`moveForward`・`moveBack`・`moveLeft`・`moveRight`・`jump`・`toggleView`、M2 の `primary`・`secondary`）とマウスの動き（`input.look`）は **無視** する。`step()` で進めても、プレイヤーは歩かない・向きを変えない・視点は切り替わらない。重力・着地・世界の端・落ちたときに戻る（M1-01 4-8）は `step()` で進む。
- **ロックがかかった瞬間と外れた瞬間**: 押されている Action をすべてはなす（外れる前から押していたキーで、戻った瞬間に勝手に歩き出さない）。
- **開発者用の F3（`toggleDebug`）** は例外: ロック・時間の止まり方に関係なく、押せばすぐ（次の描画までに）性能表示が出たり消えたりする。
- `resume()` は `pause()` を取り消すだけ。ロックなしなら、`resume()` してもふだんのゲームループは止まったまま。
- 理由: テストは `step()` で決まった回数だけ確実に進めたい（決定的に動く）。遊ぶ人にとっては、案内画面が出ているあいだは何も進まない。

## 3. 画面・見た目

### 3.1 文字（ひらがな・カタカナ。漢字はふりがな付き）

| 場所 | 文字 |
|---|---|
| あそぶ ボタン（はじめて） | `クリックして あそぼう！` |
| あそぶ ボタン（外れたあと） | `クリックして つづきを あそぼう！` |
| 操作の絵の説明（ボタンの下） | `あるく`・`ジャンプ`・`むきを かえる`・`みかた を かえる` |

- 漢字は使わない。どうしても使うなら `ruby()` でふりがな。

### 3.2 あそぶ ボタンの画面（ポインターロックの案内）

- 画面全体に、うすい黒（不透明度 50% くらい）をかぶせる。うしろの世界はうっすら見える。
- 中央に大きなボタン: 横 **画面の幅の 40% 以上（最低 320px）**、縦 **最低 96px**、角丸、明るい緑（草ブロックの色に近い）、白い太字。マウスの絵（左ボタンが光っている）をボタンの左に付ける。
- ボタンは 1.5 秒周期で少しだけ大きく・小さくなる（目を引くため。速すぎない）。
- ボタンの下に操作の絵を横に 4 つ並べる（字が読めなくても分かるように絵が主役）:
  1. W A S D のキー 4 つ（十字の形に並べる）と矢印キー 4 つ → `あるく`
  2. 横長のスペースキーと、ぴょんと跳ぶ人形の絵 → `ジャンプ`
  3. マウスと左右の矢印 → `むきを かえる`
  4. V のキーと目の絵 → `みかた を かえる`
- クリックできる場所はボタンだけでなく画面全体（ねらいが外れても OK）。
- 文字の大きさ: ボタンの文字は 32px 以上、絵の説明は 20px 以上。

### 3.3 三人称で見えるブロック人形

- 箱（直方体）を 6 つ組み合わせた人形。大きさは当たり判定の箱（幅 0.6・高さ 1.8）にだいたい合わせる。

| 部品 | 大きさ（幅 × 高さ × 奥行き、ブロック単位） | 色 |
|---|---|---|
| あたま | 0.5 × 0.5 × 0.5 | はだ色。前の面に目 2 つ（黒い小さな四角）と、上のほうに茶色の髪（頭の上面と後ろ面は茶色） |
| からだ | 0.5 × 0.7 × 0.25 | 明るい青のシャツ |
| うで（左右） | 0.2 × 0.7 × 0.2 | 上 1/3 は青（そで）、下ははだ色 |
| あし（左右） | 0.25 × 0.6 × 0.25 | こん色のズボン、いちばん下 0.1 は灰色のくつ |

- 色は単色（テクスチャなし）。前と後ろが分かるように、顔の面だけに目を描く。
- 人形の体はカメラの水平の向き（yaw）に向く。頭だけ上下の向きに合わせて少しかたむく（最大 ±45°）。
- 歩いているあいだ、うでとあしを前後に振る（最大 ±30°、1 歩 0.5 秒くらい）。止まったら 0.2 秒くらいでまっすぐに戻る。空中ではあしをそろえる。
- 人形のデザイン（色）は、りっくんの好みで後から変えられるように、色は 1 か所の設定にまとめる。

### 3.4 音

- M1 では音なし（任意）。入れるなら、着地のとき小さな「とん」。うるさい・こわい音は使わない。

## 4. ルール・数値

### 4.1 数値（1 か所の設定にまとめる）

数値は 1 か所の設定にまとめ、プレイテストで変えられるようにする（R3）。単位: 1 ブロック = 1、1 秒 = 60 ステップ（固定 1/60 秒）。「設定の名前」はテスト用の `settings.get/set`（§6.1）で使う名前。

| 項目 | 値 | 設定の名前 | メモ |
|---|---|---|---|
| 歩く速さ | **4.0 ブロック/秒** | `walkSpeed` | マイクラの歩き（約 4.3）より少しゆっくり。走る・しゃがむは M1 ではなし |
| 加速・減速 | 0 → 最高速まで **0.1 秒（6 ステップ）**、キーをはなすと **0.1 秒** で止まる | `accelTime` | すべりにくく、止まりたい場所で止まれる |
| 空中での動き | 地上と同じ速さ・同じ操作 | — | |
| ジャンプの高さ（足の上がる高さ） | **1.25 ブロック** | `jumpHeight` | 1 ブロックの段にゆとりをもって乗れる |
| 重力 | **28 ブロック/秒²** | `gravity` | |
| ジャンプの初速 | √(2 × 28 × 1.25) = √70 ≈ **8.367 ブロック/秒** | （上の 2 つから決まる） | 空中にいる時間は 約 0.6 秒（36 ステップ） |
| 落ちる速さの上限 | **30 ブロック/秒** | `maxFallSpeed` | |
| 落ちたときのダメージ | **なし**（M1） | — | 体力は M3 で決める |
| オートジャンプ | **オン**（設定でオフにできる） | `autoJump`（true / false） | 1 ブロックの段だけ（§4.6） |
| 当たり判定の箱 | 幅 **0.6** × 奥行き **0.6** × 高さ **1.8**（向きによって回らない箱） | — | 位置（`player.get().position`）は「足もとの中央」 |
| 一人称の目の高さ | 足もとから **1.62** | `eyeHeight` | |
| 視野角（たて） | **75°** | `fov` | |
| マウス感度 | **1 ピクセルあたり 0.12°**（左右・上下とも） | `mouseSensitivity` | 大人向けより少し低め。100 ピクセル動かすと 12° |
| 上下の向きの範囲 | **−89° 〜 +89°**（真上・真下でひっくり返らない） | — | マウスを上に動かすと上を向く（上下反転なし） |
| 三人称: カメラの距離 | **4.0 ブロック**（§4.4） | `thirdPersonDistance` | |
| 三人称: カメラの高さ | 目の位置より **0.5 ブロック** 上を中心に回す（§4.4） | `thirdPersonHeight` | |
| 三人称: 壁にめりこまない | 目の位置からカメラまでの間にブロックがあれば、カメラをブロックの手前 **0.2 ブロック** に寄せる | — | 寄せるのは一瞬、離れるときは 0.25 秒かけてなめらかに戻す |
| 三人称: 近すぎるとき | カメラと目の距離が **1.0 ブロック未満** になったら人形を見えなくする | — | 画面が人形でうまらないように |
| ロックの再試行 | Esc 直後で失敗したら、ボタンを出したまま次のクリックを待つ | — | §2.3 |

### 4.2 水の中の動き（M1-01 4-8 はこれに従う）

- `water` は **当たり判定なし・浮力なし**。水の中でも **歩く速さ・加速・ジャンプ・重力・オートジャンプは陸とまったく同じ**（M1 では泳がない・しずまない。海は深さ 1 段なので、海の底のすなの上を歩く）。
- 浅瀬から浜へ: 海の底（すなの上面）と浜（h=7 の列の上面）の差は **1 段**（M1-01 4-3）。ジャンプの高さ 1.25 で登れる。オートジャンプのとき、`water` は「固くない」ので段の上のすき間として数える（§4.6）。
- 水の中の見た目（画面が青くなる など）は M1 ではなし。

### 4.3 向きの決まり（yaw・pitch。M1-01 の向きはすべてこれで書く）

| 項目 | 決まり |
|---|---|
| 座標 | M1-01 4-1 のとおり。y が上、北が -Z、東が +X |
| yaw（左右の向き、度） | **yaw = 0° が北（-Z）**。上から見て **時計回り（右回り）に増える**: 東（+X）= 90°、南（+Z）= 180°、西（-X）= 270° |
| yaw の値の範囲 | **0 以上 360 未満** にそろえる（例: 0° から左へ 12° 回すと 348°） |
| 水平の向きの単位ベクトル forward | **(x, z) = (sin yaw, −cos yaw)**（yaw 0 → (0, −1)、yaw 90 → (1, 0)） |
| 右の向き | (cos yaw, sin yaw)（yaw 0 → (1, 0) = 東） |
| pitch（上下の向き、度） | **0° が水平**、上を向くと **プラス**、下を向くとマイナス。範囲 −89°〜+89° |
| マウス | 右へ動かす（dx > 0）と yaw が増える（右を向く）。上へ動かす（dy < 0）と pitch が増える（上を向く） |
| スタート（M1-01 4-7） | **yaw 0°・pitch 0°**（北を水平に見る） |

### 4.4 三人称カメラの置き方（上下を向いたとき）

- 目の位置 E から **0.5 上** の点 P = E + (0, 0.5, 0) を中心にする。
- 見ている向きの単位ベクトル D（yaw と pitch の両方を使う 3 次元の向き）の **反対へ 4.0** 進んだ所にカメラを置く: カメラ = P − 4.0 × D。カメラはプレイヤーと同じ向き D を見る。
  - pitch = 0° のとき: 目より 0.5 上、水平に 4.0 後ろ（目からの距離 √(4.0² + 0.5²) ≈ 4.03）。
  - 下を向く（pitch −89°）と、カメラはプレイヤーの頭の上（目より 約 4.5 上）から見下ろす。人形は画面に残る。
  - 上を向くと、カメラは後ろの低い所へ回る。地面にぶつかる場合は §4.1 の「壁にめりこまない」で手前に寄せる。
- 壁の判定は「目の位置 E からカメラまでの線分」で行う。

### 4.5 位置の計算方法（1 ステップ = 1/60 秒）

- **上下**: そのステップのはじめの上下の速さを v、重力を g、dt = 1/60 として、新しい速さ v' = max(v − g·dt, −30)、位置の変化 = **(v + v') / 2 × dt**（重力が一定なら y += v·dt − ½·g·dt² と同じ）。ジャンプしたステップは、v を初速 √70 にしてからこの計算をする。
  - この方法での値（計算で確かめた）: 足の最高 **1.2500**（18 ステップ目）、着地 **36 ステップ目**。高さ 20 から落ちると 73 ステップで着地し、下向きの速さは 30 で止まる。
- **水平**: 方法は決めない（どの方法でも AC1・AC2 の範囲に入る。例: 速さを先に変えてから位置を動かすと 60 ステップで 3.83 進む）。

### 4.6 オートジャンプの条件（すべて満たすとき、そのステップでジャンプする）

1. `autoJump` が true、ロック中、地面に立っている（`onGround` が true）。
2. 移動の入力があり、水平の速さが 0 でない。
3. 進む向きに体の箱を **0.3 ブロック** 動かしたと考えると、足の高さ（足の y 〜 足の y + 1）の固いブロックにぶつかる。
4. そのぶつかる先で、足の y + 1 〜 足の y + 2.8 に固いブロックが無い（段の上に体が入る。`water`・`air` は固くない）。
5. 頭の上（今いる場所の 足の y + 1.8 〜 足の y + 3.05）に固いブロックが無い（跳んでも頭をぶつけない）。

## 5. 例外のとき・当たり判定

- **当たり判定の相手**: (1) M1-01 4-2 の「固い」ブロックすべて（`water`・`air` は固くない）。(2) **世界の端の 4 つの面 x=0・x=64・z=0・z=64**（M1-01 4-8 の見えないかべ）。端の面はブロックの面と同じに扱い、体の箱（幅 0.6）は面をこえない。だから足もとの中央は x・z とも **0.3〜63.7** にとどまる。(3) `outside`（世界の外の座標）のブロックは固くないが、(2) の面があるので体は外に出ない。
- **島の形・出現位置・下に落ちたとき**: M1-01 に従う（4-7・4-8）。
- **水の中**: §4.2。
- **壁にぶつかったとき**（ブロック・世界の端とも）: めりこまない。ななめに壁へ歩いたら、壁にそってすべるように進む（ぴたっと止まらない）。
- **天井に頭をぶつけたとき**: 上向きの速さを 0 にして落ち始める。頭はブロックにめりこまない。
- **1 ブロックのすき間**: 幅 1 ブロック・高さ 2 ブロックのすき間は通れる。高さ 1 ブロックのすき間は通れない（しゃがみはない）。
- **2 ブロック以上の壁**: ジャンプしても登れない。
- **足場の端**: 落ちないようにする仕組み（しゃがみ・自動ブレーキ）は M1 ではなし。そのまま落ちる。
- **ロックが外れているあいだ**: キーを押してもキャラは動かない。マウスを動かしても向きは変わらない。ふだんの時間は止まる（§2.4）。
- **ウィンドウがフォーカスを失ったとき**: ロックが外れたときと同じ扱い（§2.3）。
- **カメラがブロックの中から始まる**（例: 三人称に切り替えた瞬間、後ろが壁）: 同じステップ内に手前に寄せ、ブロックの中が映るフレームを出さない。

## 6. 受け入れ基準

前提:
- テストは `window.__rikkun` の窓口（§6.1）を使う。**特にことわりがなければ**、まず `pause()` → `lock.simulate(true)` してから、§6.2 のテスト地形を作り、`player.set()` でプレイヤーを置き、`input.*` で入力を入れて `step()` で進める。

### 6.1 テスト用の窓口（`window.__rikkun`）— 全体の一覧

**名前の決まり**
- 最上位の名前は、**関数** か **入れ物（オブジェクト）** のどちらか一方。同じ名前を関数と入れ物の両方には使わない。入れ物の中身はすべて関数。
- 入れ物は 6 つ: `world`（世界。中身は M1-01 §6.1 が決める）、`player`（プレイヤー）、`camera`（カメラ・視点）、`input`（入力の注入）、`lock`（ポインターロックと案内画面）、`settings`（§4.1 の数値）。`world` 以外はこの仕様書が決める。
- 既存の口（`src/debug/testHook.ts`）はそのまま残す。`step()` のふるまいは §2.4（いつでも必ず進む）。
- 名前は開発係が変えてもよいが、変えたら `src/debug/testHook.ts` の型に書き、M1-01・M1-02 との対応を報告すること。

| 口 | 中身 | 決める仕様書 |
|---|---|---|

## 付録 A: りっくん操作テスト（M1 の終わり、3 分）

記録先: `docs/playtests/M1.md`（R11）。オーナーが横で見て、下の表に ○・×・メモを書く。大人は口を出さず、聞かれたら答える。

### 進め方（合計 3 分）
1. **0:00〜0:30** 画面を見せるだけ。「ボタンを押してみて」とも言わずに待つ（30 秒たっても押さなければ指でさす）。
2. **0:30〜1:30** 自由に歩く。1 回だけ「あの木まで行ってみよう」と目標（10 ブロックくらい先）を言う。

4. **2:00〜2:30** 1 ブロックの段（オートジャンプ オン）、スペースでのジャンプを試す。
5. **2:30〜3:00** わざと Esc を押してもらい、ひとりで戻れるか見る。
