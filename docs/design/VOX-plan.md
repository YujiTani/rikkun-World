# VOX-plan: 9×9×9 本番の設計（#28）

- 対象 issue: #28（決めること 1〜4）、#32（自動セーブの全マス比べ）、#78（広さ・変化・高さ）、#87（バイオーム）
- もとにした資料: `docs/decisions.md`（2026-10-16 の決定）、`docs/perf-reports/VOX-0.md`・`VOX-3.md`、`docs/art/DESIGN.md` §5.4、調査メモ `/mnt/project-files/design-28/save.md`・`world.md`
- 読む人: オーナー（大人のエンジニア）と、開発・テストの係。ゲームのコードはまだ変えていない。

## 1. 目的と決まったこと

目的: 9×9×9 の見た目（B ごつごつ・小ブロック地形）のまま、**終わりのない世界**を歩けるようにする。起動は速く、保存は軽く、ブロックを置いても止まらないこと。

| # | 決まったこと（出典 `docs/decisions.md` 2026-10-16） |
|---|---|
| 1 | 論理ブロックは 1 マスのまま。見た目だけ 9×9×9（hybrid: 近く=小ブロック、中=箱＋模様、遠く=LOD）。r=32 でも Mac で 60fps。 |
| 2 | ほる・おく・当たり判定・光・保存は 1 ブロック単位（#28 の 1〜3 の答え。細工ブロックの別の持ち方は作らない）。 |
| 3 | 地形の高低差は 3 倍。世界の高さ 144。 |
| 4 | 世界は無限。プレイヤーのまわりのチャンクを作る・読みこむ。 |
| 5 | 今の島は引きつがない。新しい世界を作る。 |
| 6 | 保存は「さわったチャンクだけ、丸ごと圧縮して IndexedDB」（save.md の 1 位。差分方式はやめる。#28 の 4 と #32 の答え）。 |
| 7 | 光は 1 ブロック単位のざっくりした形（world.md の案 A ＋ 配列を詰める）。 |
| 8 | バイオームの種類はデザインが案を出し、オーナーが選ぶ（#87）。この文書は「しくみ」だけ決める。 |

## 2. 全体のつくり

**単位はチャンク 1 本 = 16×144×16 の列**（今の `CHUNK_SIZE=16`、高さは全部で 1 本）。チャンクは次の順に段を進む。

```
なし → (IDB にある? 読む : 生成) → 生成ずみ → 光ずみ → メッシュずみ（見える）
                                                   ↓ 遠くなった
                                    (dirty なら保存してから) 捨てる
```

- **段の条件**（となりが要るので、外側ほど浅い段で止まる）
  - 光: 自分＋8 つのとなりが「生成ずみ」。光は 15 マスしか広がらない（16 未満）ので、3×3 を見れば決まる。
  - メッシュ: 自分＋8 つのとなりが「光ずみ」（角の光と小ブロックの縁は となり 2 マスを読む）。
- **持つ範囲**（チャンク距離 = チェビシェフ距離。チャンク単位）

| 輪 | 半径 | 中身 |
|---|---|---|
| 描く | 6（=96 ブロック。今の描画 88 が入る） | メッシュずみ。r 以内は小ブロック、48 まで箱、その先 LOD |
| 光 | 7 | 光ずみ |
| 生成 | 8 | 生成ずみ（17×17 = 289 本） |
| 捨てる | 10 より外 | ブロック・光・メッシュを捨てる（8〜10 は残す。行ったり来たりで作り直さない） |

- **メモリの見積もり**（1 チャンク: ブロック 36,864 B ＋ 詰めた光 36,864 B = 72 KB）
  - 世界＋光: 最大 21×21 = 441 本 × 72 KB ≒ **32 MB**（ふだんは 289 本で 21 MB）。今の 128×48×128（世界＋光 4 本 = 3.9 MB）より大きいが、M4 には小さい。
  - メッシュ: r=32 で小ブロック約 20 本、VOX-0 で 95〜130 MB（CPU と GPU で約 2 倍）。箱・LOD は数 MB。合計の上限を **300 MB** とする。
- **座標**（無限なので負もある）
  - チャンク番号は `cx = x >> 4`、中の位置は `lx = x & 15`（負でも正しい。`Math.floor(x/16)` と `%` は使わない）。|x| < 2^31 で足りる。
  - チャンクの辞書のキーは数 1 つ: `(cx + 32768) * 65536 + (cz + 32768)`。IndexedDB のキーは `[saveId, cx, cz]`。
  - **Float の精度**: メッシュの頂点はチャンクの中の座標（0〜16）で作り、`mesh.position` にチャンクの原点を入れる。GPU は float32 なので、原点から遠いと 1/9 の小ブロックがゆれる（10 万で 1 目盛り 0.008、100 万で 0.06）。→ **±30,000 ブロックに見えない壁**を置く（歩くと片道 2 時間。実用上の無限）。JS の位置（double）はそのままでよい。
  - 空と霧・海の板（`src/game/scenery.ts:8-17`）はプレイヤーについて動かす。

## 3. 生成

- `generateIsland`（島の形・中心・岸が固定）はやめる。`src/world/gen/` に **`generateChunk(seed, cx, cz) → Uint8Array(36,864)`** を新しく作る。**同じシード・同じ番号なら、作る順に関係なく同じ中身**（ほかのチャンクを読まない）。
- **高さ**: 列の高さ `H(x,z)` を seeded のノイズ（今の `valueNoise`、`src/world/gen/random.ts:38`。負の座標でも動く）を重ねて決める。
  - 大きい形（512 ブロック）: 海・陸・山の地方。中くらい（64）: 丘。小さい（16）: でこぼこ。バイオームの数で強さを変える（下）。
  - 海面 `SEA_Y = 48`（案）。地下 48 段、地上 96 段。陸の高さは 50〜135、`H` は 1〜140 に収める。y=0 は こわれない底。
  - 地層は VOX-3 と同じ（草 1・土 1〜2・その下は石）。鉱石は高さとノイズで決める（深いほど よい物）。
- **木・花・岩など（チャンクをまたぐ物）**: 物の位置はチャンクごとのシード（`hash(seed,cx,cz)`）で決める。チャンクを作るとき、**3×3 のチャンクの物を全部考え、自分の中に入るマスだけ書く**。→ 木がとなりにはみ出しても、作る順で形が変わらない。
- **小ブロック地形 S(mx,mz)**: `src/proto/voxel/terrain/microSurface.ts` を本番の `src/world/micro/` に移す。`ColumnSource`（:54）はチャンクの辞書から列を読む形に直す。`MICRO_PARAMS`（:21）はバイオームごとに持ち、境目でまぜる。小ブロックの形は保存しない（位置のハッシュで毎回同じ）。
- **バイオームのしくみ**（中身は #87 でオーナーが選ぶ）
  - 世界を 1 辺 128 ブロック（8 チャンク）の升目に分け、升目ごとに seeded で「点」を少しずらして置く（ボロノイ）。いちばん近い点のバイオームがその場所の種類。
  - 種類はノイズ 2 本（たとえば「しめり」と「でこぼこ」）の値で表から引く。となりどうしが変になりにくい。
  - バイオーム 1 つ = 数の表: 高さの強さ・丘の大きさ・崖の割合・`MICRO_PARAMS`・地面の色・木/花/岩/作物の置く量・妖怪の出やすさ。
  - 境目: 近い 2 点の距離の差で 16 ブロックかけて数をまぜる（高さは段差にならない。色は 3×3 のかたまり単位で切りかえ）。
  - 最初は仮の 2 種（草原・森）で しくみ を作り、中身はあとで入れる。
- **スタート地点**: 原点から外へ、うずまき順にチャンクを見る。`H` だけで調べ（ブロックは作らない）、条件「陸・SEA_Y+2〜+12・まわり 5×5 の高さの差 2 以下・はじまりのバイオーム」を最初に満たす列。シードで決まる。見つけた地点は meta に保存し、たいまつ（今の `start_torch`）を置く。

## 4. 光（案 A）

- **持ち方**: チャンクごとに `Uint8Array(36,864)`。1 マス 1 バイトに 空 4 ビット・明かり 4 ビットを詰める。今の `oldSky`/`oldBlock`（`src/world/light/WorldLight.ts:19-22`）はやめる。値・広がり方（たいまつ 14、1 マス 1 弱まる）は今と同じ。
- **計算**: チャンク C の光は、3×3 のチャンクにある光の元（空・たいまつ）から計算し、**C の中だけ書く**。生成と同じく、順番に関係なく同じ答え（Worker に出せる）。
  - 空の光は、列の一番上の固いブロック（高さ地図）より上を 15 で埋めるだけ。空気を走らない。下の洞くつ・張り出しの中だけ広げる。
- **境目**: となりのチャンクが新しく読みこまれても、C の答えは変わらない（3×3 が そろってから計算するので）。チャンクを捨てるとき、そのとなりの光は捨てない。
- **ブロックを変えたとき**: 変えたマスから 15 以内にかかるチャンク（最大 3×3）を「光の作り直し待ち」に入れる。高さは高さ地図で 切りつめる。光が変わったチャンクだけメッシュ作り直し待ちに入れる。
- **順番待ち**: 1 コマに光 1 チャンク・光だけのメッシュ作り直し 1 チャンクまで。プレイヤーが自分で変えたチャンクを先にする。
- **小ブロックの面**: 面の前のマスの光を 1 つ読み、頂点に `aLight`（2 バイト）として焼く。なめらかにしない・AO なし。箱・LOD は今の角の平均のまま。昼夜は今と同じシェーダー（`WorldRenderer.ts:78-117`）。
- 「あとで」: 光をチャンクの 3D テクスチャにする案 B（たいまつの作り直しが目立ったら）。

## 5. メッシュ（hybrid）

- 近さの段: 小ブロック r=**32（既定）**、箱＋模様 48 まで、LOD 96 まで。F3 の設定で r=16/24 に下げられる。近さは水平の距離（3D はあと）。
- **境目の段差**: r に ±2 のずらし（出るときは r+2、入るときは r−2）でチラつきを防ぐ。境目は霧の濃くなる所なので、まずはこれだけ。目立てば箱の模様にうねりを足す（アート）。
- **空気の段を飛ばす**: チャンクごとに「固いマスの y の最小・最大」を持ち、その間だけ作る。上下左右がうまっている段（岩の中）も飛ばす（見込み 74 → 50 ms）。
- **捨てる**: 描く輪の外に出たメッシュは `dispose` する（今の試作は隠すだけ。VOX-0 の注意）。メッシュの合計（`geometryBytes`）が上限を超えたら、遠い順に捨てる。
- **作り直しの量**: 1 コマに箱・LOD 2 本まで（試作の `maxBuilds=2`）、小ブロック 1 本まで。プレイヤーがブロックを変えたら、そのチャンクを先頭にする。小ブロックは約 50 ms かかるので、**先に箱で出して、できたら小ブロックに差しかえる**（VOX-0 の改善案 2-③）。
- **Web Worker**: 生成・光・小ブロックのメッシュは three を使わず配列を返すだけ（`src/proto/voxel/meshVoxel.ts:21` のコメント）なので、Worker に出せる。まずはメインスレッドで「1 コマ 8 ms まで」の予算で動かし、あとの issue で Worker（2 本）に移す。型付き配列は transfer で渡す（コピーしない）。

## 6. 保存（save.md の 1 位）

- **入れ物**: IndexedDB のデータベース `rikkun-world`（版 1）。ストアは 2 つ。
  - `chunks`: キー `[saveId, cx, cz]`、値 `{ v: 形式の版, gen: 生成の版, data: deflate-raw したブロック番号（36,864 B、y→z→x の順）}`。光・小ブロックの形は保存しない（読んだあとに計算）。
  - `meta`: キー `saveId`。`{ v, gen, seed, spawn, tick, time, player, inventory, bags, furnaces, armor, level, storage, achievements, farm }`（今の JSON の「blocks 以外」）。かまど・たんす・畑は数が少ないので、まずは meta のまま。
  - `saveId` = `main`（セーブは 1 つ）。
- **dirty**: `setBlock` が、描画用の dirty とは別に `saveDirty`（チャンク番号の集合）に入れる。保存は `takeSaveDirty()` で受け取る。**全マス比べ（#32）はなくなる。** meta は各しくみの「変わった」印で書くか決め、`JSON.stringify` は 1 回にする。
- **いつ書くか**: 今と同じ 600 ステップ（10 秒）ごと・ロック解除・画面を閉じる・`visibilitychange(hidden)`。それに **dirty のチャンクを捨てる前**。
  - 手順: ①dirty チャンクを `CompressionStream('deflate-raw')` で縮める → ②**縮め終わってから** readwrite のトランザクションを 1 つ開き、チャンクたちと meta を一緒に書く。（トランザクションの中で IDB 以外を待つと勝手に閉じるため。）全部書けるか、何も書けないか。
  - 書き終わるまで、そのチャンクは「保存中」。捨てない。
- **pagehide の保険**: 非同期は終わらないことがある。前の保存から変えたマスの一覧 `[x,y,z,番号]…` と meta を、localStorage の `rikkun-world-pending` に同期で書く。次の起動でそれを当てて IDB に書き、消す。一覧が 2 万件を超えたら、その場で ふつうの保存をする。
- **persist()**: 起動のとき `navigator.storage.persist()` を 1 回だけたのむ（だめでも遊べる）。
- **ファイルに出す / 読む**: 大人向けの設定に置く。全チャンク＋meta を JSON にして gzip した `.rikkun.gz`（数十 KB〜数 MB）。Safari の 7 日消去にそなえる。読むときは今のセーブを上書きする前に確認する。
- **版番号**: `v`（形式）が古ければ、読みかえの関数を順番に通す。`gen`（生成）が変わったら、保存したチャンクはそのまま、保存していない所だけ新しい生成になる（境目に段差が出ることはある）。
- **今のセーブ**（localStorage `rikkun-world-save-v1-<seed>`）: 島は引きつがない。**持ち物・レベル・実績・よろい だけ引きつぐ**のを既定にする【オーナー確認】。たんす・かまどの中身は、スタートに置く たんす 1 つに入れる【オーナー確認】。古いキーは消さず、meta に `migratedFrom` を書く。`?reset=1`（IDB のセーブを消す）・`?nosave=1` は今のまま。

## 7. 起動

1. meta を読む（なければシードを決めて、スタート地点をさがす）。`chunks` のキーだけ全部読む（`getAllKeys`。さわったチャンクの数だけ。数千まで）。→ 「IDB にあるか」は辞書で分かる。
2. プレイヤーのいるチャンクから近い順に、生成（または IDB から読む）→ 光 → メッシュ。
3. **半径 2（5×5）が小ブロックまで、半径 4 が箱までできたら開始**（`start`）。そこまで「じゅんびちゅう」を出す。残りは 1 コマの予算の中で外へ広げる。プレイヤーは、足もとのチャンクができるまで動かさない（落ちない）。
4. 目標: **開始まで Mac 1 秒以内・クラウド 2.5 秒以内**（今の AC と同じ）。描く輪が全部そろうまで Mac 5 秒以内。

## 8. ゲームのしくみへの影響

1 ブロック単位のままなので、当たり判定・ほる/おく・妖怪の歩き方の中身は変わらない。変わるのは「世界は 0〜128 の箱」という前提だけ。

- **入れ物の口**: `VoxelWorld` の `size.x/z` は無くし、`size.y=144` と `isLoaded(x,z)` を足す（コンパイルで使う所を全部見つけるため）。`getBlock` は**読みこんでいないマスを `'outside'`（固い）**として返す（今の範囲外と同じ扱い）。
- **見えない壁**: ±30,000 で、今の「世界の端」の処理を使う。
- **regions**（山・森などの固定の円）はなくなる。かわりに `biomeAt(x,z)` と「近くの目印（山の頂上など）」を生成が返す。種のでやすさ・実績の「行った所」は、デザインで読みかえる。

## 9. テストと性能の目標

- **ユニット**（`npm run check:fast`）: 負の座標の `>>`/`&`、`generateChunk` が順番に関係なく同じハッシュ（(0,0)→(1,0) と逆順）、光が 3×3 だけで決まる、保存 → 読む で全チャンクのハッシュが同じ（`ChunkStore` のメモリ版 ＋ `fake-indexeddb` 1 本）、壊れたレコードはそのチャンクだけ生成に戻る、旧セーブの引きつぎ。
- **E2E**（関係する spec と smoke だけ）: `__rikkun` に `world.teleport(x,z)`・`world.loadedChunks()`・`world.hash(cx,cz)`・`save.now()`（Promise）・`save.info()`（`dirtyChunks`, `bytes`, `lastMs`）を足す。x=−5000 へ飛んでほる → 保存 → 読みなおし → 同じ。pagehide の保険は `page.close({ runBeforeUnload: true })` で確かめる。
- **性能**（`npm run perf` に「まっすぐ 2 分歩く」シナリオを足す。クラウドで測れる数）:

| 項目 | 目標（クラウド） |
|---|---|
| 三角形（スタート） | r=32 で 120 万以下、r=16 で 70 万以下（DESIGN §11） |
| 描画回数（スタート / 上空） | 150 / 350 以下 |
| 開始までの時間 | 2.5 s 以下（Mac 1 s） |
| チャンク 1 本の生成＋光 | 中央値 5 ms 以下 |
| 小ブロックの作り直し 1 本 | 中央値 50 ms 以下（Worker のあとは「1 コマの止まり 16 ms 以下」） |
| 1 コマの作り直し・生成の合計（メインスレッド） | 8 ms 以下（歩いている間の最大） |
| 保存 1 回（dirty 4 本＋meta） | メインスレッド 5 ms 以下、書き終わり 50 ms 以下 |
| メモリ（世界＋光 / メッシュ） | 32 MB / 300 MB 以下。2 分歩いても上限で止まる |

## 11. 決まっていないこと（オーナーに聞くこと）

1. **引きつぐ物**: 持ち物・レベル・実績・よろい を引きつぎ、たんす・かまどの中身はスタートのたんす 1 つにまとめる、でよいか（全部リセットも選べる）。
