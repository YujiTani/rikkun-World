## 1. ねらい（りっくんがどう楽しむか）

- 自分のキャラ（ピンクのパーカーの女の子）が、ドット絵 RPG のように 歩く方へくるっと向いて、てくてく歩き、走り、ぴょんと跳ぶ。マウスでカメラを回すと、正面・ななめ・横・うしろ の絵が自然に切りかわる。
- 「自分のキャラが かわいい・かっこいい」と思えて、いろんな角度から ながめたくなる。
- 操作はかんたんなまま: WASD で歩く、マウスでカメラ、スペースでジャンプ、シフトで走る。見方の切りかえ（V）はなくなる。

## 2. 遊び方（プレイヤーから見た動き）

### 2.1 第 1 段階でできること

1. ゲームを始めると、キャラの少しうしろ・上・**少し右**からのカメラ（三人称・肩ごし）。キャラは背中をこちらに向けて、画面の「＋」の **左下** に立っている。「＋」は はじめから 3 マスくらい先の地面に乗っている（すぐ ほれる・おける）。
2. **マウスを動かすと カメラだけが キャラのまわりを回る**（左右・上下）。止まっているキャラは向きを変えない。
3. **W A S D（矢印キー）で歩く**。歩く向きは カメラから見た向き（W = 画面のおく、S = 画面の手前、A = 左、D = 右）。キャラは歩く向きへ くるっと向く。S を押すと こちらへ歩いてきて、顔が見える。
4. **シフトを押しながら歩くと 走る**（速く・走る絵）。
5. **スペースでジャンプ**。ふみきり → のぼる → てっぺん → おちる → ちゃくち の絵になる。
6. 画面の真ん中の「＋」で ブロックや妖怪（ようかい）を ねらう。「＋」の先は キャラにかくれない。ほる（左クリック）・おく（右クリック）・たたく などは 今のまま。押すと キャラが ねらった方を向く。
   - 妖怪は「＋」が 少し外れていても（画面で 4 度まで）、とどく所なら ねらえる。ねらえた妖怪には 今と同じ 黄色い ふちどりが出るので、字が読めなくても「いま たたける」と分かる。
7. カメラを上から見下ろすと 見下ろしの絵、高い所に立って 下から見上げると 見上げの絵になる。

第 1 段階のあいだ、下の行動では **キャラの絵は「たつ／あるく／はしる／ジャンプ」の決まりのまま**（今の箱人形の うでの動きは出さない）。ただし、ブロックのひび・音・粒・白い弧など、キャラの外の手ごたえは今のまま出る。

## 3. 画面・見た目

### 3.1 キャラの絵

- 何が分かればよいか: **色と形だけで「自分のキャラ」と分かる**（ピンクのパーカー・白い髪のツインテール・ネコ耳ヘッドホン・白と黒のくつした）。正面・うしろ・横が ひと目で分かる。
- ドットはくっきり（にじませない。となりのコマや段の色がまざらない）。
- 左右の絵を反転して使わない（LANE の字、白と黒のくつしたが左右で ちがうため）。8 方向それぞれ撮影した絵を使う。
- 色は撮影の色見本（`art/CHAR-1-v2/palette.json`）のまま。こまかい色・線のきまりはアートチームに任せる。
- こわくない。痛そうな表現はしない（ダメージは 少し赤くなるだけ）。

### 3.2 文字（案内画面「うごく」タブ）

一人称がなくなるので、案内画面「うごく」の 4 つの説明を次にする（数は 4 のまま）。

| # | 絵 | 文 |
|---|---|---|
| 1 | W A S D と 矢印のキー（今のまま） | W A S D で あるく（今のまま） |
| 2 | スペースのキー（今のまま） | スペース で ジャンプ（今のまま） |
| 3 | マウスの絵（今のまま） | マウス で カメラ を まわす |
| 4 | `shift` のキー と 走る絵 | シフトを おしながら あるくと はしる |

- キーの絵の字は、キーボードに書いてある字（`shift`）。説明の文はカタカナ。

### 3.3 刀・弓の小さな印（オーナー決定 §8-2）

第 1 段階は キャラの絵が刀・弓を持たないので、かまえと 弓の引きが見えなくなる。そのかわりに、「＋」のそばに小さな印を出す（第 2 段階で絵の動きができたら消す）。

- **かまえの印**: 刀のなかま（R でかまえを変えられる物）を持っているあいだだけ、「＋」の右に 横の短い線を 3 本、上から 上段・中段・下段 の順に ならべる。今のかまえの 1 本だけ 明るい色、ほかの 2 本は うすい灰色。R でかまえを変えると、明るい線が動く（音は今の R の音のまま）。
- **弓の印**: 弓を引いているあいだだけ、「＋」の下に 丸を 3 つ 横にならべる。引いた段（1〜3）の数だけ 色がつく。はなすと消える。
- 字は使わない（色と形だけ）。

### 3.4 音

- 新しい音は作らない。歩く・走る・ジャンプはくり返す行動なので、`docs/fun.md` §0・§1 のとおり 演出も音も足さない。
- ほる・おく・たたく などの音は今のまま。

### 3.5 盛り上げのきまり（`docs/fun.md`）との合わせ

| 場面 | 演出・音 |

### 3.6 画面の配置

- **キャラ（肩ごしのカメラ。§4.1）**: キャラは「＋」の **左下**。「＋」の先（ねらう物）は キャラにかくれない。
  - 計算（1280×800、ひらけた平らな地面、はじめの pitch −25。たての画角 75 度 → 焦点 f = 400 ÷ tan37.5° = 521.3 ピクセル）: キャラの たての中心線は ＋ の 約 72〜86 ピクセル 左。頭のてっぺんは ＋ の 約 49 上（画面の上から 351）、足もとは ＋ の 約 144 下（画面の上から 544）。キャラの背の高さは 約 193 ピクセル。からだの はば 0.7・おく 0.7 の箱で見ると、右はしは ＋ の 約 30 ピクセル 左、いちばん下（カメラに近い 下のかど。深さ 4 − 0.35 cos25° + 1.40 sin25° = 4.27、下へ 521.3 × (0.35 sin25° + 1.40 cos25°) ÷ 4.27 = 約 173）は 画面の上から 約 573。地平線は ＋ の 約 243 上（画面の上から 157）で、空も見える。
  - 画面の下の レベル・ハートの板（1280×800 で 上から 約 600〜695）と キャラの足は、はじめの pitch −25 では 重ならない（足もとの中心 約 544・箱の手前の下のかど 約 573。余白 約 27）。pitch 0 では 足もとの中心は ＋ の 521.3 × 1.40 ÷ 4.0 = 約 182 下（上から 約 582）だが、箱の手前の下のかどは 深さ 3.65 で 約 200 下（上から 約 600）で 板の上端に ふれる（くつの先が 少し かかることがある。受け入れは はじめの pitch −25 で見る。AC48）。
  - 画面の大きさごと（はじめの pitch −25 の背の高さ）: 1280×800 で約 193、1440×900 で約 217、1024×700 で約 169 ピクセル。1 ドット（2.12 ÷ 256 = 0.0083）は 約 0.89・1.00・0.78 ピクセル（第 5.1 版より 少し小さい。細い線が消えることがある → Mac で確認 §7）。
  - キャラの右へのずらしが 壁で小さくなると（§4.1）、キャラは ＋ に近づく。ずらし 0 のときは ＋ の真下（第 5.1 版と同じ見え方。ねらいの枠は 板にかくれない §4.3）。
- **かまえの印**: 「＋」の中心から 右へ 28 ピクセルの所に、横 18 × たて 5 ピクセルの線を 3 本、すきま 5 ピクセルで たてにならべる（全体の高さ 5×3 + 5×2 = 25 ピクセル、まん中の線が ＋ と同じ高さ）。
- **弓の印**: 「＋」の中心から 下へ 24 ピクセルの所に、直径 10 ピクセルの丸を 3 つ、すきま 6 ピクセルで横にならべる（全体のはば 10×3 + 6×2 = 42 ピクセル、まん中の丸が ＋ の真下）。

## 4. ルール・数値

### 4.1 カメラ

| 項目 | 値 |
|---|---|
| 見方 | 三人称だけ（はじめから） |
| 体の基準点 P | キャラの目（足もと + 1.62）の 0.5 上 = 足もと + 2.12。**ただし P のブロック（または目から P までの間）が固いときは、そのブロックの下の面より 0.1 下まで下げる**（2 マスの高さのトンネルでは 足もと + 1.90）。届く距離は P から はかる（§4.5） |
| 肩の点 S（カメラの回転の中心・ねらいの線の出どころ） | P の **0.72 下**（ひらけた所で 足もと + 1.40。トンネルでは + 1.18）から、カメラの右向き R（水平。yaw 0 なら +X）へ **ずらし s** だけ動かした点 |
| 右へのずらし s | **s = 0.70 × cos(pitch)**（pitch 0 で 0.70、−25 で 0.634、−45 で 0.495、−89 で 0.012）。真下を見るほど 0 に近づき、足もとのブロックも ねらえる |
| 壁ぎわのずらし（めりこみ） | P の 0.72 下の点から R の向きへ線をのばし、s + 0.2 より手前に 固いブロックがあれば、s を その面の 0.2 手前まで その場で小さくする（0 より小さくしない）。じゃまがなくなったら 0.25 秒（15 ステップ）で もとの s へもどす。固定ステップで決める（ねらいが ステップごとに決まるように） |
| カメラの位置 | S から 見ている向き D の反対へ 4.0（今の `thirdPersonDistance`）。ひらけた所・pitch 0 で キャラの 右 0.70・うしろ 4.0・足もと + 1.40 |
| カメラの向き | D（今の yaw・pitch）。カメラの真ん中の線（「＋」の線）は いつも S を通る |
| はじめの pitch | **−25 度**（スタート・やり直し・セーブの読みこみ）。ひらけた平らな地面で「＋」は 3.0 先の地面（3 マス先のブロック）に乗る |
| 左右の回転（yaw） | マウスの左右だけ。1 ピクセル 0.12 度（今の `mouseSensitivity`）。キーでは回さない（矢印キーは歩くのまま） |
| 上下の回転（pitch） | マウスの上下だけ。範囲 −89〜+89 度（今のまま） |
| キャラが動いたときのカメラ | カメラの向きは変わらない（キャラのうしろへ自動で回りこまない）。位置だけ キャラについていく |
| 壁へのめりこみ | S からカメラへの線で 最初に当たる固いブロックの 0.2 手前まで、その場で寄せる（今の `WALL_MARGIN`）。じゃまがなくなったら 0.25 秒で 4.0 へもどす（今の `WALL_RECOVER_SECONDS`） |
| 左右の入れかえ（左の肩ごし） | なし（第 1 段階はいつも右の肩ごし） |
| キャラをかくす | カメラと キャラの「からだの中心」（足もと + 1.0）の距離が **1.2 未満**のとき、キャラの板をかくす（カメラが キャラの中に入って 画面いっぱいになるのを防ぐ）。今の「目から 1.0 未満」はこれに置きかえる |
| 見下ろしカメラ（`camera.overview`） | 今のまま（キャラは出さない） |

計算の確認（ひらけた平らな地面。からだの中心 C = 足もと + 1.0 から見ると S は 右 s・上 0.40）:
- **はじめの pitch −25 を決めた理由**: 「＋」の線は S（高さ 1.40）から 25 度 下へ進むので、地面には 1.40 ÷ tan25° = 3.00 先で当たる（キャラが ブロックの真ん中なら 3 マス先のブロック）。P からの距離は 3.73 で 届く（≤ 5）。地平線は 画面で ＋ の 25 度 上（1280×800 で ＋ の 243 ピクセル上）なので 遠くも見える。背の低い妖怪（からかさ: 当たりの上 2.10）は、線の高さが 0〜2.10 の所にいれば当たる。線の高さは 前へ f 進むと 1.40 − f × tan25°（f = 0 で 1.40、f = 3.0 で 0）なので、0〜3 マス先の からかさに「＋」が乗る。
- **pitch 0（まっすぐ前）**: 線は 高さ 1.40 の水平。からかさ（2.10）・ちょうちん（2.00）・ぬりかべ（3.3）・ろくろ首（3.0）の どれにも 正面なら当たる（第 5.1 版の P = 2.12 は からかさの 2 cm 上を通っていた）。地面には当たらない。
- **地面を ねらえる pitch**: 地面に当たる点の P からの距離 = √((1.40 ÷ tanθ)² + s² + 2.12²) ≤ 5 → **約 −17.5 度より下で ねらえる**（−18 で 4.31 先・P から 4.85 で届く。−17 で 4.58 先・P から 5.09 で届かない）。第 5.1 版は −26 度より下だった。
- **キャラが「＋」をかくさない**: 線は キャラの中心から 右へ s（pitch 0 で 0.70）はなれて通る。キャラの はば（ツインテールまで）は 中心から 約 0.35 なので、線と キャラのあいだは 0.35 以上（画面では §3.6 の 約 30 ピクセル）。
- 上を見上げる（pitch +）と カメラは S から 地面へ向かう線で 地面にぶつかって寄る。カメラから C までの距離: +45 で 1.60（見える）、+57 で 1.22（見える）、+58 で 1.19（かくす）、+60 で 1.14、+80 で 0.84（かくす）。だから **平らな地面で見上げの絵は出ず、強く見上げると キャラがかくれる**（空が見える）。見上げの絵が出るのは、高い所（柱の上・がけのふち）に立って 下から見たとき（§8-3）。
  - 例 +45: カメラは S から 1.40 ÷ sin45° − 0.2 = 1.78 → C から 右 0.495・下 0.859・うしろ 1.259 → 1.60。
- 下を見下ろす（pitch −）: −45 で 段は水平（カメラの仰ぎ角 48.4 度）、−57.5 前後で 見下ろしに切りかわり、−65 で 66.9 度。
  - 例 −65: カメラは C から 上 0.40 + 4 sin65° = 4.025、うしろ 4 cos65° = 1.690、右 0.7 cos65° = 0.296 → 水平の距離 1.716 → 仰ぎ角 atan(4.025 ÷ 1.716) = 66.9 度。

### 4.2 キャラの向き（facing）

| 項目 | 値 |
|---|---|
| 向きの数え方 | yaw と同じ（0 = 北 −Z、90 = 東 +X、上から見て時計まわり。0 以上 360 未満） |
| 歩いているとき | 歩く入力の向き（カメラの yaw に W・A・S・D を合わせた 8 つの向き）へ回る。壁を押していても 入力の向きへ向く |
| 回る速さ | 1 秒に 720 度（1 ステップ 12 度）。近いほうへ回る。ちょうど 180 度のときは 時計まわり |
| 止まったとき | 最後の向きのまま |
| ねらう行動 | 左クリック・右クリック（ほる・おく・たたく・たべる・みずやり 等）・Q／シフト＋Q（すてる）を押したとき、押しているあいだ、はなしてから 30 ステップ（0.5 秒）のあいだは、**カメラの yaw（ねらいの向き）へ回る**。このあいだは 歩く入力より優先 |
| スタート・やり直し | スタートの向き（spawn の yaw）。カメラも同じ yaw（背中が見える） |
| セーブ | 向きは保存しない。読みこんだら カメラの yaw と同じ向き |
| ゲームの判定 | 向きは見た目だけ。ねらい・投げる向き・突きのふみこみ・たんすの向きなどは 今のまま カメラの yaw・pitch を使う |

### 4.3 板の表示

| 項目 | 値 |
|---|---|
| 板の大きさ | たて・よこ = SPAN × k（SPAN = 2.0、k = 1.8 ÷ モデルの背の高さ H）。H = 1.7 なら 2.12 |
| 板の中心 | 足もと + CENTER × k（CENTER = 0.95）。H = 1.7 なら 1.006 |
| 背の高さ | 立ちの正面の絵で、いちばん上のドット（ネコ耳の先）が 足もと + 1.80 ± 0.05 |
| 足もと | 立ちの正面の絵で、いちばん下のドット（くつの底）が 足もと ± 0.03 |
| 1 ドットの大きさ | 2.12 ÷ 256 = 約 0.0083 |
| 方向 i（0〜7） | カメラの方角（キャラの足もとから **カメラの位置** を見た水平の方角。yaw と同じ数え方。肩ごしなので yaw + 180 より 少し小さい。pitch 0 で yaw + 180 − atan(0.70 ÷ 4.0) = yaw + 170.07）から キャラの向きをひいた角 r（0 以上 360 未満）で、i = floor((r + 22.5) ÷ 45) を 8 で割ったあまり。0 = 正面、2 = キャラの右手がわ、4 = うしろ、6 = 左手がわ（撮影の道具の「カメラがキャラの右へ 45 度ずつ」と同じ） |
| 段（0・1・2） | からだの中心（足もと + 1.0）から見たカメラの仰ぎ角 e が **+60 度以上 → 1（見下ろし）**、**−60 度以下 → 2（見上げ）**、そのあいだ → 0（水平）。切りかえの ゆとり（ヒステリシス）はなし |
| 板の向き | 段 0: たての軸だけ回して カメラの方を向く（板は たてのまま。板の上 = 真上）。段 1・2: 板の面を カメラの位置へ まっすぐ向け、**板の上は カメラの上向き（画面の上）に そろえる**（板は画面の中で かたむかない。撮影も カメラを かたむけずに撮っているので それと同じ）。pitch −89 のように真上から見ても 板の上は 画面の上（＝カメラの yaw の おくの方角）で、ぐるぐる回らない |
| ドット | となりの色をまぜない（くっきり）。透けるドットは 描かない（半とうめいにしない） |
| 明るさ | 板の色 = 絵の色 × キャラの明るさ（今の箱人形・妖怪と同じ「doll」の明るさ。昼・夜・たいまつ・ほら穴で変わり、`dollMin` より暗くならない）。霧も 今のほかの物と同じにかかる。光の向きによる かげはつけない |
| ダメージ | §4.6 |
| ねらいの枠 | ねらっているブロックの白い枠は、キャラの板の うしろにあっても 見える（板にかくれない）。ブロックのうしろでは今のまま |
| かべとの重なり | 板は 1 まいの平らな板なので、かべのそばで ツインテールの先などが かべに少し入ることがある（0.1 くらい）。そのままでよい |

方向の確認（キャラの向き 0 = 北、pitch 0、ひらけた所のとき、カメラの yaw → 方向）: 0 → 4、45 → 5、90 → 6、135 → 7、180 → 0、225 → 1、270 → 2、315 → 3（どれも 境めから 12 度以上 はなれる）。境め: カメラの方角 202.5 = yaw 32.43 なので **yaw 32 → 4、yaw 33 → 5**（第 5.1 版の 22／23 から 変わる）。

### 4.5 ねらい（「＋」）と届く距離

| 項目 | 値 |
|---|---|
| ねらいの線（2 段） | ① **カメラから D の向き**（= 画面の真ん中の「＋」を通る線）。カメラと キャラのあいだ（カメラから S まで）で当たった物は 無視する。線は S を通るので、これは「S から D の向きへ のばした線」と同じ。② 当たった点が 届く距離の中かは **P から** はかる |
| ねらいの点 X | ①の線（S から 64 まで）で 最初に当たる物（ブロック または 妖怪の当たりの箱）の点。何もなければ S + D × 64 |
| ねらうブロック | X がブロックで、P から X まで ≤ 届く距離 のとき そのブロック（置く面も X の面）。届かなければ ねらうブロックなし |
| ねらう妖怪 | (1) ①の線が ブロックより手前で 妖怪に当たり、P からその点まで ≤ 届く距離 → その妖怪。(2) (1) がないとき **やさしい ねらい補助**（下の表）で選んだ妖怪。どちらも 今と同じ 黄色い ふちどりを出し、ブロックの白い枠は出さない（今と同じ）。たたく・刀のわざ・たたくヒントは この妖怪に向かう |
| 使う所 | 今「目から 向きへ線をのばす」所ぜんぶ（ほる・おく・たたく・刀のねらい・弓・みずやり・はたけ・とりいれ・妖怪のふちどり）。線の出どころを S に、向きを D に、届く距離の はかり始めを P にする |
| 届く距離 | P から はかる。数は今のまま（ほる・おく 5.0、素手でたたく 3.5、刀のねらい 4.5、どうぐは今の表のとおり） |
| 矢 | **P から X へ向けて** 出す（出る位置は P から X の向きへ 今の矢の出る距離。山なりの はじめの向きが X の向き）。速さ・山なりは今のまま。矢には ねらい補助を使わない（X は ①の線で当たった点だけ） |
| 「＋」 | あそんでいるあいだ いつも出す（見下ろしカメラのときは出さない。今のまま）。見た目も今のまま |

**やさしい ねらい補助（妖怪だけ。ブロックには補助しない）**

| 項目 | 値 |
|---|---|
| 補助の角 | **4 度**（設定 `aimAssistDeg`。オーナー確認で変えてよい） |
| 選べる妖怪 | 次の 3 つを ぜんぶ満たす妖怪: ア）カメラから見て、D と、その妖怪の当たりの箱（今のねらいで使う 広げた箱）の どこかの点への向き との角の いちばん小さい値（＝画面で「＋」から その妖怪の形までの角）が 4 度以内。イ）P から その当たりの箱まで いちばん近い距離 ≤ 届く距離。ウ）S から その当たりの箱の中心までの まっすぐな線が 固いブロックを通らない（かべの向こうの妖怪は選ばない） |
| どれを選ぶか | アの角が いちばん小さい妖怪。同じ角（差 0.01 度未満）なら P に近い方 |
| ブロックとの順番 | 補助で選べた妖怪がいれば、①の線が ブロックに当たっていても 妖怪をねらう（6 歳が 妖怪のそばの地面を ねらって 空ぶりしないため。4 度は 6 マス先でも 約 0.4 マスなので、妖怪から はなれた所の ブロックは 今までどおり ほれる） |
| 演出・音 | 今の ふちどり（黄色・点滅なし）だけ。補助で ねらえたことを 別の音や印で知らせない（ねらうのは くり返す行動。`docs/fun.md` §1） |
| 失敗したとき | 補助でも ねらえない（4 度より外・届かない）ときは 今と同じ（ふちどりなし。たたくと 今の空ぶり）。BGM・音は変えない |

計算の確認（ひらけた平らな地面、足もとの高さ G、キャラは (x0 + 0.5, G, z0 + 0.5)、yaw 0。右 R = +X。S = (x0 + 0.5 + s, G + 1.40, z0 + 0.5)、P = (x0 + 0.5, G + 2.12, z0 + 0.5)）:

### 4.8 重さ（コマ表）

| 項目 | 値 |
|---|---|
| コマ表（撮影ずみ） | 動きごとに 1 まい（`public/models/char/<動き>.png`）と、まとめの `atlas.json`。よこ = コマ、たて = 段 × 8 方向 = 24 行（撮影の道具の並び） |
| 1 コマ | 256 × 256 ドット |
| 大きさ（今の PNG） | 4 まいとも よこ 2048（8 コマ）× たて 6144 |
| ファイルの大きさ | PNG 合わせて 4.9 MB（目安 8 MB 以下） |
| そのまま RGBA で のせたとき | 1 まい 2048 × 6144 × 4 = 50,331,648 バイト × 4 まい = **201,326,592 バイト（約 201 MB）**。重すぎるので **このままでは のせない** |
| GPU メモリの目安（第 1 段階） | キャラのコマ表 ぜんぶで **64 MB 以下** |
| 描画回数・三角形 | キャラの板は 描画 1 回・三角形 2（今の箱人形は 描画 約 20 回）。白い弧・星は 出ているときだけ 今のまま |

**減らし方**（見た目は 1 ドットも 変えない。どれも PNG と同じ色・同じ形が出ること）:

| 方法 | 決まり | 計算 |
|---|---|---|
| ① 色番号だけで持つ（**必ずやる**） | 1 ドットを 色見本の番号（約 20 色 ＋ とうめい）1 バイトで持ち、色見本で 色にもどして描く | 201 MB × 1/4 = **50,331,648 バイト（約 50 MB）** → これだけで 目安 64 MB に入る |
| ② コマの余白を切りつめる（やってよい） | 動きごとに、ぜんぶのコマ（24 行 × 8 コマ）の 見えるドットを ふくむ いちばん小さい四角 ＋ ふち 2 ドット に そろえて切る。切った大きさと ずらしたドット数は `atlas.json` に書き、板の大きさ・中心も それに合わせる（足もと・背の高さは 変わらない） | 1 コマの はばが 256 → w になると × w/256（例: w = 160 なら ①と合わせて 約 31 MB） |
| ③ 使う動きだけ読む（必ずやる） | 始めに たつ・あるく を読み、出せるようになったら キャラを出す。はしる・ジャンプは そのあとで読む（読めるまでは §5 の代わりの絵）。第 2 段階の動き（ほる 等）は 使うまで読まない | 始めの読みこみは 半分（①なら 約 25 MB） |

- 左右反転は 使わない（§3.1）。
- 第 2 段階で動きを足すと、①でも 1 つの動き（8 コマ）ごとに 約 12.6 MB ふえる。目安をこえそうなら ②と③（使っていない動きを GPU から おろす）を 性能ループで決める。
- 1 まいの絵の上限: よこ 8192 ドット（= 32 コマ）まで。たて 6144。

撮影についての決まり（PO・アートの作業。ゲームのコードではない）:
- たつ・あるく・はしる は つなぎめのないループ。どの動きも その場の動き（前へ進むぶんは 撮影のとき 打ち消す。今の 4 つは そうなっている）。
- ジャンプは こしの高さの上がり下がりを 打ち消して撮る（撮影ずみ）。キャラが上がるのは ゲームの体の動きでつける。
- `atlas.json` に モデルの背の高さ H（ネコ耳の先まで）を入れる（ゲームは k = 1.8 ÷ H を これで計算する）。今の `atlas.json` には ないので書き足す。書き足すまでは H = 1.7（試しの表示と同じ）。
- どのコマも 絵が コマのふちから 2 ドット以上 はなれる（となりのコマが 見えない）。

## 7. Mac で確かめること（オーナー）

1. F3 の fps が 今と同じ（60 前後）。キャラのまわりを カメラで回しながら・走りながら・ジャンプしながら。
2. Chrome の タスクマネージャで、「GPU プロセス」のメモリの増えが 新しいキャラを入れる前と比べて 100 MB 以内（見つもり 約 50 MB）。
3. 始めてから キャラが出るまで 2 秒以内。はじめて 走る・ジャンプしたとき、絵が 一瞬 止まったり カクッとしたり しない。
4. 1024×700 くらいの小さな窓と 1280×800 で、ドットの線が 消えたり ちらついたりしないか（肩ごしの はじめの見え方で 1 ドットは 約 0.78・0.89 ピクセル）。
5. 色番号で描いた絵が、試しの表示（`?char=kittywalk`）と 同じ色に見えるか（夜・たいまつのそばも）。
6. AC36〜AC39・AC49。

## 8. 決まったこと（オーナーの答え 2026-10-16）

1. **走る**: シフトを押しながら歩くと走る。速さ 5.6（歩く 4.0 の 1.4 倍）。→ §4.4
2. **第 1 段階の 刀・弓の見せ方**: 「＋」のそばに 小さな印（かまえの 3 本線・弓の 3 つの丸）を出す。FIX-katana-tune でなくした かまえのアイコンを もう一度出してよい。→ §3.3
3. **見上げの絵**: 平らな地面で強く見上げたら キャラをかくす。見上げの絵は 高い所のキャラを 下から見るときだけ。→ §4.1
4. **ねらい方（PO の決定 2026-10-16。オーナーが「調べてよい案がなければ PO の推奨案で」と任せた）**: ねらいは カメラから「＋」の向きの線（キャラより手前は無視、届く距離は体の P から）、右の肩ごしのカメラ（ずらし 0.70 × cos pitch・高さ 足もと + 1.40・はじめの pitch −25）、妖怪だけ 4 度の やさしい ねらい補助（Minecraft の三人称 mod や TPS の方法）。→ §4.1・§4.5

**PO の提案（オーナー決定 §0 にない追加。オーナー確認②で 遊んで見てもらう）**
- ねらう行動（クリック・Q）では、キャラが カメラの向き（ねらいの向き）を向く（§4.2）。歩く向きとちがう方を ほったり すてたり するとき、キャラが そっぽを向いたままに ならないため。
