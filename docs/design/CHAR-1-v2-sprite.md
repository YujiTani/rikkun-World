## 1. ねらい（りっくんがどう楽しむか）

- 自分のキャラ（ピンクのパーカーの女の子）が、ドット絵 RPG のように 歩く方へくるっと向いて、てくてく歩き、走り、ぴょんと跳ぶ。マウスでカメラを回すと、正面・ななめ・横・うしろ の絵が自然に切りかわる。
- 「自分のキャラが かわいい・かっこいい」と思えて、いろんな角度から ながめたくなる。
- 操作はかんたんなまま: WASD で歩く、マウスでカメラ、スペースでジャンプ、シフトで走る。見方の切りかえ（V）はなくなる。

## 2. 遊び方（プレイヤーから見た動き）

### 2.1 第 1 段階でできること

1. ゲームを始めると、キャラの少しうしろ・上からのカメラ（三人称）。キャラは背中をこちらに向けて立っている。
2. **マウスを動かすと カメラだけが キャラのまわりを回る**（左右・上下）。止まっているキャラは向きを変えない。
3. **W A S D（矢印キー）で歩く**。歩く向きは カメラから見た向き（W = 画面のおく、S = 画面の手前、A = 左、D = 右）。キャラは歩く向きへ くるっと向く。S を押すと こちらへ歩いてきて、顔が見える。
4. **シフトを押しながら歩くと 走る**（速く・走る絵）。
5. **スペースでジャンプ**。ふみきり → のぼる → てっぺん → おちる → ちゃくち の絵になる。
6. 画面の真ん中の「＋」で ブロックを ねらう。ほる（左クリック）・おく（右クリック）・たたく などは 今のまま。押すと キャラが ねらった方を向く。
7. カメラを上から見下ろすと 見下ろしの絵、高い所に立って 下から見上げると 見上げの絵になる。

### 2.2 第 1 段階の範囲

| やること | 中身 |
|---|---|
| 動き 4 つ | たつ・あるく・はしる・ジャンプ（§4.4） |
| 8 方向 × 3 段 | 水平・見下ろし・見上げ（§4.3） |

## 3. 画面・見た目

### 3.1 キャラの絵

- 何が分かればよいか: **色と形だけで「自分のキャラ」と分かる**（ピンクのパーカー・白い髪のツインテール・ネコ耳ヘッドホン・白と黒のくつした）。正面・うしろ・横が ひと目で分かる。
- ドットはくっきり（にじませない。となりのコマや段の色がまざらない）。
- 左右の絵を反転して使わない（LANE の字、白と黒のくつしたが左右で ちがうため）。8 方向それぞれ撮影した絵を使う。
- 色は撮影の色見本（`art/CHAR-1-v2/palette.json`）のまま。こまかい色・線のきまりはアートチームに任せる。
- こわくない。痛そうな表現はしない（ダメージは 少し赤くなるだけ）。

### 3.2 文字（案内画面「うごく」タブ）

一人称がなくなるので、案内画面「うごく」の 4 つの説明を次にする（数は 4 のまま）。

| # | 絵 | 文 |
|---|---|---|
| 1 | W A S D と 矢印のキー（今のまま） | W A S D で あるく（今のまま） |
| 2 | スペースのキー（今のまま） | スペース で ジャンプ（今のまま） |
| 3 | マウスの絵（今のまま） | マウス で カメラ を まわす |
| 4 | `shift` のキー と 走る絵 | シフト を おしながら あるく と はしる |

- キーの絵の字は、キーボードに書いてある字（`shift`）。説明の文はカタカナ。

### 3.3 刀・弓の小さな印（案 A。オーナー確認待ち §8-2）

第 1 段階は キャラの絵が刀・弓を持たないので、かまえと 弓の引きが見えなくなる。そのかわりに、「＋」のそばに小さな印を出す（第 2 段階で絵の動きができたら消す）。

- **かまえの印**: 刀のなかま（R でかまえを変えられる物）を持っているあいだだけ、「＋」の右に 横の短い線を 3 本、上から 上段・中段・下段 の順に ならべる。今のかまえの 1 本だけ 明るい色、ほかの 2 本は うすい灰色。R でかまえを変えると、明るい線が動く（音は今の R の音のまま）。
- **弓の印**: 弓を引いているあいだだけ、「＋」の下に 丸を 3 つ 横にならべる。引いた段（1〜3）の数だけ 色がつく。はなすと消える。
- 字は使わない（色と形だけ）。

### 3.4 音

- 新しい音は作らない。歩く・走る・ジャンプはくり返す行動なので、`docs/fun.md` §0・§1 のとおり 演出も音も足さない。
- ほる・おく・たたく などの音は今のまま。

### 3.5 盛り上げのきまり（`docs/fun.md`）との合わせ

| 場面 | 演出・音 |
|---|---|
| 歩く・走る・ジャンプ・向きを変える（くり返す行動） | 絵の動きだけ。音・粒・ゆれは足さない |
| ちゃくち | かがむ絵を 6 ステップだけ（ぽよんとした手ごたえ）。音は足さない |
| ダメージ（失敗） | 板が 1 回だけ 少し赤くなる（点滅しない）。BGM は止めない |
| 達成（ばんざいの場面など） | 今の演出のまま（このタスクでは変えない） |

### 3.6 画面の配置

- **キャラ**: 水平に見ているとき、キャラは画面の真ん中より下。「＋」はキャラの頭の上に すこし離れて出る（計算: 画面の高さ 800 のとき、＋ は 400、頭のてっぺん は 約 442、足もと は 約 659。キャラの背の高さは 約 226 ピクセル）。
  - 画面の大きさごと（背の高さ・水平に見たとき）: 1280×800 で約 226、1440×900 で約 254、1024×700 で約 198 ピクセル。1 ドットは 約 1.04・1.17・0.91 ピクセル（1024×700 は 1 ドットより小さく、細い線が消えることがある → Mac で確認 §7）。
- **かまえの印（案 A）**: 「＋」の中心から 右へ 28 ピクセルの所に、横 18 × たて 5 ピクセルの線を 3 本、すきま 5 ピクセルで たてにならべる（全体の高さ 5×3 + 5×2 = 25 ピクセル、まん中の線が ＋ と同じ高さ）。
- **弓の印（案 A）**: 「＋」の中心から 下へ 24 ピクセルの所に、直径 10 ピクセルの丸を 3 つ、すきま 6 ピクセルで横にならべる（全体のはば 10×3 + 6×2 = 42 ピクセル、まん中の丸が ＋ の真下）。
- 印は 3 つの画面の大きさ（1280×800・1440×900・1024×700）で 同じピクセルの大きさ。画面の真ん中のまわり 60 ピクセル以内に入るので、ほかの画面（ホットバー・ハート・できごと）と 重ならない。
- **いちばん多いとき**: 案内画面「うごく」タブは 4 つのまま。いちばん長い文は 4 番（17 文字）で、今いちばん長い「1〜9 か ホイール で もちものを えらぶ」（ほる・おく タブ）より短い。かまえの印と弓の印は 同時に出ない（両方を同時に持てない）。

## 4. ルール・数値

### 4.1 カメラ

| 項目 | 値 |
|---|---|
| 見方 | 三人称だけ（はじめから） |
| カメラの回転の中心 P | キャラの目（足もと + 1.62）の 0.5 上 = 足もと + 2.12。**ただし P のブロック（または目から P までの間）が固いときは、そのブロックの下の面より 0.1 下まで下げる**（2 マスの高さのトンネルでは 足もと + 1.90） |
| カメラの位置 | P から 見ている向き D の反対へ 4.0（今の `thirdPersonDistance`） |
| カメラの向き | D（今の yaw・pitch）。カメラの真ん中の線は いつも P を通る |
| 左右の回転（yaw） | マウスの左右だけ。1 ピクセル 0.12 度（今の `mouseSensitivity`）。キーでは回さない（矢印キーは歩くのまま） |
| 上下の回転（pitch） | マウスの上下だけ。範囲 −89〜+89 度（今のまま） |
| キャラが動いたときのカメラ | カメラの向きは変わらない（キャラのうしろへ自動で回りこまない）。位置だけ キャラについていく |
| 壁へのめりこみ | P からカメラへの線で 最初に当たる固いブロックの 0.2 手前まで、その場で寄せる（今の `WALL_MARGIN`）。じゃまがなくなったら 0.25 秒で 4.0 へもどす（今の `WALL_RECOVER_SECONDS`） |
| キャラをかくす | カメラと キャラの「からだの中心」（足もと + 1.0）の距離が **1.2 未満**のとき、キャラの板をかくす（カメラが キャラの中に入って 画面いっぱいになるのを防ぐ）。今の「目から 1.0 未満」はこれに置きかえる |
| 見下ろしカメラ（`camera.overview`） | 今のまま（キャラは出さない） |

計算の確認（ひらけた平らな地面）:
- 上を見上げる（pitch +）と カメラは地面にぶつかって P の下へ寄る。pitch +65 で からだの中心まで 1.22（見える）、+70 で 1.07（かくす）。だから **平らな地面で見上げの絵は出ず、強く見上げると キャラがかくれる**（空が見える）。見上げの絵が出るのは、高い所（柱の上・がけのふち）に立って 下から見たとき（§8-3）。
- 下を見下ろす（pitch −）: −45 で 段は水平（カメラの仰ぎ角 54.4 度）、−52 前後で 見下ろしに切りかわり、−65 で 70.4 度。

### 4.2 キャラの向き（facing）

| 項目 | 値 |
|---|---|
| 向きの数え方 | yaw と同じ（0 = 北 −Z、90 = 東 +X、上から見て時計まわり。0 以上 360 未満） |
| 歩いているとき | 歩く入力の向き（カメラの yaw に W・A・S・D を合わせた 8 つの向き）へ回る。壁を押していても 入力の向きへ向く |
| 回る速さ | 1 秒に 720 度（1 ステップ 12 度）。近いほうへ回る。ちょうど 180 度のときは 時計まわり |
| 止まったとき | 最後の向きのまま |
| ねらう行動 | 左クリック・右クリック（ほる・おく・たたく・たべる・みずやり 等）・Q／シフト＋Q（すてる）を押したとき、押しているあいだ、はなしてから 30 ステップ（0.5 秒）のあいだは、**カメラの yaw（ねらいの向き）へ回る**。このあいだは 歩く入力より優先 |
| スタート・やり直し | スタートの向き（spawn の yaw）。カメラも同じ yaw（背中が見える） |
| セーブ | 向きは保存しない。読みこんだら カメラの yaw と同じ向き |
| ゲームの判定 | 向きは見た目だけ。ねらい・投げる向き・突きのふみこみ・たんすの向きなどは 今のまま カメラの yaw・pitch を使う |

### 4.3 板の表示

| 項目 | 値 |
|---|---|
| 板の大きさ | たて・よこ = SPAN × k（SPAN = 2.0、k = 1.8 ÷ モデルの背の高さ H）。H = 1.7 なら 2.12 |
| 板の中心 | 足もと + CENTER × k（CENTER = 0.95）。H = 1.7 なら 1.006 |
| 背の高さ | 立ちの正面の絵で、いちばん上のドット（ネコ耳の先）が 足もと + 1.80 ± 0.05 |
| 足もと | 立ちの正面の絵で、いちばん下のドット（くつの底）が 足もと ± 0.03 |
| 1 ドットの大きさ | 2.12 ÷ 256 = 約 0.0083 |
| 方向 i（0〜7） | カメラの方角（キャラの足もとから見た水平の方角 = yaw + 180）から キャラの向きをひいた角 r（0 以上 360 未満）で、i = floor((r + 22.5) ÷ 45) を 8 で割ったあまり。0 = 正面、2 = キャラの右手がわ、4 = うしろ、6 = 左手がわ（撮影の道具の「カメラがキャラの右へ 45 度ずつ」と同じ） |
| 段（0・1・2） | からだの中心（足もと + 1.0）から見たカメラの仰ぎ角 e が **+60 度以上 → 1（見下ろし）**、**−60 度以下 → 2（見上げ）**、そのあいだ → 0（水平）。切りかえの ゆとり（ヒステリシス）はなし |
| 板の向き | 段 0: たての軸だけ回して カメラの方を向く（板は たてのまま）。段 1・2: 板をカメラにまっすぐ向ける |
| ドット | となりの色をまぜない（くっきり）。透けるドットは 描かない（半とうめいにしない） |
| 明るさ | 板の色 = 絵の色 × キャラの明るさ（今の箱人形・妖怪と同じ「doll」の明るさ。昼・夜・たいまつ・ほら穴で変わり、`dollMin` より暗くならない）。霧も 今のほかの物と同じにかかる。光の向きによる かげはつけない |
| ダメージ | §4.6 |
| ねらいの枠 | ねらっているブロックの白い枠は、キャラの板の うしろにあっても 見える（板にかくれない）。ブロックのうしろでは今のまま |
| かべとの重なり | 板は 1 まいの平らな板なので、かべのそばで ツインテールの先などが かべに少し入ることがある（0.1 くらい）。そのままでよい |

方向の確認（キャラの向き 0 = 北 のとき、カメラの yaw → 方向）: 0 → 4、45 → 5、90 → 6、135 → 7、180 → 0、225 → 1、270 → 2、315 → 3。境め: yaw 22 → 4、yaw 23 → 5。

### 4.4 動きとコマ

コマは **固定ステップ（1/60 秒）で進める**（画面の fps によらない。止めているあいだは進まない）。v = 水平の速さ（ブロック/秒）。

撮影ずみ（2026-10-16、`public/models/char/{idle,walk,run,jump}.png` と `atlas.json`。どれも 8 コマ）:

| 動き | Meshy の動き | もとの速さ（atlas.json の fps） |
|---|---|---|
| たつ | Idle_4 | 0.57 コマ/秒（もとの動きは 約 14 秒） |
| あるく | Walking_Woman | 8.0 |
| はしる | Run_03 | 9.6 |
| ジャンプ | Regular_Jump（こしの上がるぶんを消して撮影。上下はゲームの体の動きで出す） | 4.27 |

| 動き | コマ数 | えらばれる決まり | コマの進み方 |
|---|---|---|---|
| たつ（idle） | 8 | 地面（またはみず）にいて v < 0.5 | 45 ステップ（0.75 秒）に 1 コマ。1 周 6 秒。ループ |
| あるく（walk） | 8 | v ≥ 0.5 で、走る入力なし | 1 秒に 10 × (v ÷ 4.0) コマ。ただし 4〜16 の間。ループ |
| はしる（run） | 8 | v ≥ 0.5 で、走る入力あり | 1 秒に 12 × (v ÷ 5.6) コマ。ただし 6〜18 の間。ループ |
| ジャンプ（jump） | 8（使うのは 1〜7） | 下の表 | 下の表 |

- たつ をもとの速さ（0.57）より少し速くするのは、8 コマを 14 秒に広げると 動いて見えないため。あるく・はしる は もとの速さ（8.0・9.6）より少し速い（足のすべりは Mac で確認 AC37）。

- 歩く ⇔ 走る の切りかえでは コマの番号を引きつぐ。たつ → 歩く・走る は 0 番から。
- 計算: 歩く 4.0 のとき 10 コマ/秒 = 6 ステップに 1 コマ、1 周 0.8 秒。走る 5.6 のとき 12 コマ/秒 = 5 ステップに 1 コマ、1 周 0.67 秒。みずの中の歩く（2.0）は 5 コマ/秒。

**走る**（オーナー確認待ち §8-1）

| 項目 | 値 |

### 4.5 ねらい（「＋」）と届く距離

| 項目 | 値 |
|---|---|
| ねらいの線 | P から D の向き（= 画面の真ん中の「＋」を通る線）。カメラと P のあいだのブロックは ねらわない |
| 使う所 | 今「目から 向きへ線をのばす」所ぜんぶ（ほる・おく・たたく・刀のねらい・みずやり・はたけ・とりいれ）。線の出どころを 目 → P に かえる |
| 届く距離 | P から はかる。数は今のまま（ほる・おく 5.0、素手でたたく 3、どうぐ・刀は今の表のとおり） |
| 矢 | 今のまま（目から D の向き） |
| 「＋」 | あそんでいるあいだ いつも出す（見下ろしカメラのときは出さない。今のまま） |

計算の確認（ひらけた平らな地面、足もとの高さ G、キャラは (x0 + 0.5, G, z0 + 0.5)、yaw 0）:
- pitch −30: 線は 前へ 2.12 ÷ tan30 = 3.67 で 地面に当たる → z = z0 + 0.5 − 3.67 = z0 − 3.17 → ねらうのは **(x0, G − 1, z0 − 4)**（P からの距離 4.24 ≤ 5）。今の目からの線なら (x0, G − 1, z0 − 3) だった。
- pitch −20: 地面までの距離 2.12 ÷ sin20 = 6.20 > 5 → **ねらうブロックなし**（目からなら 4.74 で届いていた）。

### 4.8 重さ（コマ表）

| 項目 | 値 |
|---|---|
| コマ表（撮影ずみ） | 動きごとに 1 まい（`public/models/char/<動き>.png`）と、まとめの `atlas.json`。よこ = コマ、たて = 段 × 8 方向 = 24 行（撮影の道具の並び） |
| 1 コマ | 256 × 256 ドット |
| 大きさ（今の PNG） | 4 まいとも よこ 2048（8 コマ）× たて 6144 |
| ファイルの大きさ | PNG 合わせて 4.9 MB（目安 8 MB 以下） |
| そのまま RGBA で のせたとき | 1 まい 2048 × 6144 × 4 = 50,331,648 バイト × 4 まい = **201,326,592 バイト（約 201 MB）**。重すぎるので **このままでは のせない** |
| GPU メモリの目安（第 1 段階） | キャラのコマ表 ぜんぶで **64 MB 以下** |
| 描画回数・三角形 | キャラの板は 描画 1 回・三角形 2（今の箱人形は 描画 約 20 回）。白い弧・星は 出ているときだけ 今のまま |

**減らし方**（見た目は 1 ドットも 変えない。どれも PNG と同じ色・同じ形が出ること）:

| 方法 | 決まり | 計算 |
|---|---|---|
| ① 色番号だけで持つ（**必ずやる**） | 1 ドットを 色見本の番号（約 20 色 ＋ とうめい）1 バイトで持ち、色見本で 色にもどして描く | 201 MB × 1/4 = **50,331,648 バイト（約 50 MB）** → これだけで 目安 64 MB に入る |
| ② コマの余白を切りつめる（やってよい） | 動きごとに、ぜんぶのコマ（24 行 × 8 コマ）の 見えるドットを ふくむ いちばん小さい四角 ＋ ふち 2 ドット に そろえて切る。切った大きさと ずらしたドット数は `atlas.json` に書き、板の大きさ・中心も それに合わせる（足もと・背の高さは 変わらない） | 1 コマの はばが 256 → w になると × w/256（例: w = 160 なら ①と合わせて 約 31 MB） |
| ③ 使う動きだけ読む（必ずやる） | 始めに たつ・あるく を読み、出せるようになったら キャラを出す。はしる・ジャンプは そのあとで読む（読めるまでは §5 の代わりの絵）。第 2 段階の動き（ほる 等）は 使うまで読まない | 始めの読みこみは 半分（①なら 約 25 MB） |

- 左右反転は 使わない（§3.1）。
- 第 2 段階で動きを足すと、①でも 1 つの動き（8 コマ）ごとに 約 12.6 MB ふえる。目安をこえそうなら ②と③（使っていない動きを GPU から おろす）を 性能ループで決める。
- 1 まいの絵の上限: よこ 8192 ドット（= 32 コマ）まで。たて 6144。

撮影についての決まり（PO・アートの作業。ゲームのコードではない）:
- たつ・あるく・はしる は つなぎめのないループ。どの動きも その場の動き（前へ進むぶんは 撮影のとき 打ち消す。今の 4 つは そうなっている）。
- ジャンプは こしの高さの上がり下がりを 打ち消して撮る（撮影ずみ）。キャラが上がるのは ゲームの体の動きでつける。
- `atlas.json` に モデルの背の高さ H（ネコ耳の先まで）を入れる（ゲームは k = 1.8 ÷ H を これで計算する）。今の `atlas.json` には ないので書き足す。書き足すまでは H = 1.7（試しの表示と同じ）。
- どのコマも 絵が コマのふちから 2 ドット以上 はなれる（となりのコマが 見えない）。

## 8. オーナーに決めてもらうこと

1. **走る の操作と速さ**: おすすめは「シフトを押しながら歩く」・速さ 5.6（歩く 4.0 の 1.4 倍。妖怪から にげやすくなる）。ほかの案: W を すばやく 2 回、歩きつづけると 自動で走る。
2. **第 1 段階の 刀・弓の見せ方**: キャラの絵は刀・弓を持たないので、
   - 案 A（おすすめ）: 「＋」のそばに 小さな印（かまえの 3 本線、弓の 3 つの丸）。前に「かまえのアイコン」をなくした（FIX-katana-tune）ので、もう一度出してよいか。
   - 案 B: 印は出さない（わざの 白い弧だけ）。第 2 段階まで かまえは 見えない。
   - 案 C: 第 2 段階ができるまで、新しいキャラは 試し（URL の切りかえ）のままにして、ふだんの遊びは今の一人称・箱人形。
3. **見上げの絵が見える場面**: 平らな地面で強く見上げると、カメラがキャラの足もとに入るので キャラを かくす。見上げの絵は 高い所に立って 下から見たときだけ。これでよいか。
