## 1. ねらい（りっくんがどう楽しむか）

- 刀を えらぶと、キャラが **ほんとうに刀をかまえる**。R で かまえを変えると 絵も 中段・上段・下段に変わる。かまえたまま てくてく歩く。
- クリックすると、絵のとおりに ずいっと ふみこんで 突く・とびこんで 大きく切る・4 歩 歩いて 切り上げる。体も 絵といっしょに 前へ出るので「自分が 切りこんだ」と感じられる。
- 弓を えらぶと 弓を持って立つ。おしているあいだ 矢をつがえて ぎゅっと引き、はなすと びゅんと うつ。続けてうつと すばやい連射の絵になる。引きながら歩くこともできる。
- 字が読めなくても、**絵の形（刀の高さ・弓の引き）と 今の小さな印** で、いま どのかまえか・どれだけ引いたかが分かる。

## 2. 遊び方（プレイヤーから見た動き）

### 2.1 刀（ぼくとう・かたな・きらきらの かたな）

1. ホットバーで刀を えらぶ → その場で **中段のかまえの絵**（`katana_thrust` の 1 コマ目）。はじめて刀を持ったときは 絵を読みこむあいだ（ふつう 1 秒くらい）だけ 第 1 段階の絵（§5）。
2. W A S D で歩く・シフトで走る → **かまえ歩き**（今のかまえ）。
3. R → かまえが変わり、立っていれば そのかまえの 1 コマ目、歩いていれば そのかまえの かまえ歩きに すぐ変わる（「＋」の右の かまえの印も 今までどおり動く）。
4. クリック → わざ。キャラは **カメラの向き（ねらいの向き）へ すぐ向き**、絵のとおりに ふみこむ。わざのあいだは 歩く入力・ジャンプは きかない（体は 絵の ふみこみだけで動く）。カメラは いつでも回せる。
5. わざが おわると かまえの 1 コマ目にもどり、また歩ける。おしつづけると 同じわざを くりかえす（今のまま）。

### 2.2 弓（ゆみ）

1. ホットバーで弓を えらぶ → **弓を持って立つ絵**（`bow_shot` の 1 コマ目）。歩く・走る → `bow_hold_walk`。
2. クリックを おしつづける → 引いた長さで `bow_shot` の 0〜7 コマめ（7 コマめ = いちばん引いた絵 = 段 3 になったとき）。
3. はなす → 矢が飛び、`bow_shot` の はなす絵（8〜11 コマめ）。
4. うって すぐ（はなす絵が おわる前に）次を引くと **連射の絵** `bow_rapid`。
5. 引きながら歩く → `bow_walk`（今までどおり 歩く速さ 0.5 倍）。うしろへ下がると 足の絵が うしろ歩きになる（§4.4）。
6. 引きが たりないまま はなす（から引き）→ 矢は飛ばず 今の「ぽよん」、絵は 弓を持って立つ絵に もどる。

### 4.1 どの場面で どの絵の 何コマめを 出すか

**刀を持っている（ぼくとう・かたな・きらきらの かたな）**

| # | 場面（`sprite.scene`） | えらぶ決まり | 絵 | コマ |
|---|---|---|---|---|
| K1 | わざ `tech` | 刀の `phase` が startup・active・recovery | 中段 `katana_thrust`／上段 `katana_kesa`／下段 `katana_kiriage`（出している わざ） | 刀の `frame` から §4.2 の表 |

### 4.4 歩く絵のコマ（かまえ歩き 3 つ・`bow_walk`・`bow_hold_walk`）

- コマの進み方は **CHAR-1 §4.4 の あるく・はしる と同じ**: 走る入力なし = 1 秒に 10 × (v ÷ 4.0) コマ（4〜16）、走る入力あり = 1 秒に 12 × (v ÷ 5.6) コマ（6〜18）。8 コマで回る。
  - 理由（PO の「9 tick ずつ」を変えた）: 刀・弓を持って歩く速さは 4.0（走る 5.6）。絵の 9 tick（1 周 1.2 秒）のままだと 1 周で 4.8 進み、ふつうの歩く（1 周 0.8 秒・3.2）より 足が 1.5 倍 すべる。ふつうの歩くと同じ決まりなら 同じ すべり方になる（オーナーが CHAR-1 AC37 で見る）。
  - 計算: 刀・弓を持って歩く 4.0 → 10 コマ/秒（6 ステップに 1 コマ）、走る 5.6 → 12 コマ/秒（5 ステップに 1 コマ）、引きながら歩く 2.0 → 5 コマ/秒（12 ステップに 1 コマ）、引きながら走る 2.8 → 6 コマ/秒（10 ステップに 1 コマ）、みずの中 2.0 → 5 コマ/秒、みずの中で引きながら 1.0 → 4 コマ/秒（下限）。
- **コマの番号の引きつぎ**: 足を動かす絵（`walk`・`run`・かまえ歩き 3 つ・`bow_walk`・`bow_hold_walk`）のあいだで 切りかわるとき（歩く⇔走る、かまえ変え、引きはじめ・はなす、持ちかえ）は 番号を引きつぐ。足を動かさない場面（立つ・空中・わざ・引く・はなす）から 足を動かす絵へは 0 番から。
- **うしろ歩き**（新しい 5 つの歩く絵だけ）: 水平の速さの向きと キャラの向き（facing）の角が 90 度より大きいとき、コマを 逆の順（7→6→…→0→7）に進める。引きながら うしろへ下がるとき（キャラは ねらいの向きを向く）に 足が 前へ歩いて すべって見えないため。`walk`・`run` は 今のまま（範囲外）。

### 4.5 わざのあいだの 体の動き（ふみこみ）

**わざの向き u**: わざを始めたステップの カメラの yaw（ねらいの向き。水平）。わざが おわるまで 変えない。わざを始めたときの 足もとの位置を O とする。

| 項目 | 決まり |
|---|---|
| キャラの向き | わざを始めたステップの おわりに facing = u（回らずに すぐ）。わざのあいだ ずっと u（歩く入力・ねらう行動・カメラを回しても 変わらない）。おわったら CHAR-1 §4.2 のまま |
| 当たりの向き | 大けさぎり・切り上げの 扇の向きは u。突きの線の向きは 始めたステップの ねらいの向き（上下もふくむ）。線と扇の 出どころ・中心は 今のまま その ステップの 体の位置（ふみこんだ位置） |
| 歩く入力 | わざのあいだ（出だし・当たり・もどり）は きかない（`bladeMoveMul` の 4 つを ぜんぶ 0 に）。始めたステップの おわりに 水平の速さを 0 にする |
| ジャンプ | わざのあいだ できない（今は 大けさぎりの もどりだけ） |
| カメラ（マウス） | いつでも 回せる（O6）。わざの向き・キャラの向きは 変えない |
| 体の前への動き | 下の「ふみこみの線」A。F = f の ステップの おわりに、体（当たり判定の足もと）が O から u の向きへ A(f) の所（ひらけた所で ±0.001）。わざが おわったとき 突き 0・大けさぎり 0.80・切り上げ 1.04 |
| かべ | 体は かべで止まる（今の `PlayerController.lunge` と同じ当たり方）。まだ進めていない ぶんは 押しつづけるが 通りぬけない。突きは もどるとき、止まった所から O まで もどる（O より うしろへは 行かない）。おわったときの体の位置は ひらけた所なら O + u × A(最後) |
| みずの中・空中 | 同じ（ふみこみは 水平だけ。上下は 今の重さ・うき）。がけの先へ ふみこんだら 落ちる |
| 取り消し | その場で止まる（突きでも O へ もどらない） |
| 今の `thrustLunge`（0.25） | なくす（突きの ふみこみは A に置きかえる） |

**ふみこみの線 A(τ)**（τ は 絵の時。tick）: 点 (0, 0)、各コマ k の まん中の時 m_k = c_k + ticks_k ÷ 2 に advance_k、さいご（ぜんぶの長さ）に `step` を とり、そのあいだを 直線で つなぐ。F = f の ステップの おわりの めあては A(f)（設定の長さが 絵とちがうときは §4.2 と同じ 段階ごとの比で τ = P_p + j × L_p ÷ S_p）。

- まん中の時を使う理由: 絵は コマの まん中ごろの形を撮ってある（`labels` の t）。コマの切りかわりの あいだに 足が ずれる量が いちばん小さくなる（1 コマの進みの 半分まで。切り上げの 1 歩 0.13 なら ±0.065）。板は 体といっしょに 動かす（板だけ 別に ずらさない）。
- 計算の確認（1 ステップの動き。カメラも 同じだけ動く）:
  - 突き: 点 (0,0)(1,0)(3,0.08)(4.5,0.255)(5.5,0.26)(7.5,0.29)(14.5,0.32)(22,0.285)(26,0.241)(30,0.16)(34,0.073)(38.5,0.002)(41,0)。いちばん速いのは F4（3→4.5 のあいだ、1 ステップ 0.117）。A(4) = 0.197、A(6) = 0.2675、いちばん前は F14・F15 の 約 0.318、A(41) = 0。
  - 大けさぎり: 点 (0,0)(4,0)(11.5,0.019)(17,0.088)(21,0.22)(25.5,0.351)(29,0.543)(31,0.62)(33,0.639)(36.5,0.691)(53,0.8) から あとは 0.8。いちばん速いのは F26〜29（1 ステップ 0.055）。A(29) = 0.543、A(34) = 0.654、A(53) = 0.8、A(106) = 0.8。
  - 切り上げ: 点 (0,0)(2.5,0)(7.5,0.13)(12.5,0.26)(17.5,0.39)(22.5,0.52)(27.5,0.65)(32,0.78)(36,0.91)(39,1.016)(40.5,1.04)(42,1.059)(47,1.05)(64.5,1.04) から あとは 1.04。いちばん速いのは F37〜39（1 ステップ 0.035）。A(39) = 1.016、A(104) = 1.04。
  - どのわざも 1 ステップの体の動きは **0.12 以下**（走る 5.6 は 1 ステップ 0.093）なので カメラは ガクガクしない。
- 絵のデータ（`ticks`・`advance`・`step`・`phases`）は ゲームの設定にも 写しておく（新しい設定 `bladeAdvance`。§9）。**体の動き・当たりは 絵の読みこみに たよらない**（絵が読めなくても・`?char=block` でも 同じに動く）。設定と `atlas.json` が同じことは ユニットで確かめる。

### 4.6 1 ステップの順番（つなぎ込みの決まり）

1. 刀・弓の 歩く倍率・ジャンプ止め・向きの指定を プレイヤーへ → 2. プレイヤーを動かす → 3. カメラ（S）→ 4. ねらい・刀（`dig.update` の中。わざの ふみこみは ここで 体を動かす）・弓 → 5. **板のコマを決める（4 で決まった 同じステップの 刀の `frame`・弓の `drawTicks` を使う）** → 描く。
- 今は 板のコマ（5）が 4 より前にあるので、うしろへ移す。ふみこみは カメラの あとなので、カメラと板は 体（当たり判定）より 1 ステップぶん おくれて ついていく（いつも同じおくれなので なめらか）。

### 4.7 絵の読みこみと 重さ（CHAR-1 §4.8 の 第 2 段階）

**置き場所（開発の前に PO がやる）**: 10 まいの PNG（`bow_shot`・`bow_walk`・`bow_hold_walk`・`bow_rapid`・`katana_thrust`・`katana_kesa`・`katana_kiriage`・`katana_walk_chudan`・`katana_walk_jodan`・`katana_walk_gedan`）を `public/models/char/` に入れ、`atlas.json` に その 10 の動きを 書き足す（`naginata_sweep` は 入れない）。PNG の形は 今と同じ（1 コマ 256、たて 6144 = 24 行、色見本の 20 色だけ、ふちから 2 ドット以上）。よこ = コマ数 × 256（いちばん大きい 切り上げで 4608。上限 8192）。

**読む時（CHAR-1 §4.8 ③「使うまで読まない」）**:

| 組 | 読みはじめる時 | 読む順（1 まいずつ。2 まいを同時に 色番号にしない） |
|---|---|---|
| はじめ | ゲームを始めたとき（今のまま） | たつ・あるく → はしる・ジャンプ |
| 刀の組（6 まい） | はじめて 刀を 持った（えらんだ）ステップ | `katana_thrust`・`katana_walk_chudan`（持ったときは いつも中段）→ `katana_kesa`・`katana_walk_jodan` → `katana_kiriage`・`katana_walk_gedan` |
| 弓の組（4 まい） | はじめて 弓を 持ったステップ | `bow_shot` → `bow_hold_walk` → `bow_walk` → `bow_rapid` |

- **読んだら おろさない**（持ちかえのたびに 読み直して カクつかないように。PO の考え）。セーブを読みこんで はじめから刀を持っていれば すぐ 刀の組を読む。
- はじめの組が 読み終わる前に 刀・弓を持ったら、はじめの組の あとに読む。
- 読みこみ（PNG を ほどいて 色番号にする所）で ゲームが 止まって見えないこと（Mac で確かめる §7。止まるなら 性能ループで やり方を決める）。

**重さ**（①色番号 1 バイトのまま。1 コマ = 256 × 6144 = 1,572,864 バイト）

| 読んだもの | コマ | GPU のバイト |
|---|---|---|
| はじめの 4 つ | 32 | 50,331,648（約 50.3 MB。今のまま） |
| 刀の組（わざ 11 + 15 + 18、かまえ歩き 8 × 3） | 68 | 106,954,752（約 107.0 MB） |
| 弓の組（12 + 8 + 8 + 11） | 39 | 61,341,696（約 61.3 MB） |
| はじめ ＋ 刀 | 100 | 157,286,400（約 157.3 MB） |
| はじめ ＋ 弓 | 71 | 111,673,344（約 111.7 MB） |
| ぜんぶ | 139 | 218,628,096（約 218.6 MB） |

- **目安**: 刀・弓を持つ前は 第 1 段階の 64 MB 以下（50.3 MB のまま）。持ったあとは 第 1 段階の目安を こえるので、CHAR-1 §4.8 のとおり **性能ループで決める**。それまでの 上限は「ぜんぶ読んで 218,628,096 バイト（220 MiB = 230,686,720 以下）」とし、これより ふえたら 不合格。
- 性能ループで えらぶ 案（この仕様では 決めない）: ② コマの余白を切る（5〜25% へる）、使っていない武器の組を 一定時間で GPU から おろす（CPU に 色番号を 残して すぐ 上げなおす）、見上げの段（段 2）を 武器の絵では 読まずに 段 0 で代える（1/3 へる）。どれも 見た目が 変わるものは オーナー確認。
- PNG: はじめに読む PNG は 今のまま（4 まい・目安 8 MB 以下）。武器の PNG は 持ったときに ダウンロードする（6 まいで 7.4 MB ＋ かまえ歩き・持って歩く 4 まい）。
- 描画回数・三角形: キャラの板は 今のまま 描画 1 回・三角形 2（絵を 変えても ふえない）。
