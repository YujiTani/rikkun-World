## 1. ねらい（りっくんが どう 楽しむか）
ためて はなすと、空から とがった 雷が 一気に 落ちて、当たった 所で 光の 玉が ぷくっと ふくらむ。どこから 見ても いちばん かっこいい 絵が 正面に 見え、「ペラペラの 板」に 見えない。まわりの ブロックや 妖怪（ようかい）が 一しゅん ほんのり 黄色く 照らされて、「でっかいのが 落ちた！」と 分かる。こわすぎず、まぶしすぎない。
持ちものの 雷神剣の 絵も 新しく なり、稲妻（いなずま）の 刃文で 「雷の 剣」と 1 目で 分かる。

## 2. 遊び方（プレイヤーから 見た 動き）
遊び方は 変わらない（WEAPON-7 §3）。雷神剣を 60 ステップ ためて はなす → はなした ステップ = F1。
1. F2〜5: 空に 小さな 光（予兆）。
2. F6〜7: すじが 一気に のびる。まわりが 少し 明るく なる。
3. **F8〜9: 着地**（すじが いちばん 太い ＋ 小さな 玉）。この F8 に 妖怪に 当たる（今と 同じ）。地面に 光の 輪、光の つぶが まいあがる。まわりが いちばん 明るい。
4. F10〜15: **玉（決め）**。いちばん 大きく 明るい 絵で 6 ステップ 止まる。
5. F16〜32: ふくらむ → しぼむ → のこり → きえかけ。明るさは 3 段で もどる。
6. つぶは F88 までに 全部 きえる。

## 8. 決めきれなかった 所（PO・design-reviewer に 見て ほしい）
1. **ささる 所（ソフトパーティクル）を 描画回数の 上限の 中で 作れるか**: 世界を カメラから もう 1 回 描くと 上限（4）を こえる。地面は 高さで うすく できるが、かべとの 切れ目を どう 消すかは developer 次第。上限の 中で できなければ 台帳に 書いて デザインへ もどす（かべは 4 段の 網の 絵 だけで よし、に する 案）。
2. **`thunder_ground.png` は のこす**: 依頼書は「使わない」だが、ため中の 手の 光と ため いっぱいの わが 使って いる（`src/fx/thunderFx.ts`）。この 2 つは 今の まま（DESIGN 18.4）なので のこした。
3. **明るさの 届き方**（5 まで そのまま・8 で 0）と **AC11 の 1.10 倍**・**AC16 の 8・245・20%** は 私が 決めた 数。安全の 数（AC16）は SwiftShader の スクショで 1 回 はかって 合わない ときは デザインへ もどす（実装に 合わせて 変えない）。
4. **空が 見えない ときは 明るく しない** は 私の 判断（屋根の 下に 光が もれない ため）。
5. ため いっぱいの わ（青白）と 新しい 雷（白〜黄）の 色が ちがう。今回は 変えない（このまま の 物）。気に なれば 別の issue。
6. GPU の 絵の 量は 約 1.1 → 4.1 MB。性能の 係に 見て もらう（PR に 前後の 数）。
