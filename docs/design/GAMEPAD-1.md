# GAMEPAD-1: コントローラーで 1 人プレイ（仕様書）

> 関係: オーナー承認「まずはコントローラーで 1 人プレイ」（2026-11-05）／下調べ Phase 0  
> 想定パッド: 子ども向け・小型の **Switch Pro 風 Bluetooth**（Amazon B0CMLD2KCK / RemarksJapan 系。gyro・HD 振動うたい・安価だが、**振動は使わない**。レビューにスティックドリフト・ボタンのもたつきあり）  
> 遊ぶ環境: **Mac + Chrome または Safari**、Bluetooth 接続が主  
> 実装は **まだしない**。オーナー確認①のあと、テスト準備 → 開発へ。  
> 土台: `src/input/actions.ts`（Action / ActionState）。ロック: `src/input/lockController.ts`。

## 1. ねらい（りっくんがどう楽しむか）

- キーボードとマウスがむずかしくても、**コントローラーをさすだけで**歩いて・掘って・戦える。
- キーとマウスも **今までどおり全部使える**。途中で持ちかえても困らない。
- コントローラーのときは「クリックしてあそぼう」を出さず、すぐ遊べる（マウスを画面に閉じ込めなくてよい）。
- 安いパッドや機種差があっても、**ボタン確認画面**と**かんたん割り当て直し**で困りにくい。
- あとから **2 人プレイ**を足すとき、入力の仕組みを作り直さない（最初から人数スロットの形）。

## 2. 遊び方（プレイヤーから見た動き）

### 2.1 できること（Phase 0）

| したいこと | パッド |
|---|---|
| あるく・走る・ジャンプ | できる |
| むきを かえる | できる（右スティック） |
| ほる・こうげき / おく・たべる | できる |
| ホットバーを となりへ | できる（数字キー 1〜9 の一発はパッドではやらなくてよい） |
| もちもの・つくる・できごと | できる（今の画面をパッドで操作） |
| メニューの 移動・決定・もどる | できる |
| すてる・かまえ・ロープおり | できる |
| ボタン確認・割り当て直し | できる（§4） |
| 分割画面・2 人同時 | **やらない** |
| ジャイロ（傾き操作） | **やらない**（うたってあっても対象外） |

### 2.2 さいごにさわった入力

- キー・マウス・パッドの **最後に使った方**を覚える。
- 操作ヒント（安くできるとき）は、その方の絵に切りかえる。必須ではない（§7）。

### 2.3 さした・ぬいた

- さした: 1 本目を 1 人目用にする（Phase 0 は 1 本だけ使う）。
- ぬいた: そのパッドの入力を全部はなす（歩きっぱなし禁止）。キーがあれば続き可。
- ぬいたあと必要なら、大きなひらがな案内を出してよい。

### 2.4 ポインターロックなし（パッド時）

- パッドが 1 人目に割り当てられているあいだは、ロック無しでも時間進行・遊び入力 OK。案内黒画面は出さない。
- キー／マウスだけのときは今までのロック決まりのまま（M1-02・M2）。
- もちもの中の「時間ゆっくり」は今と同じ。

### 2.5 もちもの・つくる・メニュー

- ひらく・とじる・フォーカス移動・決定・もどるは §3 の表どおり。
- 今キーで動く画面（本・建築士・とりごやメニューなど）は、同じ Action でパッドからも動かす（遊びに必要なものから順に）。

### 2.6 感度・デッドゾーン・ドリフト

- **カメラ感度**（右スティック）を設定で変更（例: `gamepadLookSensitivity`）。初期は子ども向けに控えめ。
- **デッドゾーンは広め**（初期案 **0.22〜0.25**。安いパッドの遊び・ドリフト対策）。設定で調整可。
- **ドリフト耐性**: デッドゾーン内は 0 扱い。必要なら「スティック校正（真ん中を覚える）」をボタン確認画面から 1 タップで（簡易で可）。
- **振動（rumble）**: **やらない**（オーナー決定。コードも書かない。パッドがうたっていても無視）。
- **ジャイロ**: 対象外（読みもしない）。

## 3. ボタン割り当て（最終表）

> **決定**＝オーナー回答済み。**提案**＝こちらからの案（まだ OK をもらう）。  
> 刻印は **Switch 風**（子ども用 Pro 風パッド）を主に書く。カッコ内は Xbox standard の位置・刻印。

### 3.1 きまり: 位置で決め、ヒントは刻印で出す

- 内部の番号はブラウザの **standard 位置**（下=0, 右=1, 左=2, 上=3…）。
- Switch は **A/B・X/Y の刻印が Xbox と入れかわる**。ヒントにはそのパッドの刻印を出す。
- 例: 「下の面ボタン」＝ジャンプ。Switch 刻印は **B**、Xbox 刻印は **A**（位置はどちらも下）。

### 3.2 面ボタンの位置対応（見比べ）

| 位置 | Switch 刻印 | Xbox 刻印 | standard |
|---|---|---|---|
| 下 | B | A | buttons[0] |
| 右 | A | B | buttons[1] |
| 左 | Y | X | buttons[2] |
| 上 | X | Y | buttons[3] |

### 3.3 最終レイアウト表

| 状態 | 位置 / 操作 | Switch 刻印めやす | Xbox めやす | やること | Action / 入口 |
|---|---|---|---|---|---|
| **決定** | 左スティック | 左スティック | 同 | あるく | `moveForward` など 4 つ |
| **決定** | 右スティック | 右スティック | 同 | むき | look |
| **決定** | ZR（RT） | ZR | RT | ほる・こうげき | `primary` |
| **決定** | ZL（LT） | ZL | LT | おく・たべる | `secondary` |
| **決定** | L（LB） | L | LB | ホットバー ← | `hotbarPrev` |
| **決定** | R（RB） | R | RB | ホットバー → | `hotbarNext` |
| **決定** | 下の面ボタン | **B** | A | 遊び: ジャンプ ／ メニュー: 決定 | `jump` / `confirm` |
| **決定** | 右の面ボタン | **A** | B | **走る** | `run` |
| **決定** | 左の面ボタン | **Y** | X | もちものを ひらく・とじる | `toggleInventory` |
| **決定** | 上の面ボタン | **X** | Y | みかた切替（一人称↔三人称） | `toggleView` |
| **決定** | 十字（メニュー中） | 十字 | 同 | フォーカス移動 | UI フォーカス |

| **提案** | 十字 ↑（遊び中） | 十字うえ | 同 | （空き・予備。できごとは − へ） | — |
| **提案** | 十字 ↓（遊び中） | 十字した | 同 | 1 こ すてる | `drop` |
| **提案** | ＋（Start） | ＋ | Menu | メニュー／とじる（もちもの開閉でも可） | `toggleInventory` または `closeMenu` |
| **提案** | −（Select） | − | View | できごと（ログ） | `openLog` |
| **提案** | 右の面ボタン（メニュー中） | **A** | B | もどる・キャンセル（遊び中は走る） | `closeMenu` |
| **提案** | 右の面ボタン（ロープぶら下がり中） | **A** | B | おりる | `ropeDown` |
| **提案** | R3（右スティック押し込み） | 右押し込み | 同 | まとめてすてる | `dropStack` |
| **提案** | L3（左スティック押し込み） | 左押し込み | 同 | （予備。割り当て直し用） | — |
| （載せない） | — | — | — | 性能表示など | `toggleDebug` / `cycleMicroR` / `hotbar1`〜`9` はキーのまま |

#### 補足

- **振動**: やらない（決定）。コードも書かない。
- **走る**: 右の面ボタン（Switch **A** / Xbox B）。スティック押し込みにはしない（決定）。
- **みかた切替 (`toggleView`)**: オーナー決定で上の面ボタンへ。※いまのゲームは三人称のみで、この Action は割り当てが外れている（CHAR-1）。実装時は **切替を再び有効にする**か、オーナーに「まだ三人称だけ」と確認する（デザインの続きで決める）。
- **つくる**: 専用ボタンなし。もちもの（Y）を開くと右に「つくる」がある（今の画面）。
- 十字↑を空けた理由: できごとは −、みかたは上の面、すてるは十字↓／R3 に分けて覚えやすくするため。

### 3.4 メニュー中のまとめ（提案込み）

| 操作 | やること |
|---|---|
| 十字・左スティック | フォーカス移動（決定: 十字） |
| 下の面（B/A） | 決定 `confirm` |
| 右の面（A/B） | もどる `closeMenu` |
| 左の面（Y/X）または ＋ | とじる（もちものトグル） |
| − | できごとタブへ（提案） |

## 4. ボタン確認画面と割り当て直し（必須）

安いパッド差・ドリフト・「押したつもりが別ボタン」対策。

### 4.1 コントローラーテスト（ボタン確認）

どこから: 音の設定の近く、または案内／スタートから「コントローラー」へ（ひらがな）。

画面に出すもの:

1. 検出したパッドの **id 文字列**（そのまま短く表示してよい）  
2. `mapping` が `standard` か空か、使っている **変換表の名前**（standard / Switch風 / 予備）  
3. 左・右スティックの **いまの値**（バーや数字。デッドゾーン内は灰色）  
4. **押されているボタン**が光る（位置と、そのパッド向けラベル）  
5. 「まんなかを覚える」（簡易ドリフト校正）ボタン  
6. 「もとにもどす」（初期割り当て）  

### 4.2 かんたん割り当て直し（キーコンフィグ）

- 各「やること」（ほる・ジャンプ…）に対し、**いまのボタン**を見せ、「押しなおして変更」できる。
- 保存先: **localStorage**（ブラウザに残る。セーブワールドとは別）。キー名例: `rikkun.gamepad.binds.v1`。
- 衝突（同じボタンに二つ）したら、あとの方を優先し、前を空けるか警告する（子ども向けにやさしい文言）。
- キーボードの割り当て変更は Phase 0 の範囲外（パッドのみ）。

## 5. マッピング戦略（standard だけに頼らない）

### 5.1 検出の順

1. `Gamepad.mapping === 'standard'` → standard 番号表（§3）を使う。  
2. そうでない（`mapping === ''` など）とき、`id` 文字列を見て **Switch Pro 風テーブル**を選ぶ。めやす（部分一致・大文字小文字無視）:  
   - `Pro Controller` / `Wireless Gamepad` / `057e` / `2009` / `Switch` など  
   - オーナー想定の安価 Pro 風も、多くの場合ここに入る（**推測**: 機種ごとに id が違うので、テスト画面で id を見せて表を足せるようにする）。  
3. どれにも当てはまらない → **安全な予備**: 左スティック移動・右スティック視点だけ有効化し、面ボタンはテスト画面で必ず割り当て直す導線を出す（勝手に掘り始めない）。

### 5.2 Switch Pro 風テーブル（非 standard 用）

ブラウザが standard にそろえないときの **よくある並び**を 1 表として持つ（実装時に実機 id で微調整）。意味は §3.3 の「やること」列に合わせる。  
ユニットテストでは **偽 Gamepad** を二種類用意する: (A) `mapping: 'standard'` (B) `mapping: ''` + Switch 風 id / ボタン並び。

### 5.3 人数スロット

- `ActionState` と look を **プレイヤースロット**ごと（まずは 1）。  
- Phase 0 はスロット 0 だけを今の `Game.input` 相当につなぐ。  
- 2 人段階でスロット 1 を足せる形にする。

### 5.4 変換の流れ

毎フレーム getGamepads →（表またはユーザー割り当て）→ `press`/`release` と look。ゲーム本体は Action / look だけ見る。

## 6. テスト計画

### 6.1 ユニット（偽パッド）

- standard 表と Switch 風表の両方で、§3 の Action になること。  
- デッドゾーン内外・ドリフト校正後。  
- 長押し − → `dropStack`。  
- 抜線で release しきること。  
- localStorage の割り当て読み書き・リセット。

### 6.2 E2E（疑似）

- 偽 Gamepad 注入または `__rikkun` 拡張で、ロック無し歩行・もちもの開閉・とじるを決定的に確認。  
- 既存キー E2E は壊さない。

### 6.3 オーナー Mac

- B0CMLD2KCK 系（または持っている Pro 風）を Bluetooth 接続。  
- Chrome と、できれば Safari でも「ボタン確認」で id / mapping をメモ → 表の欠けを直す。

## 7. 受け入れ基準

1. パッドだけで歩く・視点・ジャンプ・掘る・置く・ホットバー・もちもの／メニュー操作ができる。  
2. キー＋マウスは従来どおり。  
3. パッド使用中はロック無しで進行し、案内黒画面が出ない。  
4. `mapping` が空でも Switch 風表または割り当て直しで遊べる。予備フォールバックで暴発しない。  
5. ボタン確認画面で id・mapping・スティック・押下が見える。割り当てが localStorage に残る。  
6. デッドゾーン広め＋設定可。振動コード無し。ジャイロ無し。  
7. 面ボタンは位置基準。ヒントラベルはパッド種類に合わせる。  
8. 偽パッドで standard / 非 standard の両テストが緑。既存 E2E が落ちない。  
9. 入力は Action 経由＋スロット化の形。

## 8. オーナーに聞きたいこと（確認①の残り）

**決定済み**: 左スティック移動・右スティック視点・ZR/ZL・L/R ホットバー・下＝ジャンプ・右面＝走る・左面＝もちもの・上面＝みかた切替・メニュー中十字＝フォーカス・振動なし・パッドは Switch Pro 風子ども用。

まだ OK がほしい（§3 の **提案**行）:

1. 遊び中の十字 ←→＝かまえ（`stanceNext`）、↓＝すてる、↑＝空き でよいか？  
2. ＋＝メニュー／とじる、−＝できごと、R3＝まとめてすてる、ぶら下がり中の右面＝おりる でよいか？  
3. 上面の「みかた切替」は、今は三人称だけだが **一人称を復活**させてよいか？ それともボタンは予約だけにするか？  
4. 操作ヒントのパッド絵切替は、最初から必須か、後回しでよいか？  
5. ななめ歩きはキーと同じ速さでよいか？

## 9. やらないこと

- 分割画面・2 人同時・ネット・ジャイロ。  
- **振動（rumble）** — 設定もコードも作らない。  
- キーボード割り当て変更 UI。  
- F3/F4 のパッド割り当て。  
- とりごや `coop` とは無関係。

## 10. 進み方

1. 本仕様 → design-reviewer → **オーナー確認①（§8）**。  
2. 合格後: tester がテスト準備 → developer 実装 → 検証。  
3. パッドアイコン絵が必要ならそのときアートへ。
