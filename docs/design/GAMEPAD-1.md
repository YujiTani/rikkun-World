# GAMEPAD-1: コントローラーで 1 人プレイ（仕様書）

> 関係: オーナー承認「まずはコントローラーで 1 人プレイ」（2026-11-05）／下調べ `coop-proposal.md` Phase 0  
> 実装は **まだしない**。この仕様のオーナー確認①のあと、テスト準備 → 開発へ進む。  
> 入力の土台: `src/input/actions.ts`（Action / ActionState）。ポインターロック: `src/input/lockController.ts`。

## 1. ねらい（りっくんがどう楽しむか）

- キーボードとマウスがむずかしくても、**コントローラーをさすだけで**歩いて・掘って・戦える。
- キーとマウスも **今までどおり全部使える**。途中で持ちかえても困らない。
- コントローラーのときは「クリックしてあそぼう」を出さず、すぐ遊べる（マウスを画面に閉じ込めなくてよい）。
- あとから **2 人プレイ**を足すとき、入力の仕組みを作り直さない（最初から「プレイヤー人数ぶん」の形にしておく）。

## 2. 遊び方（プレイヤーから見た動き）

### 2.1 できること（Phase 0 の範囲）

| したいこと | コントローラーでできるか |
|---|---|
| あるく・走る・ジャンプ | できる |
| むきを かえる（カメラ） | できる（右スティック） |
| ほる・こうげき / おく・たべる | できる |
| ホットバーを えらぶ | できる（となりへ送る。数字キー 1〜9 の一発指定はパッドではやらなくてよい） |
| もちもの・つくる画面を ひらく | できる（今の E と同じ画面。右に「つくる」がある） |
| メニューの カーソル移動・決定・もどる | できる |
| できごと（ログ）を ひらく | できる |
| 刀の かまえを かえる | できる |
| すてる（1 こ / まとめて） | できる |
| ロープで おりる | できる |
| 2 人同時あそび・分割画面 | **やらない**（次の段階） |

### 2.2 さいごにさわった入力（キー／マウス ↔ パッド）

- キー・マウス・パッドの **どれを最後に使ったか** を覚える。
- 画面の操作ヒント（安くできるときだけ）は、最後に使った方の絵に切りかえる（キー絵 ↔ パッドのボタン絵）。
- どちらも同じ Action に入るので、遊びの中身は変わらない。

### 2.3 さした・ぬいた（ホットプラグ）

- さした: そのパッドを「1 人目用」として使う（Phase 0 は 1 本だけ使う）。
- ぬいた: そのパッドの入力をはなす（歩きっぱなしにしない）。キーとマウスがあれば続きを遊べる。
- ぬいたあとに案内が必要なら、今の「クリックしてつづきを」に近い大きな案内を出してよい（文言はひらがな）。

### 2.4 ポインターロック（マウス閉じ込め）なし

- **パッドで遊んでいるあいだ**は、ポインターロックが無くても時間を進め、遊びの入力を受け付ける。
- 案内の黒画面（`クリックして あそぼう！`）は出さない。
- キー／マウスだけで遊ぶときは、今までのロックの決まりのまま（M1-02・M2）。
- もちもの画面を開いているあいだの「時間をゆっくり」は、今と同じ。

### 2.5 もちもの・つくる・メニュー（パッド操作）

- ひらく: 下の表の「もちもの」（今の E / `toggleInventory`）。中に「つくる・やく」パネルがある（今の画面のまま）。
- とじる: B（`closeMenu`）またはもう一度「もちもの」。
- フォーカス（どのマス・ボタンを選んでいるか）を、十字キーまたは左スティックで動かす。
- 決定: A（`confirm`）。もどる・とじる: B（`closeMenu` / 本の `bookBack` 相当のときは戻る）。
- 本（あそびかた）・建築士さん・とりごやメニューなど、今キーで動く画面は、同じ Action でパッドからも動かす（受け側が Action を見ているものから順に。全部一気でなく、遊びに必要なものから）。

### 2.6 感度・振動

- **カメラ感度**（右スティック）を設定で変えられる（今の `mouseSensitivity` と並べる。名前例: `gamepadLookSensitivity`）。初期値は子どもがふり向かれすぎないめやす（実装時に Mac で調整）。
- **振動（rumble）**は任意。当たったときなどに弱く振動。オフにできる。対応しないパッド・ブラウザでは何もしない（エラーにしない）。
- オーナー確認の質問（§7）で「振動あり／なし」を決める。なしなら実装しない。

## 3. ボタン割り当て（standard マッピング）

ブラウザの **Standard Gamepad** 番号を使う（Xbox レイアウトの名前で書く。Switch Pro などはブラウザが同じ番号にそろえる）。

### 3.1 スティック（アナログ）

| スティック | やること | ゲームへの入れ方 |
|---|---|---|
| 左スティック | あるく | デッドゾーンを超えた方向を、今の `moveForward` / `moveBack` / `moveLeft` / `moveRight` の押しに変える（ななめ可。速さは今のキー歩きと同じでよい） |
| 右スティック | むきを かえる | Action ではなく **見る量**（今の `MouseLook` / `input.look` と同じ入口）。上下は逆転しない（必要なら設定で後から） |

- **デッドゾーン**: 初期 0.18（スティックの遊び）。設定で変えられるとなおよい（必須ではない）。
- 左スティック押し込み（L3）: `run`（走る）。押し込みが苦手な機種向けに、**LB 押しながら移動でも走れる**（同じ `run`）。

### 3.2 ボタン ↔ いまある Action

| パッド（standard） | やさしい名前 | Action / 入口 | いまのキー・マウス |
|---|---|---|---|
| 左スティック | あるく | `moveForward` など 4 つ | WASD / 矢印 |
| 右スティック | むき | look（Analog） | マウス移動 |
| A（buttons[0]） | 決定・ジャンプ | 遊び中: `jump` ／ メニュー中: `confirm` | Space / Enter |
| B（buttons[1]） | もどる・とじる | `closeMenu`（本が出ていれば戻りも兼ねる） | Esc |
| X（buttons[2]） | かまえ | `stanceNext` | R |
| Y（buttons[3]） | もちもの・つくる | `toggleInventory` | E |
| LB（buttons[4]） | 走る補助・ロープ | 押しながら: `run` ／ ぶら下がり中: `ropeDown` | Shift / C |
| RB（buttons[5]） | ホットバー → | `hotbarNext` | ホイール下 |
| LT（buttons[6]） | おく・たべる | `secondary` | 右クリック |
| RT（buttons[7]） | ほる・こうげき | `primary` | 左クリック |
| Back / View（buttons[8]） | すてる | `drop`（長押し 0.4 秒で `dropStack`） | Q / Shift+Q |
| Start / Menu（buttons[9]） | できごと | `openLog` | L |
| L3（buttons[10]） | 走る | `run` | Shift |
| R3（buttons[11]） | （予備。Phase 0 では使わない） | — | — |
| 十字 ↑↓←→（12–15） | メニュー移動／ホットバー | メニュー中: フォーカス移動 ／ 遊び中: ←`hotbarPrev` →`hotbarNext`（↑↓は予備） | ホイール・矢印（本） |

**やらない（Phase 0）**

- `hotbar1`〜`hotbar9` のパッド一発指定（数字キーは残す）。
- `toggleView`（一人称切替はもう無い。名前だけ残っている）。
- `toggleDebug` / `cycleMicroR`（F3/F4。開発用。キーのまま）。

### 3.3 画面ヒント（安くできるとき）

- 最後にパッドを使っていれば、画面の「E」などのキー絵を、対応するパッド絵（Y など）に差し替える。
- コストが高い・絵が足りないときは **後回し可**（受け入れの必須にしない）。必須なのは操作そのものがパッドでできること。

## 4. 仕組み（実装の約束。コードはまだ書かない）

### 4.1 変換の流れ

1. 毎フレーム `navigator.getGamepads()` を読む（または `gamepadconnected` で開始）。
2. standard マッピングでボタン／軸 → `ActionState.press/release` と look の押し込み。
3. ゲーム本体は今どおり **Action と look だけ**を見る（Dig・Player・Screen はパッドを直接読まない）。

### 4.2 人数ぶんの入れ物（あとで 2 人に使う）

- `ActionState` と look の入口を、**プレイヤースロット（まずは 1）**ごとに持つ形にする。
- Phase 0 の配線はスロット 0 だけを今の `Game.input` につなぐ（動きは 1 人のまま）。
- 2 人段階でスロット 1 を足せるように、最初から「配列または PlayerId 付き」で設計する（リファクタを一度で済ませる）。

### 4.3 ロック制御の追加条件（仕様）

今: `realtimeAllowed` ≒ ロック中 or もちもの中 or かけ直し中。  
追加: **「パッドが 1 人目に割り当てられていて、案内を出さないモード」**のときは、ロック無しでも `realtimeAllowed` と遊び入力を許可する。  
（名前やフラグの細部は実装に任せる。テストで「パッド接続シミュレート → ロック無しで歩ける」を必ず書く。）

## 5. テスト計画

### 5.1 ユニット（偽のゲームパッド）

- デッドゾーン内外で移動 Action が付く／付かない。
- 右スティック → look の量（感度倍率込み）。
- 各ボタン → 表どおりの Action（遊び中／メニュー中の A の切り替わり）。
- 抜いたとき `releaseAll` 相当ではなし終わる。
- 長押し Back → `dropStack`。

### 5.2 E2E（疑似パッド）

- 実機パッドは CI に無いので、`window.__rikkun` の入力窓口を拡張するか、偽 Gamepad を注入して「ロック無しで 1 歩歩く」「Y でもちものが開く」「B で閉じる」を決定的に確かめる。
- キーだけの既存 E2E は壊さない。

### 5.3 オーナー確認（Mac）

- 持っているパッド 1 本で、歩く・掘る・置く・もちもの・つくるが lit くんにできるか。
- 感度が速すぎ／遅すぎないか。

## 6. 受け入れ基準（短く）

1. パッドだけで、歩く・ジャンプ・視点・掘る・置く・ホットバー送り・もちもの開閉・メニュー決定／戻るができる。  
2. キー＋マウスは今までどおり全部使える。最後に使った方のヒント切替は「できれば」。  
3. パッド使用中はポインターロック無しで時間が進み、案内黒画面が出ない。  
4. 抜き差しで歩きっぱなしにならない。  
5. 感度を設定で変えられる。振動は §7 の答えに従う。  
6. 入力は Action 経由。スロット化の形が残っていて、2 人目を足すときにパッド読みを複製しやすい。  
7. ユニット＋疑似パッド E2E が緑。既存のキー操作 E2E が落ちない。

## 7. オーナーに聞きたいこと（確認①）

1. **ボタン表（§3.2）でよいか？** 変えたいボタンがあれば教えてください（例: ほるを RB にしたい、など）。  
2. **持っているコントローラー**は何ですか？（例: Switch Pro、DualSense、Xbox）。何本ありますか？  
3. **振動**は使いますか？（あり / なし）  
4. 画面の操作ヒントをパッド絵に切り替えるのは、**最初から必須**にしますか？ それとも操作ができれば後回しでよいですか？  
5. 左スティックの「ななめ」は、今のキーと同じ速さでよいですか？（速くしない）

## 8. やらないこと（この仕様の外）

- 分割画面・2 人同時・ネット協力。  
- キーボードの割り当て変更画面（大きな設定 UI）。  
- 開発用 F3/F4 のパッド割り当て。  
- とりごやの `coop` とは無関係（名前が似ているだけ）。
